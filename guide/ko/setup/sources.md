# 소스 추가

나중에 번역 파일을 더 추가하거나, 소스의 기준 언어를 바꾸거나, 더 이상 관리하지 않는 소스를 제거합니다.

소스 하나는 리포지토리에 있는 번역 파일 묶음 하나입니다. 프로젝트 소유자는 소스를 추가하고 기준 언어를 선언할 수 있고, 번역자(편집자 역할)는 소스 상태를 볼 수 있지만 프로젝트 설정은 바꿀 수 없습니다.

## 소스 열기 {#sources}

프로젝트 내비게이션에서 **소스**를 엽니다. 행마다 소스의 상태(**아직 동기화 안 됨**, **동기화 중…**, **동기화됨**, **일부 동기화됨**, **동기화 실패**)와 키·언어 수가 표시됩니다.

![파일 경로, 키 수, 언어가 표시된 동기화된 소스 두 개가 있는 소스 페이지](/guide/sources.webp "소스 하나는 번역 파일 묶음 하나입니다.")

## 소스 추가하기 {#add-sources}

1. **소스 추가**를 선택하고, 감지된 파일을 고르거나 지원하는 경로를 입력합니다. **다음**을 선택합니다. 새 파일을 하나 이상 고르기 전에는 꺼져 있습니다.
2. **기준 언어 고르기**에서 새 소스마다 **기준 언어**를 고르고 **선택한 소스 추가**를 선택합니다. 선택을 바꾸려면 **이전**을 선택하세요. 고른 내용은 그대로 남습니다. 다른 파일은 추가되는데 한 파일만 실패할 수 있으니 결과를 하나씩 확인합니다. 아무것도 추가되지 않으면 이 단계에 머물고 선택도 그대로 남습니다.
3. 결과의 **설정** 링크를 따라가 생성된 워크플로에서 새 소스 단계를 복사해 리포지토리의 워크플로 파일에 넣습니다. 소스를 추가해도 그 파일은 자동으로 수정되지 않습니다.

![왼쪽에 감지된 번역 파일, 키와 값 미리보기, 기준 언어 메뉴가 있는 소스 추가 대화상자](/guide/add-sources.webp "파일을 고르고 미리보기를 확인한 뒤 기준 언어를 고릅니다.")

## 소스 제거하기 {#remove-source}

1. **소스**에서 소스의 상세를 열고 **소스 제거**를 선택합니다. 프로젝트 소유자만 쓸 수 있고, 프로젝트의 마지막 소스는 제거할 수 없습니다.
2. 확인 창을 읽고 **소스 제거**를 한 번 더 선택합니다. 미전송 편집이 있으면 몇 건인지 알려 주고, 나중에 다시 추가하면 그 편집이 리포지토리의 값으로 바뀐다고 알려 줍니다. 열린 Malmoi PR이 있으면 이 소스의 변경이 다음 게시에서 빠진다고 알려 줍니다.
3. 리포지토리의 워크플로 파일에서 이 소스의 단계를 지웁니다. 지우기 전에는 다음 실행이 실패하고 그 뒤 소스도 멈춥니다.

소스를 제거하면 동기화가 멈춥니다. 리포지토리의 파일은 바뀌지 않으며, 소스는 **소스**·게시·야간 업데이트에서 사라집니다. 키·번역·이력은 남습니다.

## 제거한 소스 다시 추가하기 {#re-add}

**소스 추가**를 선택하고 같은 경로를 같은 파일 형식으로 고르면 제거한 소스가 번역과 함께 돌아옵니다. 그다음 첫 동기화에서 리포지토리에 값이 있는 칸의 미전송 편집이 리포지토리의 값으로 바뀝니다. 리포지토리에 값이 없는 편집은 미전송으로 남습니다. 경로는 같은데 파일 형식을 다르게 고르면 새 소스가 추가됩니다. 다른 새 소스와 같이 워크플로를 고치세요.

## 기준 언어 바꾸기 {#base-language}

1. **소스**에서 소스의 상세를 엽니다. **기준 언어**에서 원문을 작성한 언어를 고르고 **저장**을 선택합니다. 적용될 때까지 소스 상세에 **적용 대기 중**이 표시됩니다. 변경은 리포지토리의 GitHub Actions 워크플로가 다음에 동기화할 때 적용되며, **동기화** 버튼으로는 적용되지 않습니다.
2. 워크플로의 `base-locale:` 값을 같은 언어로 고칩니다.
3. 워크플로를 실행합니다. 미전송 변경 사항이 있으면 리포지토리 업데이트가 보류됩니다. 변경 사항을 게시하거나 정리한 뒤 워크플로를 다시 실행합니다.

[리포지토리에서 동기화](../sync/revert.md#resync)는 값을 교체하지만 현재 기준 언어는 그대로 둡니다.

## 다음 단계 {#next}

다음에 워크플로가 성공하면 선언한 기준 언어로 소스를 읽습니다. 소스를 제거한 뒤에도 그 소스의 단계가 남은 워크플로는 제거된 소스라는 이유로 거부되어 아무것도 적재하지 않으니, 그 단계를 지우세요.
