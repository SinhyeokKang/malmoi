# 동기화의 원리

저장소의 변경은 앱 텍스트를 Malmoi로 가져오고, 게시는 저장한 번역을 개발팀이 검토하도록 돌려보냅니다.

## 동작 방식 {#how-it-works}

어떤 앱 텍스트 조각(키)이 있는지는 저장소가 정합니다. 갱신과 갱신 사이에는 Malmoi가 번역 값을 보관합니다. 저장소에서 갱신이 올 때마다 Malmoi의 값은 저장소의 값으로 교체됩니다. 두 값을 합치거나 어느 쪽이 이겼는지 고르지 않습니다. 이것이 병합 없는 흐름입니다. 미전송 편집이 있거나 Malmoi의 변경 요청(풀 리퀘스트)이 아직 열려 있으면 자동 갱신은 보류됩니다. 갱신은 커밋마다 저장소의 워크플로에서 오거나, 하루 한 번 [야간 실행](nightly.md#repository-changes)에서 옵니다.

**게시**는 Malmoi의 값을 변경 요청(GitHub의 *풀 리퀘스트*)에 담아 개발팀이 검토하고 머지하게 합니다.

들어오는 방향은 [코드가 바뀌면](push.md)을, 돌아가는 길은 [풀 리퀘스트 머지](merging.md)를 읽으세요.
