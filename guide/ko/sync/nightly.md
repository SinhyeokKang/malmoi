# 매일 밤

매일 밤 Malmoi는 활성 프로젝트마다 저장한 변경 사항을 게시하거나 리포지토리의 새 변경을 가져옵니다.

야간 실행은 18:00 UTC에 예약되어 있습니다. 프로젝트마다 많아야 한 가지 일을 합니다. 보내지 않은 편집을 게시하거나, 리포지토리에서 프로젝트를 갱신하거나, 할 일이 없어 건너뜁니다. 한 번 들를 때마다 **로그**에 **야간** 표시가 붙은 사건이 많아야 하나 남습니다.

## 확인 대상 프로젝트 {#eligible}

프로젝트는 활성 상태이고, 리포지토리에 연결되어 있고, 첫 동기화에 성공한 소스가 하나 이상 있어야 합니다. 보관됐거나 연결되지 않은 프로젝트는 제외됩니다. 한 번의 실행은 프로젝트를 최대 50개까지, 마지막 야간 확인 뒤 가장 오래 기다린 프로젝트부터 확인합니다. 시간이 다 되면 더 일찍 멈출 수 있어 어떤 프로젝트는 다른 날 밤까지 기다릴 수 있습니다. 실행 후반에 도달한 프로젝트에 새 커밋이 있으면 그 프로젝트도 다음 날 밤으로 넘어가며, 그때는 맨 앞에 섭니다.

## 자동 게시 {#nightly}

저장한 편집 중 하나라도 미전송이면 야간 실행은 프로젝트에 저장된 변경 사항을 변경 요청(GitHub의 *풀 리퀘스트*)으로 게시합니다. 열린 풀 리퀘스트가 있으면 두 번째를 여는 대신 그것을 갱신합니다. 그날 밤에는 리포지토리에서 프로젝트를 갱신하지 않습니다.

게시할 수 없는 저장 값은 Malmoi에 남습니다. 변경 사항이 밤사이 게시되지 않았다면 **로그**를 확인하고, 보고된 실패가 있으면 프로젝트 소유자에게 문의하세요.

## 리포지토리에서 오는 갱신 {#repository-changes}

게시를 기다리는 것이 없으면 야간 실행은 Malmoi가 마지막으로 소스를 읽은 뒤 Malmoi가 읽는 브랜치에 새 커밋이 있는지 확인합니다.

- 새 커밋이 없고 지난번에 실패한 것도 없으면 아무것도 읽지 않고 사건에 **최신 상태**가 표시됩니다. 파일 갱신에 실패했다면 야간 실행이 성공할 때까지 매일 밤 다시 시도합니다.
- 새 커밋이 있으면 Malmoi가 리포지토리에서 소스를 읽어 프로젝트를 갱신합니다. 프로젝트 소유자의 동기화와 같은 방식이지만 아무것도 버리지 않습니다. 그러면 홈의 **동기화** 탭에 **마지막 동기화**로 **야간 동기화**가 표시되고, **동기화 시각**에 끝난 시각이, **변경**에 바뀐 번역 수가 표시됩니다.

야간 갱신이 진행되는 동안 누군가 번역을 저장하면, Malmoi는 새 편집을 덮어쓰지 않도록 다음 소스 전에 멈춥니다. 이미 갱신한 소스는 갱신된 상태로 남습니다.

## 야간 실행이 갱신을 보류할 때 {#held}

다음과 같은 경우 야간 실행은 갱신을 보류합니다. 프로젝트는 갱신되지 않고 **로그**에 **보류**와 이유가 표시됩니다.

- Malmoi 풀 리퀘스트가 아직 열려 있습니다. 그 번역은 아직 리포지토리에 없으므로 갱신하면 덮어쓰게 됩니다. 풀 리퀘스트를 머지하거나 닫으면 다음 야간 실행이 변경을 가져옵니다. 홈의 **동기화** 탭은 **보류** 행에 **보류**를 표시하고, 보낼 항목 카드가 이유를 알려 줍니다.
- GitHub가 그 풀 리퀘스트가 열려 있는지 응답하지 않았습니다. Malmoi는 추측하지 않습니다. 홈에 **보류**가 표시되고 다음 실행이 다시 확인합니다.
- 변경이 서버 쪽 동기화로 처리하기에 너무 큽니다. 야간 갱신은 프로젝트를 만들 때와 같은 파일 예산을 씁니다([한도](../reference/limits.md#files) 참고). 파일 크기를 줄이거나 리포지토리 워크플로로 변경을 전달하세요.

야간 실행이 리포지토리의 브랜치를 읽지 못하거나 GitHub가 제때 응답하지 않으면, 사건은 보류가 아니라 **로그**에 **실패**로 표시됩니다. 브랜치가 더 이상 없으면 다음에 동기화가 성공할 때까지 홈에도 동기화가 실패로 표시됩니다. GitHub가 응답하지 않았을 뿐이라면 홈은 그대로이고 다음 실행이 다시 시도합니다. 프로젝트 소유자는 프로젝트 **설정**에서 브랜치와 GitHub 연결을 확인할 수 있습니다.

## 야간 동기화 또는 워크플로 {#workflow}

워크플로는 선택 사항입니다. 워크플로가 없으면 야간 실행이 하루 한 번 리포지토리의 변경을 가져옵니다. [워크플로](../setup/workflow.md)가 있으면 리포지토리의 GitHub Actions가 그 브랜치의 커밋마다 변경을 보내고, 코드 사용처도 모읍니다. **로그**에서 워크플로 실행에는 **CI** 표시가 붙습니다. CI는 리포지토리의 워크플로를 뜻합니다.

## 다음 단계 {#next}
