# 문제 해결

GitHub 접근, 설정, 리포지토리 동기화가 실패할 때 다음 단계를 찾습니다.

## GitHub 접근 복구 {#github-access}

GitHub 승인이 만료됐다면 **계정**을 열고 **GitHub App 다시 승인**을 선택합니다. 로그인 수단과 리포지토리 접근은 별개입니다.

프로젝트 **설정**은 리포지토리 연결을 배지로 보여 주며, 배지마다 다음 단계가 다릅니다.

- **연결 끊김** — 다시 연결될 때까지 동기화와 게시가 멈춥니다. **다시 연결**을 선택합니다. 앱이 제거됐다면 카드에 **앱 설치** 링크도 보입니다. 앱을 설치한 뒤 돌아와 다시 연결하세요.
- **연결 안 됨** — 아직 연결된 설치가 없습니다. **연결**을 선택합니다.
- **다른 리포지토리** — 그 주소에 이제 다른 리포지토리가 있습니다. 버튼은 없습니다. GitHub에서 확인하고, 리포지토리가 정말 교체됐다면 그 리포지토리로 새 프로젝트를 만드세요.
- **확인하지 못함** — Malmoi가 지금 연결을 확인할 수 없습니다. 무언가를 바꾸기 전에 페이지를 다시 여세요.

리포지토리가 목록에 없으면 Malmoi에서 **리포지토리 선택**을 선택한 뒤 GitHub에서 Malmoi GitHub App의 **Repository access**를 엽니다. 앱이 제거됐다면 **앱 설치**를 선택합니다.

## 워크플로 실패 해결 {#workflow-failures}

Actions 로그에서 생성된 워크플로 경로, `PUSH_TOKEN`, 허용된 action, 고른 기준 브랜치를 확인합니다. 설치가 없거나 action 정책에 막히면 요청이 프로젝트에 닿기 전에 실행이 멈출 수 있습니다. 401은 토큰이 틀렸거나 교체됐다는 뜻입니다. **설정**에서 **토큰 교체**를 선택하고 **교체하고 새 토큰 보기**로 확인한 뒤 값을 `PUSH_TOKEN`에 복사합니다. 토큰은 한 번만 표시되며 이전 push 토큰은 즉시 동작을 멈춥니다.

## 거부된 갱신 해결 {#rejected-updates}

409는 프로젝트가 보관됐거나, 프로젝트나 소스가 맞지 않거나, 형식이 맞지 않거나, 커밋이 오래됐다는 뜻일 수 있습니다. 400은 워크플로가 보낸 파일이나 설정된 파일 묶음이 검증을 통과하지 못했다는 뜻입니다. 프로젝트 설정을 바꾸기 전에 GitHub Actions의 워크플로 실행 로그에서 이유를 읽으세요.

실행 로그에 `deferred`가 보이면 갱신이 보류된 것이고, 로그에는 **보류**로 표시됩니다. 저장한 편집이 미전송이면 게시하고 워크플로를 다시 실행합니다. `open-pr`이면 Malmoi 풀 리퀘스트가 아직 열려 있으니 머지하거나 닫습니다. `pr-check-failed`이면 Malmoi가 GitHub를 확인하지 못한 것이니 나중에 워크플로를 다시 실행합니다.

**게시**가 꺼져 있다면 미전송이 없거나(“편집한 내용이 모두 이미 전송됐습니다.”), GitHub가 연결되어 있지 않거나, 프로젝트가 보관됐거나, 동기화가 진행 중일 수 있습니다(“지금은 게시할 수 없습니다.”). 편집자의 경로는 [변경 사항 게시](../translate/publish.md#publish)를 참고하세요. 프로젝트 소유자는 연결을 고치거나 동기화가 끝나기를 기다릴 수 있습니다.

`[skip-malmoi-i18n]`이 든 커밋은 건너뜁니다. 그 결과는 워크플로 실행 로그에서 읽으세요.
