# GitLab으로 프로젝트 만들기

개인 액세스 토큰으로 GitLab.com 리포지토리를 연결하고, Malmoi가 관리할 번역 파일을 골라 프로젝트를 만듭니다.

시작하기 전에: 인증된 이메일로 로그인하고 **프로젝트**로 가서 **새 프로젝트**를 선택합니다. 활성 프로젝트는 세 개까지 소유할 수 있습니다. 그 GitLab 프로젝트에서 Maintainer 이상의 역할이 있어야 합니다. 다른 호스트를 쓴다면 이 페이지 대신 [GitHub로 프로젝트 만들기](../github/create.md)를 따르세요.

## GitLab 연결 {#connect-gitlab}

Malmoi는 내 GitLab 계정의 개인 액세스 토큰으로 GitLab.com에 연결합니다. GitLab Self-Managed와 GitLab Dedicated는 지원하지 않습니다.

1. 첫 단계 맨 위에서 **GitLab** 탭을 선택합니다. 사용 중인 Malmoi가 GitLab만 제공한다면 탭 없이 바로 GitLab이 표시됩니다.
2. GitLab이 아직 연결되어 있지 않다면 **GitLab 연결**이 표시됩니다. **GitLab에서 토큰 만들기**를 선택하면 새 탭에 GitLab의 개인 액세스 토큰 페이지가 열리고, 이름 `Malmoi`와 `api` 스코프가 미리 채워져 있습니다.
3. GitLab에서 만료일을 확인하고 `api` 스코프를 고른 채로 **Generate token**을 선택합니다. GitLab이 보여 주는 토큰을 복사하세요. 토큰은 한 번만 표시됩니다. Malmoi에는 이 레거시 토큰이 필요하며, fine-grained 토큰은 받지 않습니다.
4. Malmoi로 돌아와 토큰을 **개인 액세스 토큰**에 붙여 넣고 **연결**을 선택합니다. Malmoi가 GitLab에서 토큰을 확인하는 동안에는 확인 중이라는 안내가 표시됩니다. 토큰이 거부되면 도움말 아래에 이유가 표시됩니다. Malmoi는 토큰을 다시 보여 주지 않습니다. 저장된 토큰이 만료되었거나 더 쓸 수 없으면 **GitLab 다시 연결**이 표시되니, 같은 방법으로 새 토큰을 붙여 넣습니다.

## 리포지토리 고르기 {#select-repository}

1. Malmoi는 내가 Maintainer 이상의 역할을 가진 GitLab 프로젝트를 나열합니다. 해당하는 프로젝트가 없으면 **추가할 GitLab 프로젝트 없음**이 표시됩니다. GitLab에서 그 역할을 받은 뒤 **다시 시도**를 선택합니다.
2. 리포지토리를 고르고 번역 파일이 있는 **브랜치**를 고른 뒤 **다음**을 선택합니다. 번역은 이 브랜치를 대상으로 하는 MR(GitLab의 *merge request*)로 돌아옵니다.

![GitLab 탭에서 목록 위에 연결된 계정과 토큰 만료일이 보이고, 프로젝트를 고른 뒤 브랜치로 main을 고른 새 프로젝트 4단계 중 1단계](/guide/gitlab-connect.webp "GitLab 프로젝트와 브랜치를 고른 뒤 다음을 선택합니다.")

검색창 아래에는 연결된 GitLab 계정과 토큰 만료일이 표시됩니다. 같은 계정의 새 토큰으로 바꾸려면 **토큰 교체**를 선택합니다. 토큰은 [GitLab 토큰과 연결 관리](connection.md#gitlab-token)에서도 관리할 수 있습니다. 프로젝트는 연결한 사람의 토큰으로 게시하므로, GitLab의 커밋과 MR은 그 GitLab 계정의 이름으로 남습니다.

## 파일 고르기 {#choose-files}

1. 감지된 파일을 고릅니다. 언어가 하나뿐인 파일도 지원합니다.
2. 파일이 감지되지 않으면 **경로 직접 지정**을 선택하고 지원하는 경로와 형식을 입력합니다. 경로 예시는 [지원 파일 형식](../reference/formats.md#formats)을 참고하세요.
3. 미리보기를 확인한 뒤 **다음**을 선택합니다.

Malmoi는 고른 파일 묶음마다 소스 하나를 보여 줍니다. 소스마다 기준 언어가 달라도 됩니다.

![감지된 번역 파일 묶음 두 개를 고르고 그중 하나의 키와 값을 미리 보는 4단계 중 2단계](/guide/create-files.webp "감지된 파일을 고르고 키를 확인합니다.")

## 프로젝트 정보 입력 {#confirm-project}

1. 소스마다 **기준 언어**를 확인합니다. 기준 언어의 파일을 기준으로 키 목록을 만들며, 다른 언어에만 있는 키는 포함되지 않습니다.
2. 프로젝트 **이름**과 **주소**를 입력합니다. 주소는 프로젝트 URL에 들어가는 이름으로, Malmoi 전체에서 고유해야 하고 나중에 바꿀 수 없습니다.
3. [한도](../reference/limits.md#files)에서 파일과 크기 한도를 확인한 뒤 **프로젝트 만들기**를 선택합니다.

![프로젝트 이름과 주소를 채우고 소스의 기준 언어로 영어를 고른 4단계 중 3단계](/guide/create-name.webp "프로젝트를 만들기 전에 기준 언어, 이름, 주소를 확인합니다.")

프로젝트는 바로 준비됩니다. 마지막 단계에 **Malmoi 준비 완료**가 표시되며, 곧바로 번역하고 팀원을 초대할 수 있습니다.

## 설정 마무리 {#finish-setup}

1. 준비 완료 페이지에 표시된 푸시 토큰을 복사합니다. 토큰은 한 번만 표시되며, 잃어버리면 나중에 **설정**에서 교체합니다.
2. [GitLab CI 작업 추가](ci.md)를 따라 CI 작업과 `PUSH_TOKEN` 변수를 추가합니다.
3. **프로젝트 열기**를 선택해 프로젝트 홈으로 갑니다.

프로젝트를 만든 사람은 **소유자**가 됩니다.

## 다음 단계 {#next}

CI 작업이 없어도 야간 실행이 하루 한 번 프로젝트를 최신 상태로 유지합니다. CI 작업을 추가하면 커밋마다 프로젝트가 업데이트되고, 첫 실행 뒤부터 코드 사용처가 표시됩니다. 작업이 실패해도 프로젝트는 준비된 상태를 유지합니다. 문제가 생기면 [GitLab 문제 해결](troubleshooting.md)을 참고하세요.
