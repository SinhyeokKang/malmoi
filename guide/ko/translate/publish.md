# 변경 사항 게시

저장한 번역 변경 사항을 검토하고, 개발팀이 GitHub에서 검토할 수 있도록 게시합니다.

시작하기 전에: 게시할 값을 저장합니다. 게시에는 내가 저장한 것뿐 아니라 프로젝트에 저장된 모든 미전송 변경 사항이 포함됩니다.

## 저장한 변경 사항 미리보기 {#preview}

Malmoi는 바뀐 파일을 PR(GitHub의 *pull request*) 하나에 담습니다. GitHub 계정은 없어도 됩니다. 검토와 머지는 개발팀이 합니다.

![보낼 변경 사항이 하나 있고 개수가 표시된 게시 버튼이 활성화된 프로젝트 홈](/guide/home-publish.webp "게시는 홈 맨 위에 있습니다.")

1. **홈** 또는 **번역** 맨 위에서 **게시**를 선택합니다.
2. 미리보기에서 키(앱 텍스트 한 조각)와 언어를 확인한 뒤 아래 설명대로 진행합니다.

![바뀐 값 하나와 언어, 새 PR을 여는 버튼이 나열된 게시 미리보기](/guide/publish-preview.webp "게시하기 전에 변경 사항을 하나씩 확인합니다.")

## 변경 사항 게시하기 {#publish}

**PR 열기** 또는 PR #N 교체를 선택합니다. 변경 사항이 이미 파일과 같고 열린 PR이 없으면 버튼은 **게시**입니다. PR이 열려 있고 파일이 같으면 버튼은 PR #N 닫기입니다.

게시가 꺼져 있다면 미전송 변경 사항이 없거나 게시를 잠시 쓸 수 없는 상태일 수 있습니다. 진행 중인 동기화가 끝날 때까지 기다리고, 계속 쓸 수 없으면 프로젝트 소유자에게 문의하세요.

게시가 실패해도 저장한 값은 남아 있습니다. 나중에 다시 시도하거나 프로젝트 소유자에게 알리세요.

## 결과 읽기 {#result}

결과는 다음 중 하나입니다.

- **검토 요청됨** — 개발팀을 위한 새 PR이 열렸습니다.
- **기존 PR을 업데이트했습니다** — 열려 있던 PR의 내용이 교체되었습니다.
- **파일 변경 없음** — 새로 게시할 것이 없습니다.
- **제외됨 — 일부 값을 파일에 쓸 수 없음** 또는 변경 사항 N건을 보내지 못함 — 저장한 값은 남아 있습니다. 나열된 파일을 프로젝트 소유자에게 알리세요.
- 기존 PR이 닫힘 — 변경 사항이 이제 기준 브랜치와 같아 검토할 내용이 남지 않았습니다.
- **GitHub가 응답하지 않았습니다** — 저장한 값은 남아 있습니다. 나중에 다시 시도하세요.
- **변경 사항이 전송되었는지 확인하지 못했습니다.** 다시 시도하기 전에 **로그**를 확인하세요.

![변경 사항이 이미 리포지토리에 있어 파일에 바뀐 내용이 없다고 알리는 게시 결과](/guide/publish-result.webp "닫기 전에 결과를 읽습니다.")

## 자동 게시 {#nightly}

게시하지 않으면 저장한 변경 사항은 매일 밤 한 번 자동으로 게시됩니다. 대상과 시각은 [매일 밤](../sync/nightly.md#nightly)을 참고하세요.

## PR이 열려 있는 동안 {#open-pull-request}

PR이 검토를 기다리는 동안에도 게시한 값은 보존됩니다. Malmoi는 개발팀이 PR을 머지하거나 닫을 때까지 리포지토리 업데이트를 보류하므로, 코드에 추가된 새 텍스트가 나타나기까지 시간이 더 걸릴 수 있습니다. PR이 머지되지 않고 닫히면 리포지토리에서 오는 다음 업데이트가 그 값을 리포지토리의 값으로 교체합니다.

## 다음 단계 {#next}

개발팀이 PR을 검토하고 리포지토리에 머지합니다.

나중에 확인하려면 홈의 **게시** 탭을 엽니다. **마지막 게시**는 최근 게시의 결과를, **게시 시각**은 게시한 시각을, **변경**은 파일에서 바뀐 번역 수를 보여 줍니다. **PR 상태**가 표시되면 PR이 아직 열려 있는지 알려 줍니다. **게시 로그**에는 모든 게시가 나열됩니다.
