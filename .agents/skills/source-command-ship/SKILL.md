# source-command-ship

Use this skill when the user asks to run the migrated source command `ship`.

## Command Template

작은·외과적 변경 하나를 **`/tdd` → 커밋 → `/implement` → 커밋 → `/code-review` → `/refactor` → (`/db`) → (`/postmortem`) → `/push`** 순서로 자동 오케스트레이션한다.

> **⚠️ 이 파이프라인의 끝은 프로덕션 배포다.** main 단일 브랜치라 `/push`가 곧 Vercel 프로덕션 배포이고, PR도 브랜치 프로텍션도 없어 **되돌리는 유일한 방법은 다음 배포**다. 따라서 이 스킬의 게이트는 "다음 단계로 갈 자격"이 아니라 **"배포될 자격"** 이다. 게이트를 오판하면 그대로 배포된다 — 애매하면 통과시키지 말고 중단한다.

이 스킬은 **파이프라인 지휘자**다 — 구현·리뷰·수정의 본체 로직은 각 하위 스킬이 이미 자기완결한다. `/ship`은 순서·게이트·중단만 관장한다.

## 사용

- `/ship <변경 설명>` — 설명을 `/tdd`·`/implement`에 실어 시작.
- `/ship` — 직전 컨텍스트(방금 합의한 변경)에서 대상 자동 판단.
- `/ship bypass <변경 설명>` — **스코프 가드 바이패스.** 아래 적용 범위 판정만 건너뛴다. 단계·게이트·push는 **전부 그대로** 돈다.

## 적용 범위 (스코프 가드 — 착수 전 판정)

**작은·외과적 변경 전용.** 아래 중 하나라도 해당하면 **중단하고 수동 흐름(`/feature`부터)을 권한다**:

- 여러 서브시스템에 걸친 기능 (세 흐름 중 둘 이상을 동시에 건드림)
- **`docs/MVP.md` §7 비범위 항목**을 요구 — 범위 결정은 사용자 몫이다
- **코어 불변식 변경** — export 결정성 규칙, blob SHA 계약, 커밋·PR 전략, 인증 경계 (ARCHITECTURE §1·2·3·6)
- **destructive 스키마 변경** — 2단계 배포가 필요해 한 파이프라인에 안 들어간다
- `docs/features/<slug>/`가 필요한 신규 기능

`lib/` 순수 함수 수정, 국소 버그픽스, 단일 컴포넌트 소변경, additive 스키마 컬럼 추가 같은 **한 영역 집중 변경**만 대상.

**브랜치 확인**: `git branch --show-current`가 `main`이어야 한다 (main 단일 정책). 다른 브랜치면 왜 거기 있는지 확인하고 중단한다.

### 바이패스 모드 (`/ship bypass`)

**이미 설계가 끝난 큰 변경을 파이프라인에 태우기 위한 정식 경로다.** `/feature`로 `docs/features/<slug>/`를 산출해 설계·태스크가 확정됐다면 규모 때문에 막을 이유가 없다 — 스코프 가드의 목적은 "설계 없이 큰 걸 자동으로 밀어붙이는 것"을 막는 데 있다.

- **완화되는 것: 위 적용 범위 판정뿐.** 단, **비범위 항목과 destructive 스키마는 바이패스로도 통과하지 않는다** — 전자는 사용자 결정이고 후자는 배포가 2단계로 쪼개져야 해서 구조적으로 불가능하다.
- **완화되지 않는 것 — 나머지 전부**: 브랜치 확인, 0단계 클린 워크트리 전제, 모든 단계 게이트, 중단 처리 규약, 하위 스킬 각자의 금지 사항. push(=배포)도 그대로 수행한다.
- **feature 문서가 있으면 그것을 계획 원본으로 쓴다.** `tasks.md`의 태스크·검증 항목을 0단계 인테이크에 싣고 1·2단계에 전달한다. 파이프라인이 태스크를 새로 발명하지 않는다.
- **문서가 단계를 나눠 놨으면 한 번에 한 단계만 태운다.**
- **최종 리포트에 바이패스 사용을 명시**한다 (건너뛴 판정, 계획 원본 경로).

## push 권한 / 런타임별 종착점

**Claude Code에서는 마지막에 `/push`까지 자동 수행하고, 그것이 프로덕션 배포다.** `/ship` 호출 자체가 "배포하라"는 지시로 간주된다. 배포를 원치 않으면 `/ship`을 호출하지 않고 개별 스킬로 진행한다.

**Codex에서는 마지막 커밋(10단계)까지만 돌고 멈춘다.** 원격으로 나가는 건 Claude Code 단일 창구다 (`/push` 미러도 없다). 최종 리포트에 **"배포 대기 — Claude Code에서 `/push` 실행"**을 남기고 종료한다. 브랜치 확인은 그대로 적용한다.

## 파이프라인 단계 + 게이트

`[영향 게이팅]` 표시 단계는 앞 단계 보고의 플래그가 있을 때만 실행한다.

### 0. 인테이크
- 스코프 가드·브랜치 확인. 실패 시 중단.
- **클린 워크트리 전제**: `git status --porcelain`에 미커밋 변경이 있으면 파이프라인 시작 전에 **먼저 별도 커밋**한다 (내용을 파악해 영문 메시지로, 허락 없이). 파이프라인 자체 커밋과 기존 잔여 변경을 섞지 않으려는 것.
  - 단, 미커밋 diff가 **이번 대상 변경과 겹치면** 커밋하지 말고 **중단+리포트** — `/tdd`가 테스트를 먼저 박는 순서가 이미 깨졌다.
- **`docs/MVP.md`·`docs/ARCHITECTURE.md` 관련 섹션 확인** — 대상이 코어 로직이면 불변식을 파이프라인 전체에 들고 간다.
- 변경 설명 확정.

### 1. `/tdd`
- 변경을 재현/규정하는 테스트 작성 (regression 또는 interface).
- **게이트**: red 확인됨 (또는 `/tdd` 분류표상 스킵 대상 — 이유 한 줄 기록). red를 못 만들면(예상외 green) 중단+리포트.

### 1.5 커밋 #0 (test) — 무조건
- 1단계가 만든 **테스트 코드만** 커밋. `test: ...` 스코프, 영문.
- **red 상태로 커밋하는 것이 정상이다.** 테스트를 먼저 박은 사실을 히스토리에 남기는 게 목적이고, 3단계 커밋과 섞으면 그 증거가 사라진다.
- **스킵 조건은 하나뿐**: 1단계가 분류표상 스킵으로 파일을 하나도 만들지 않은 경우.
- 1단계가 프로덕션 코드를 건드렸다면 `/tdd` 금지 사항 위반이므로 **중단+리포트**.

> **주의**: 이 커밋 하나만 놓고 보면 `pnpm test`가 red다. `/push`의 로컬 게이트는 파이프라인 끝(전부 green인 HEAD)에서 돌므로 red가 배포되지는 않지만, `git bisect`가 이 커밋에 착지하면 실패를 만난다.

### 2. `/implement`
- 테스트를 green으로. 4관점 자체 검증으로 자기완결.
- **게이트**: `pnpm test` 전체 green + `pnpm typecheck` 통과 + 🔴/🟡 전부 해소(2회 루프 내). 미해소면 **중단+리포트**.
- **플래그 수집**: "스키마 영향"·"문서 영향"·"postmortem 후보"를 기록 (뒤 단계 게이팅).

### 3. 커밋 #1 (feat/fix)
- **구현만** 커밋. 테스트는 1.5에서 이미 커밋됐다. 영문 메시지.
- 2단계가 테스트를 수정했으면(구현 중 드러난 기대값 정정) 그 변경도 함께 싣는다 — 되돌리는 게 아니라 이어지는 수정이다.

### 4. `/code-review`
- 커밋된 변경분 정적 리뷰. **리포트 전용이라 게이트 없음** — 발견 목록을 5단계로 전달.
- **다만 이 파이프라인의 끝이 배포이므로, 🔴이 하나라도 있으면 5단계를 스킵할 수 없다.**

### 5. `/refactor` (발견이 있을 때)
- 🔴/🟡를 지정해 수정 (버그성은 회귀 테스트 red→green).
- 발견 0이거나 ⚪만 있으면 스킵(보고).
- **게이트**: test green + typecheck 통과. **회귀 위험 항목**(기대값 변경·export 출력 변경·스키마 변경)은 `/refactor`가 확인을 요구하므로 그 지점에서 **중단+리포트**.
- **🔴이 남은 상태로 6단계 이후로 진행 금지** — 배포되기 때문이다.

### 6. 커밋 #2 (refactor)
- 5단계가 코드를 바꿨을 때만.

### 7. `/db` [영향 게이팅]
- 2단계 "스키마 영향" 플래그가 **additive**일 때만. **destructive면 여기 오기 전에 스코프 가드가 막았어야 한다** — 도달했다면 중단+리포트.
- 마이그레이션 생성 + SQL 확인 + generate/typecheck/test.
- **게이트**: 마이그레이션 생성됨, SQL이 의도와 일치, test green. 드리프트 검출 시 **중단+리포트**.
- **`db:deploy`는 돌리지 않는다** — 11단계 `/push`가 푸시 전에 사용자 확인을 받는다.

### 8. 커밋 #3 (db)
- 7단계가 스키마·마이그레이션을 바꿨을 때만 (`chore(db):`·`feat(db):`). 코드와 섞지 않는다.

### 9. `/postmortem` [영향 게이팅]
- **트리거**: 3단계 커밋이 `fix:`이거나, 2단계 "postmortem 후보" 플래그가 있을 때. 둘 다 없으면 스킵(사유 보고).
- **게이트**: 항목 추가, 또는 trivial 필터로 "항목 없음" 기록. **소프트 게이트 — write-only라 halt 없음.**
- **소환 회로 완성**: `/ship`은 2·4·5단계에서 하위 스킬을 통해 POSTMORTEM을 grep(읽기)한다. 이 스테이지가 쓰기를 담당해 한 바퀴 안에서 루프가 닫힌다.

### 10. 커밋 #4 (docs)
- 9단계가 POSTMORTEM을 바꿨거나 2단계 "문서 영향"으로 문서를 고쳤을 때만 (`docs(...)`).

### 11. `/push` = 프로덕션 배포 [Claude Code 전용 — Codex는 10단계에서 종료]
- `/push`가 로컬 검증 게이트(typecheck+test) → 마이그레이션 순서 확인 → 문서 신선도 → Codex 미러 → 푸시를 순서대로 돈다.
- **게이트**: `/push`의 모든 단계 통과. 어느 단계든 실패하면 **중단+리포트** — 아직 배포되지 않은 상태이므로 여기서 멈추는 것이 정상 복구 경로다.
- **`/push` 3단계에서 마이그레이션이 감지되면 `pnpm db:deploy` 실행 확인을 사용자에게 요구하고 대기한다.** 파이프라인이 대신 승인하지 않는다.
- **주의 — 층위가 다르다**: `/push`의 로컬 게이트는 배포될 HEAD 전체를 검증하고, 2단계 게이트는 구현 시점의 검증이다. 그 사이에 4·6·8·10단계 커밋이 얹히므로 둘 다 도는 게 정상이다.

### 12. 최종 리포트
- 단계별 통과/스킵/중단 요약 + 커밋 해시들 + **배포 여부** + CI run URL(결과 미확정) + 남은 수동 항목.
- **배포됐으면 그 사실을 리포트 첫 줄에 쓴다.** "푸시 완료"가 아니라 "프로덕션 배포 시작"이다.
- CI가 배포 후에 도는 구조이므로, CI 결과 확인이 사용자에게 남은 항목임을 명시한다.

## 중단 처리 (즉시 중단+리포트)

```
🛑 중단: <단계> 게이트 실패
사유: <한 줄>
배포 여부: 아직 배포되지 않음 / 이미 배포됨(<해시>)
현재 상태: 커밋 <해시들> / 미커밋 <있으면>
남은 단계: <목록>
재개: <사용자가 무엇을 결정/수정하면 이어갈 수 있는지>
```

중단 후 **임의로 우회·강행하지 않는다.** 사용자 지시를 기다린다.

## 다른 스킬과의 분리

- 개별 스킬 — 단계 하나씩 수동 진행. **배포하지 않고 커밋만 쌓고 싶으면 이 경로를 쓴다.**
- `/ship` ← 여기. **작은 변경의 전 단계 자동 오케스트레이션 + 게이트 + 프로덕션 배포**.

## 금지 사항

- **큰·다영역 변경에 사용 금지** — 스코프 가드에 걸리면 수동 흐름 권하고 종료. `/ship bypass` 명시 호출은 예외.
- **바이패스 임의 적용 금지** — 사용자가 `bypass`를 명시하지 않았는데 가드에 걸리면 스스로 켜지 않는다. "이 정도면 괜찮겠지" 판단 금지.
- **비범위·destructive 스키마·코어 불변식 변경은 바이패스로도 진행 금지.**
- **게이트 실패 우회·강행 금지** — 즉시 중단+리포트. **이 파이프라인의 끝이 배포이므로 애매한 통과는 곧 사고다.**
- **🔴 미해소 상태로 11단계 진행 금지.**
- **`pnpm db:deploy` 자동 실행 금지** — 프로덕션 DB를 바꾸는 일이다.
- **하위 스킬의 금지 사항 무력화 금지.**
- **단계 임의 생략 금지** — `[영향 게이팅]` 단계만 플래그 부재 시 스킵(사유 보고).
