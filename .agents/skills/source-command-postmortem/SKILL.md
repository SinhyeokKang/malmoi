# source-command-postmortem

Use this skill when the user asks to run the migrated source command `postmortem`.

## Command Template

방금 잡은 버그·회귀·비자명한 함정을 `docs/POSTMORTEM.md`에 남긴다. **목적은 같은 함정을 두 번 밟지 않는 것**이고, 그래서 "재발 방지" 항목이 핵심이다.

## 언제 호출하나

- `fix:` 커밋을 만들었을 때 (회귀·버그 픽스)
- 구현 중 **비자명한 함정**을 밟았을 때 (문서에 없던 제약, 조용히 실패하는 동작)
- `/implement` 리포트에 "postmortem 후보" 플래그가 있을 때

## trivial 필터 (먼저 적용)

아래는 **기록하지 않는다.** 로그가 노이즈로 차면 아무도 안 읽고, 그러면 `/implement`·`/code-review`의 grep 소환 회로가 죽는다.

- 타입 오류·오타·단순 실수 (컴파일러·테스트가 즉시 잡은 것)
- 문서를 읽었으면 안 밟았을 것 (그건 문서 문제가 아니라 절차 문제다)
- 한 번만 발생하고 다른 곳에 같은 패턴이 없는 것

**기록 기준**: (1) 조용히 실패했거나, (2) 진단에 시간이 걸렸거나, (3) 같은 패턴이 코드베이스 다른 곳에도 있을 수 있는 것.

trivial 판정이면 "항목 없음 — <이유>"를 보고하고 종료한다.

## 형식

```
### YYYY-MM-DD — <한 줄 증상>

- **영역**: <파일·모듈>
- **증상**: 관측된 잘못된 동작
- **근본 원인**: 왜 그렇게 됐는지 (표면 원인 아님)
- **그물**: 무엇이 잡았는가 / 무엇이 놓쳤는가
- **재발 방지**: 같은 함정을 다른 곳에서 찾는 grep 패턴 또는 전수 대상
```

- **날짜는 오늘 날짜를 실제로 확인해 쓴다** (추측 금지).
- **"근본 원인"에 "실수했다"를 쓰지 않는다.** 왜 그 실수가 가능했는지 — 어떤 API가 오해를 부르는지, 어떤 검사가 없었는지.
- **"그물"은 양쪽을 다 쓴다.** 무엇이 놓쳤는지가 다음 테스트를 결정한다.
- **"재발 방지"는 실행 가능해야 한다.** "주의한다"는 재발 방지가 아니다. grep 패턴, 추가할 테스트, 훅으로 막을 수 있는지.

## 절차

1. **trivial 필터** 적용. 통과하면 계속.
2. **직전 작업 맥락 파악** — `git log -3 --stat`, 방금 고친 diff.
3. **기존 항목 확인** — 같은 함정이 이미 있으면 **새 항목을 만들지 않고** 그 항목에 재발 사실을 덧붙인다 (같은 게 두 번 났다는 정보가 더 중요하다).
4. **항목 추가** — 파일 끝에 append. 기존 항목을 수정·삭제하지 않는다.
5. **재발 방지의 grep을 실제로 돌려본다.** 다른 곳에 같은 패턴이 있으면 그것도 리포트에 적는다 — 이게 이 스킬의 가장 큰 값이다.

## 리포트

```
📓 postmortem
항목: <제목> / 항목 없음(<이유>)
재발 방지 grep: <패턴>
   → 다른 곳 <n>건 발견: <목록>  ← 있으면 후속 작업 후보
   → 다른 곳 없음
```

## 금지 사항

- **코드 수정 금지.** 문서만.
- **기존 항목 삭제·수정 금지** (append-only). 재발은 해당 항목에 덧붙인다.
- **trivial 기록 금지** — 필터를 성실히 적용한다.
- **grep을 안 돌리고 "재발 방지" 쓰기 금지.**
