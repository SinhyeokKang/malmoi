작은·외과적 변경 하나를 **`/tdd` → 커밋 → `/implement` → 커밋 → `/code-review` → `/refactor` → (`/design-sync`) → (`/db`) → (`/postmortem`) → `/push`(dev)** 순서로 자동 오케스트레이션한다. 프로덕션 배포(`/merge`)는 이 파이프라인 밖이다.

> **⚠️ 이 파이프라인의 끝은 dev이고, 프로덕션이 아니다** (2026-09-04 브랜치 분리). `/push`가 dev에 푸시하면 Vercel **preview**가 뜨고, 프로덕션으로 보내는 것은 `/merge`(dev→main PR)다. **`/ship`은 `/merge`를 부르지 않는다** — 브랜치를 나눈 목적이 프로덕션 앞에 사람 판단을 하나 더 두는 것이므로, 그 판단을 파이프라인이 대신하면 나눈 의미가 없다.
>
> **그래도 게이트를 "다음 단계로 갈 자격"으로 낮추지 않는다.** 여기서 통과시킨 커밋이 그대로 `/merge`의 PR 내용이 되고, 그 PR은 보통 즉시 머지된다. 애매한 통과는 한 단계 뒤로 미뤄질 뿐 사라지지 않는다 — 중단한다.

이 스킬은 **파이프라인 지휘자**다 — 구현·리뷰·수정의 본체 로직은 각 하위 스킬이 이미 자기완결한다. `/ship`은 순서·게이트·중단만 관장한다.

> **⚠️ 하위 스킬의 리포트는 턴의 종료점이 아니다.** 각 하위 스킬은 단독 호출용으로 쓰여서 자기 리포트를
> 내고 끝나는 모양이고(`/code-review`의 "다음: /refactor", `/tdd`의 "다음: /implement"), 그 문장이 **다음
> 단계를 사용자에게 넘기라는 지시처럼 읽힌다.** `/ship` 안에서는 아니다 — **같은 턴에서 곧바로 다음
> 단계를 실행한다.** 멈추는 것은 아래 "중단 처리"의 조건뿐이고, 그때도 리포트 형식이 정해져 있다.
>
> 실제로 이 지점에서 두 번 멈췄다 (2026-09-08·09 — `/code-review` 리포트 뒤, 그리고 사용자가 끼운
> `/bugshot-qa` 라운드 뒤). **판정 질문**: 방금 낸 것이 "중단 리포트"인가 "단계 리포트"인가 — 후자면
> 아직 턴이 끝나지 않았다.

## 사용

- `/ship <변경 설명>` — 설명을 `/tdd`·`/implement`에 실어 시작.
- `/ship` — 직전 컨텍스트(방금 합의한 변경)에서 대상 자동 판단.
- `/ship bypass <변경 설명>` — **스코프 가드 바이패스.** 아래 적용 범위 판정만 건너뛴다. 단계·게이트·push(dev)는 **전부 그대로** 돈다.

## 적용 범위 (스코프 가드 — 착수 전 판정)

**작은·외과적 변경 전용.** 아래 중 하나라도 해당하면 **중단하고 수동 흐름(`/feature`부터)을 권한다**:

- 여러 서브시스템에 걸친 기능 (세 흐름 중 둘 이상을 동시에 건드림)
- **비범위 항목**을 요구 — `docs/PRODUCT.md` §4.2. 범위 결정은 사용자 몫이다
- **코어 불변식 변경** — export 결정성 규칙, blob SHA 계약, 커밋·PR 전략, 인증 경계 (ARCHITECTURE §1·2·3·6)
- **destructive 스키마 변경** — 2단계 배포가 필요해 한 파이프라인에 안 들어간다
- `docs/features/<slug>/`가 필요한 신규 기능

`lib/` 순수 함수 수정, 국소 버그픽스, 단일 컴포넌트 소변경, additive 스키마 컬럼 추가 같은 **한 영역 집중 변경**만 대상.

**브랜치 확인**: `git branch --show-current`가 `dev`여야 한다. **`main`이면 중단한다** — 작업은 dev에서 하고 main은 `/merge`만 건드린다.

### 바이패스 모드 (`/ship bypass`)

**이미 설계가 끝난 큰 변경을 파이프라인에 태우기 위한 정식 경로다.** `/feature`로 `docs/features/<slug>/`를 산출해 설계·태스크가 확정됐다면 규모 때문에 막을 이유가 없다 — 스코프 가드의 목적은 "설계 없이 큰 걸 자동으로 밀어붙이는 것"을 막는 데 있다.

- **완화되는 것: 위 적용 범위 판정뿐.** 단, **비범위 항목과 destructive 스키마는 바이패스로도 통과하지 않는다** — 전자는 사용자 결정이고 후자는 배포가 2단계로 쪼개져야 해서 구조적으로 불가능하다.
- **완화되지 않는 것 — 나머지 전부**: 브랜치 확인, 0단계 클린 워크트리 전제, 모든 단계 게이트, 중단 처리 규약, 하위 스킬 각자의 금지 사항. push(dev)도 그대로 수행한다.
- **feature 문서가 있으면 그것을 계획 원본으로 쓴다.** `tasks.md`의 태스크·검증 항목을 0단계 인테이크에 싣고 1·2단계에 전달한다. 파이프라인이 태스크를 새로 발명하지 않는다.
- **문서가 단계를 나눠 놨으면 한 번에 한 단계만 태운다.**
- **최종 리포트에 바이패스 사용을 명시**한다 (건너뛴 판정, 계획 원본 경로).

## push 권한 / 런타임별 종착점

**Claude Code에서는 마지막에 `/push`까지 자동 수행한다 — dev 푸시 = preview 배포다.** `/ship` 호출은 "dev까지 보내라"는 지시로 읽는다. **프로덕션 배포는 사용자가 `/merge`를 명시적으로 불러야 일어난다.** 리포트 마지막 줄에 그 사실을 남긴다.

**Codex에서는 마지막 커밋(10단계)까지만 돌고 멈춘다.** 원격으로 나가는 건 Claude Code 단일 창구다 (`/push`·`/merge` 미러도 없다). 최종 리포트에 **"dev 푸시 대기 — Claude Code에서 `/push` 실행"**을 남기고 종료한다. 브랜치 확인은 그대로 적용한다.

⚠️ **Codex는 6.5단계(`/design-sync`)도 못 돈다** — `ego-browser`와 `DesignSync` 도구가 없다. 시안이 있는 화면을 건드린 변경을 Codex에서 `/ship`으로 돌렸다면, 최종 리포트에 **"시안 대조 미검증"**을 남기고 Claude Code에서 `/design-sync`를 따로 돌릴 것을 적는다. ⚠️ **그 줄을 "스킵"으로 적지 않는다** — 스킵은 "볼 것이 없었다"이고 이쪽은 "봐야 하는데 못 봤다"다.

## 파이프라인 단계 + 게이트

`[영향 게이팅]` 표시 단계는 앞 단계 보고의 플래그가 있을 때만 실행한다.

### 0. 인테이크
- 스코프 가드·브랜치 확인. 실패 시 중단.
- **워크트리 소유권 게이트** (⚠️ `/push` 0b와 같은 규칙 — 2026-09-16 신설): `git status --porcelain`의
  **추적 중인** 변경(`M`·`D`·`A`·`R`) 중 **이번 세션이 건드리지 않은 것**이 하나라도 있으면 **중단**한다.
  다른 창구(Codex · 다른 Claude 세션 · 다른 머신)가 **같은 체크아웃**에서 작업 중이라는 뜻이다.
  - ⚠️ **`/ship`은 `/push`보다 노출이 크다** — 이 스킬은 0단계에서 **먼저 커밋**하고 그 뒤로도 단계마다
    커밋한다. 남의 미완성 편집을 내 이름으로 싣기 시작하면 되돌릴 자리가 여러 곳으로 흩어진다.
  - ⚠️ **"다른 워크트리에서 작업한다"는 말을 근거로 쓰지 않는다** — `git worktree list`로 확인한다.
    2026-09-16에 그 말을 믿고 안 겹친다고 판단했는데 **체크아웃이 하나였다.**
  - ⚠️ **미추적(`??`)은 중단시키지 않고 보고만 한다** — 스테이지하지 않는 한 커밋에 못 들어간다.
  - ⚠️ **모든 단계의 게이트 숫자가 함께 오염된다** — `pnpm test`·`build`는 HEAD가 아니라 **워크트리**를
    잰다. 중단 리포트에 그 숫자를 적지 않는다.
  - 중단 리포트에 담을 것: 남의 것으로 보이는 경로 · `git log --oneline -3` · **"그 작업이 커밋되면 다시 부르라"**.
- **클린 워크트리 전제**: 위 게이트를 지난 **내 미커밋 변경**이 있으면 파이프라인 시작 전에 **먼저 별도 커밋**한다 (내용을 파악해 영문 메시지로, 허락 없이). 파이프라인 자체 커밋과 기존 잔여 변경을 섞지 않으려는 것.
  - 단, 미커밋 diff가 **이번 대상 변경과 겹치면** 커밋하지 말고 **중단+리포트** — `/tdd`가 테스트를 먼저 박는 순서가 이미 깨졌다.
  - ⚠️ **경로를 하나씩 명시해 stage한다** — `git add -A`·디렉터리 통째는 **그 아래 남의 파일까지** 싣는다. 위 게이트가 못 막는 유일한 구멍이다.
- **`docs/PRODUCT.md`·`docs/ARCHITECTURE.md` 관련 섹션 확인** — 대상이 코어 로직이면 불변식을 파이프라인 전체에 들고 간다.
- 변경 설명 확정.

### 1. `/tdd`
- 변경을 재현/규정하는 테스트 작성 (regression 또는 interface).
- **게이트**: red 확인됨 (또는 `/tdd` 분류표상 스킵 대상 — 이유 한 줄 기록). red를 못 만들면(예상외 green) 중단+리포트.

### 1.5 커밋 #0 (test) — 무조건
- 1단계가 만든 **테스트 코드만** 커밋. `test: ...` 스코프, 영문.
- **red 상태로 커밋하는 것이 정상이다.** 테스트를 먼저 박은 사실을 히스토리에 남기는 게 목적이고, 3단계 커밋과 섞으면 그 증거가 사라진다.
- **스킵 조건은 하나뿐**: 1단계가 분류표상 스킵으로 파일을 하나도 만들지 않은 경우.
- 1단계가 프로덕션 코드를 건드렸다면 `/tdd` 금지 사항 위반이므로 **중단+리포트**.

> **주의**: 이 커밋 하나만 놓고 보면 `pnpm test`가 red다. `/push`의 로컬 게이트는 파이프라인 끝(전부 green인 HEAD)에서 돌므로 red가 dev에 나가지는 않지만, `git bisect`가 이 커밋에 착지하면 실패를 만난다.

### 2. `/implement`
- 테스트를 green으로. 4관점 자체 검증으로 자기완결.
- **게이트**: `pnpm test` 전체 green + `pnpm typecheck` 통과 + 🔴/🟡 전부 해소(2회 루프 내). 미해소면 **중단+리포트**.
- **플래그 수집**: "스키마 영향"·"문서 영향"·"postmortem 후보"를 기록 (뒤 단계 게이팅).

### 3. 커밋 #1 (feat/fix)
- **구현만** 커밋. 테스트는 1.5에서 이미 커밋됐다. 영문 메시지.
- 2단계가 테스트를 수정했으면(구현 중 드러난 기대값 정정) 그 변경도 함께 싣는다 — 되돌리는 게 아니라 이어지는 수정이다.

### 4. `/code-review`
- 커밋된 변경분 정적 리뷰. **리포트 전용이라 게이트 없음** — 발견 목록을 5단계로 전달.
- **다만 이 파이프라인의 끝이 `/merge` 바로 앞이므로, 🔴이 하나라도 있으면 5단계를 스킵할 수 없다.**
- ⚠️ **그 리포트를 내고 멈추지 않는다.** 게이트가 없다는 것은 "실패로 중단할 조건이 없다"는 뜻이지
  "여기서 사용자에게 넘긴다"가 아니다 — 발견이 있으면 **같은 턴에서** 5단계를 실행한다. 이 스킬이
  실제로 여기서 멈춘 전례가 있다 (2026-09-08).

### 5. `/refactor` (발견이 있을 때)
- 🔴/🟡를 지정해 수정 (버그성은 회귀 테스트 red→green).
- 발견 0이거나 ⚪만 있으면 스킵(보고).
- **게이트**: test green + typecheck 통과. **회귀 위험 항목**(기대값 변경·export 출력 변경·스키마 변경)은 `/refactor`가 확인을 요구하므로 그 지점에서 **중단+리포트**.
- **🔴이 남은 상태로 6단계 이후로 진행 금지** — dev에 올라가면 다음 `/merge`가 그것을 프로덕션으로 데려간다.

### 6. 커밋 #2 (refactor)
- 5단계가 코드를 바꿨을 때만.

### 6.5 `/design-sync` [영향 게이팅 — Claude Code 전용]

**시안이 있는 화면을 건드렸으면 여기서 대조한다.** `/code-review`·`/refactor`는 **코드**를 보고, 이 단계는 **시안과 같은가**를 본다 — 값이 맞고 표현만 틀린 부류는 앞의 둘도 `pnpm test`도 원리적으로 못 본다 (2026-09-13: 새 프로젝트 모달이 핸드오프와 29곳 어긋난 채 3,000개가 green이었다).

- **트리거 (둘 다 참일 때만)**:
  1. 이 파이프라인의 커밋이 `components/**`·`app/**`의 `.tsx`나 `app/globals.css`를 건드렸다.
  2. 그 화면의 **핸드오프가 실재한다** — `DesignSync list_files`로 확인한다.
- **둘 중 하나라도 아니면 스킵하고 사유를 보고한다.** ⚠️ **"화면을 건드렸는데 시안이 없다"와 "화면을 안 건드렸다"를 같은 문장으로 적지 않는다** — 앞엣것은 다음에 시안이 생기면 되돌아올 자리다.
- **게이트**: `/design-sync`의 실측이 전부 일치하고 리뷰 지적이 0일 때 통과. **불일치나 지적이 남으면 중단+리포트** — 그 루프는 자기 안에서 수정→실측→리뷰를 돌리므로, 여기까지 왔는데 남았다는 것은 사람 판단이 필요하다는 뜻이다.
- ⚠️ **Codex에는 이 단계가 없다** (`ego-browser`도 `DesignSync`도 없다). Codex 런타임이면 **스킵하고 리포트에 "미검증"으로 남긴다** — 스킵을 통과로 적지 않는다.
- ⚠️ **`/ship`은 작은 변경용이라 이 단계가 파이프라인에서 가장 무겁다.** 시안이 있는 화면을 **여러 개** 건드리는 변경이면 `/ship`의 스코프 가드가 먼저 막았어야 한다 — 도달했다면 중단하고 `/design-sync`를 단독으로 돌릴 것을 권한다.

### 6.6 커밋 #2.5 (design-sync)
- 6.5단계가 코드를 바꿨을 때만. prefix는 그 변경의 성격을 따른다(`fix(ui):`·`feat(ui):`).
- ⚠️ **문서는 `/design-sync` 7단계가 자기 규약대로 문서별 커밋을 이미 만든다** — 여기서 중복으로 만들지 않는다.

### 7. `/db` [영향 게이팅]
- 2단계 "스키마 영향" 플래그가 **additive**일 때만. **destructive면 여기 오기 전에 스코프 가드가 막았어야 한다** — 도달했다면 중단+리포트.
- 마이그레이션 생성 + SQL 확인 + generate/typecheck/test.
- **게이트**: 마이그레이션 생성됨, SQL이 의도와 일치, test green. 드리프트 검출 시 **중단+리포트**.
- **`db:deploy`는 돌리지 않는다** — 프로덕션 스키마를 넓히는 것은 `/merge` 1단계다. 이 파이프라인은 dev DB(`pnpm db:migrate`)까지만 건드린다.

### 8. 커밋 #3 (db) — 확인만
- 커밋 자체는 7단계 `/db`가 자기 규약(6단계 — 스키마+마이그레이션만, `chore(db):`/`feat(db):`)대로 이미 만들었다. 하위 스킬 중 `/db`만 커밋 권한이 있다.
- 이 단계는 그 커밋 해시를 수집하고, 코드 변경이 섞이지 않았는지 확인만 한다. 섞였으면 **중단+리포트**.

### 9. `/postmortem` [영향 게이팅]
- **트리거**: 3단계 커밋이 `fix:`이거나, 2단계 "postmortem 후보" 플래그가 있을 때. 둘 다 없으면 스킵(사유 보고).
- **게이트**: 항목 추가, 또는 trivial 필터로 "항목 없음" 기록. **소프트 게이트 — write-only라 halt 없음.**
- **소환 회로 완성**: `/ship`은 2·4·5단계에서 하위 스킬을 통해 POSTMORTEM을 grep(읽기)한다. 이 스테이지가 쓰기를 담당해 한 바퀴 안에서 루프가 닫힌다.

### 10. 커밋 #4 (docs)
- 9단계가 POSTMORTEM을 바꿨을 때만 (`docs(postmortem):`).
- 2단계 "문서 영향" 플래그는 여기서 소비하지 않는다 — PRODUCT/ARCHITECTURE/DIRECTORY/CLAUDE 갱신 주체는 11단계 `/push`의 4단계(문서 신선도)다. 플래그를 트라이아지 힌트로 전달만 한다.

### 11. `/push` = dev 푸시 (preview 배포) [Claude Code 전용 — Codex는 10단계에서 종료]
- `/push`가 로컬 검증 게이트(**typecheck + test + build**) → dev 마이그레이션 확인 → 문서 신선도 → Codex 미러 → 푸시를 순서대로 돈다. `build`가 셋 중 유일하게 RSC 경계를 본다.
- **게이트**: `/push`의 모든 단계 통과. 어느 단계든 실패하면 **중단+리포트**.
- **주의 — 층위가 다르다**: `/push`의 로컬 게이트는 푸시될 HEAD 전체를 검증하고, 2단계 게이트는 구현 시점의 검증이다. 그 사이에 4·6·8·10단계 커밋이 얹히므로 둘 다 도는 게 정상이다.
- **여기서 파이프라인이 끝난다.** `/merge`를 이어 부르지 않는다 — 프로덕션으로 보낼지는 사용자가 정한다.

### 12. 최종 리포트
- 단계별 통과/스킵/중단 요약 + 커밋 해시들 + **dev 푸시 여부** + CI run URL(결과 미확정) + 남은 수동 항목.
- **6.5단계는 셋 중 하나로 적는다**: `시안 대조: 통과(<화면>)` / `시안 대조: 해당 없음(<사유 — 화면 미변경 또는 시안 없음>)` / `시안 대조: 미검증(Codex 런타임 — Claude Code에서 /design-sync 필요)`.
- **프로덕션에 배포되지 않았다는 사실을 마지막 줄에 명시한다** — `/merge`가 남은 수동 항목이다. 마이그레이션이 포함됐으면 `/merge` 1단계의 `pnpm db:deploy`도 함께 적는다.

## 중단 처리 (즉시 중단+리포트)

```
🛑 중단: <단계> 게이트 실패
사유: <한 줄>
워크트리: 내 것만 / ⚠️ 남의 추적 변경 <경로들> — 게이트 숫자는 근거가 아니다
dev 푸시 여부: 아직 푸시되지 않음 / 푸시됨(<해시>, preview 배포 중)
프로덕션: 배포되지 않음 — /merge 필요
현재 상태: 커밋 <해시들> / 미커밋 <있으면>
남은 단계: <목록>
재개: <사용자가 무엇을 결정/수정하면 이어갈 수 있는지>
```

중단 후 **임의로 우회·강행하지 않는다.** 사용자 지시를 기다린다.

## 다른 스킬과의 분리

- 개별 스킬 — 단계 하나씩 수동 진행. **푸시하지 않고 커밋만 쌓고 싶으면 이 경로를 쓴다.**
- `/ship` ← 여기. **작은 변경의 전 단계 자동 오케스트레이션 + 게이트 + dev 푸시(preview)**. 프로덕션은 뒤이어 `/merge`.

## 금지 사항

- **큰·다영역 변경에 사용 금지** — 스코프 가드에 걸리면 수동 흐름 권하고 종료. `/ship bypass` 명시 호출은 예외.
- **바이패스 임의 적용 금지** — 사용자가 `bypass`를 명시하지 않았는데 가드에 걸리면 스스로 켜지 않는다. "이 정도면 괜찮겠지" 판단 금지.
- **비범위·destructive 스키마·코어 불변식 변경은 바이패스로도 진행 금지.**
- **게이트 실패 우회·강행 금지** — 즉시 중단+리포트. 끝이 dev로 바뀌었어도 애매한 통과는 `/merge`까지 그대로 흘러간다.
- **`/merge` 자동 실행 금지.** 프로덕션 배포는 사용자가 별도로 부른다.
- **🔴 미해소 상태로 11단계 진행 금지.**
- **`pnpm db:deploy` 자동 실행 금지** — 프로덕션 DB를 바꾸는 일이다.
- **워크트리 소유권 게이트 우회 금지** — 이번 세션이 안 건드린 **추적 중인** 미커밋 변경이 있으면 **한 단계도 진행하지 않는다.** 커밋이 여러 개 쌓이는 파이프라인이라 되돌리는 비용이 `/push`보다 크다.
- **`git add -A`·디렉터리 통째 stage 금지** — 단계마다 경로를 하나씩 명시한다.
- **하위 스킬의 금지 사항 무력화 금지.**
- **단계 임의 생략 금지** — `[영향 게이팅]` 단계만 플래그 부재 시 스킵(사유 보고).
- **하위 스킬 리포트를 낸 뒤 턴을 끝내지 않는다.** "다음: /refactor" 같은 줄은 단독 호출용 문장이고
  이 파이프라인에서는 **내가 그 다음을 실행한다.** 중단은 "중단 처리"의 조건일 때만이고 그때는 🛑
  형식으로 쓴다 — 그 형식이 아닌 리포트로 턴이 끝나면 파이프라인이 멈춘 것이다.
- **사용자가 끼운 추가 단계에도 같은 규칙이 적용된다** (예: `/push` 전 `/bugshot-qa`). 그 스킬도
  리포트 전용이라 자기 리포트로 끝나지만, **루프를 지시받았으면 green까지 이어간다.**
