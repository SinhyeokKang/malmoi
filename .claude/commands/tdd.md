테스트 코드를 **먼저** 짜는 단계 전용 스킬. 이 스킬은 **테스트 파일만** 만들고, red를 확인하고, 끝낸다.

## 사용

- `/tdd` — 직전 컨텍스트(`/feature` 산출물 / `/code-review` 발견)에서 모드 자동 판단.
- `/tdd interface <대상 설명>` — **A 모드**: 신규 함수·헬퍼 시그니처를 테스트로 결정.
- `/tdd regression <버그 설명>` — **B 모드**: 발견된 버그·엣지케이스를 재현하는 테스트.

## 두 가지 모드

### A. 신규 인터페이스 박기 (`/feature` 직후)

테스트가 시그니처를 결정하게 한다. 대상 모듈이 없어도 OK — import 실패가 첫 red다. 시그니처는 호출하는 쪽 관점으로 짜고, 케이스 순서는 단순한 정상 → 엣지(빈 입력·경계값·undefined) → 에러.

### B. 회귀 테스트 박기 (`/code-review` 직후, 또는 버그 발견 시)

버그를 **재현하는** 테스트부터. 픽스 전에 빨간불을 확인해야 진짜 같은 버그를 잡았다고 보장할 수 있다. 기존 테스트가 있으면 같은 파일에 case 추가.

## TDD 강제 vs 스킵 (이 프로젝트 기준)

### ✅ TDD 강제 — 거의 항상 이 스킬을 호출한다

- **`lib/adapters/`의 writer** — 결정성이 이 프로젝트의 핵심 불변식이다. **같은 입력 두 번 호출이 같은 문자열**이라는 케이스를 반드시 포함한다.
  - 재생성(`chrome-locales`·`json-catalog`): 정렬 순서·들여쓰기·끝 개행·`orphaned` 제외를 각각 케이스로 박는다
  - 수술적 치환(`ts-dict`): 규칙이 반대다 — 빈 줄·주석·키 순서가 **보존**되는지, 값이 안 바뀌면 원본이 바이트 동일하게 나오는지, 이스케이프가 필요한 값(`"`·`\`·개행)이 재파싱을 견디는지
- **`lib/githash.ts`** — `git hash-object` 실측값을 **골든 값으로 박는다**. 빈 문자열 / ASCII / 한글 / 이모지 4건 최소 (UTF-8 바이트 길이 버그가 여기서 잡힌다)
- **`lib/scan/`** — 키 추출. 리터럴 정상 / 동적 인자(실패해야 함) / `@l10n-keys` 주석 / 주석 속 호출(무시해야 함) / 중복 키 다른 원문(실패해야 함)
- **정렬·그룹핑 헬퍼** — `namespace` 파생, 키 정렬, 필터 판정
- **stale 전파 로직** — `sourceHash` 변경 시 어떤 `Translation`에 `needsReview`가 서는지 (순수 함수로 분리해 테스트)
- **재현되는 버그** — 입력으로 깨지는 게 확정된 케이스

### ❌ TDD 스킵 OK — 이유 한 줄 보고 후 종료

- **React 컴포넌트 렌더·인터랙션** — 실 브라우저 검증이 더 정확. e2e가 서면 그쪽으로
- **Prisma 쿼리 자체** — DB 모킹 비용 > 가치. 쿼리를 감싸는 순수 로직만 강제
- **GitHub API 호출** — fetch 모킹 비용 > 가치. 단 **요청 페이로드를 조립하는 순수 함수는 강제**(`base_tree` 누락 같은 치명적 실수가 여기서 잡힌다)
- **Auth.js 콜백 배선** — 프레임워크 통합. 단 **org 멤버십 판정 함수는 강제**(fail-closed가 지켜지는지)
- **Next.js 라우트 핸들러 껍데기** — 핸들러가 부르는 순수 함수는 강제

스킵 결정 시 **이유를 한 줄로 보고**하고 종료. "스킵 OK라 안 짭니다" 무성의 금지.

## 절차

1. **모드·범위 결정** — 인자에서 추출. 자동 모드는 직전 대화가 `/feature` 산출물이면 A, `/code-review` 발견 리스트면 B.
2. **`docs/TASKS.md`에서 완료 조건을 가져온다** — 현재 단계의 태스크마다 "검증:" 줄이 붙어 있고 **그게 곧 테스트 케이스 목록이다.** 새로 발명하기 전에 그것부터 덮는다. 목록에 없는 케이스를 추가하는 건 좋지만, 목록에 있는 걸 빼먹으면 완료 판정이 불가능해진다.
3. **`docs/POSTMORTEM.md` grep** — 대상 영역의 과거 함정을 케이스로 되살린다. 같은 버그를 두 번 밟지 않는 유일한 장치다.
4. **테스트 파일 작성** — 위치는 대상 모듈 옆 `__tests__/<name>.test.ts`. 케이스 이름은 한국어로 무엇을 보장하는지 쓴다.
5. **red 확인** — `pnpm test`를 돌려 **실제로 실패하는지** 본다.
   - 예상외로 green이면 **중단하고 보고**한다. 테스트가 버그를 안 재현하거나 이미 구현돼 있다는 뜻이라, 그대로 넘어가면 가짜 안전망이 남는다.
6. **리포트.**

## 리포트

```
🔴 tdd: <모드> — <대상>
파일: <경로>
케이스: <개수>건 — <핵심 케이스 요약>
TASKS 완료 조건 커버: <n>/<m>건 (미커버가 있으면 이유)
red 확인: <실패 메시지 요약>
POSTMORTEM 소환: <인용 항목 또는 없음>
스킵: <이유> (스킵한 경우)
다음: /implement
```

## 금지 사항

- **프로덕션 코드 생성·수정 금지.** 테스트 파일만. 대상 모듈이 없어 import가 깨지는 게 정상이다.
- **커밋 금지** (`/ship`이 커밋 #0을 담당).
- **테스트를 green으로 만들려 하지 않는다** — 그건 `/implement`다.
- **red를 못 만들었는데 진행 금지** — 중단하고 보고.
