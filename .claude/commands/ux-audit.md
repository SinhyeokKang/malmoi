같은 개념(상태·동작·정보)이 화면·맥락마다 **다른 색, 다른 낱말, 다른 형태, 다른 배치, 다른 순서**로 표현되는 것을 코드베이스 전체에서 찾는다.
**리포트 전용 스킬** — 자동 fix 안 하고, 커밋도 안 한다. `/audit`과 같은 레인이다.

**이 스킬을 만든 이유** (2026-10-01, ux-drift-unify): 2026-09-30 전수조사에서 원시 181건 · 🔴 15건이 나왔다. 같은 "동기화 실패"가 `/projects` 행에서는
회색, Home Alert에서는 빨강, Home 주의 카드에서는 호박이었다. 원인은 규칙이 컴포넌트 단위였고, 화면 단위 핸드오프가 정본이었고, 테스트가
한 화면 안의 결정만 고정했고, **리뷰·감사의 범위가 전부 diff였다**는 것이다 — `/code-review`는 변경분만, `/audit`은 불변식·경계·부채만 본다.
화면 사이의 어긋남은 어느 쪽도 보지 않았다.

## 언제 돌리나

- **`/merge` 전에 한 번** — 프로덕션에 나가는 화면 묶음을 한 번에 본다.
- **새 화면 핸드오프(`/design-sync`)가 dev에 들어간 뒤 한 번** — 화면 단위 시안은 옆 화면을 모른다.

## 사용

- `/ux-audit` — 차원 일곱 전부 병렬.
- `/ux-audit <차원> [차원...]` — 지정 차원만(`state` · `wording` · `actions` · `structure` · `tokens` · `judgments` · `guide`).

## 다른 스킬과의 분리

- `/code-review`: **변경분**만. 이번 diff가 옆 화면과 어긋나는지는 못 본다.
- `/audit`: 전체이되 **불변식·원칙·경계·부채**. 화면 표현은 대상이 아니다.
- `/design-sync`: **신규 페이지 하나**를 시안과 대조. 다른 화면과의 일관성은 대상이 아니다.
- `/ux-audit` ← 여기. **화면과 화면 사이**.

## 절차

### 1. 기준 로드

정본은 셋이다 — **`docs/DESIGN.md` §2.4(상태 톤·낱말·글리프·동작 규칙 표)와 §10.1(개념 색인 — ko·es 열 포함)** · `messages/en.tsx`(원문 — ko·es 사전은 같은 키의 번역이고 §10.1 열과 `dictionary-consistency.test.ts`가 낱말을 묶는다) · `components/ui/*`(variant → 실제 클래스).
코드판 정본은 `lib/status/canon.ts`의 `STATE`다(§2.4가 가리킨다).

**이미 테스트가 막는 것을 먼저 읽는다** — 그 부류는 red가 났을 것이므로 다시 찾지 않고, 테스트가 **못 보는 자리**를 찾는다:

| 테스트 | 막는 것 |
|---|---|
| `lib/status/__tests__/cross-screen.test.ts` | 목록·Home·Settings·Sources·거부 문구가 같은 입력에서 같은 상태(연결·실패·보류·가용성)를 말한다 |
| `components/__tests__/visual-system.test.ts` "화면 간 불변식" | `ExternalLink` 0 · `ui/` 밖 수제 스피너(허용 목록) · 셸 안 radius 16 · `partial-import` 손 비교 · `IconTile` 상태 색 덮기 · `TriangleAlert` + danger |
| `components/__tests__/action-rules.test.tsx` | 확정 `danger` ⇒ 트리거 `danger`(Sync 예외) · 셸 안 독립 파랑 링크 = 새 탭 |
| `lib/i18n/__tests__/terminology.test.ts` | §10.1의 금지 동의어 |
| `lib/guide/__tests__/content.test.ts` | 가이드의 굵은 라벨 = 사전 값 |

`docs/POSTMORTEM.md`에서 UI 표현에 걸린 항목(`grep -n "톤\|낱말\|배지\|variant" docs/POSTMORTEM.md`)도 함께 읽는다.

### 2. 차원별 병렬 감사

차원마다 에이전트를 **동시에** 띄운다(`subagent_type: general-purpose`). 대상: `app/**` · `components/**`(랜딩 목업 포함) · `messages/{en,ko,es}.tsx` · `guide/{en,ko,es}/**`의 화면 서술.
각 에이전트는 **인벤토리 표**(개념 | 화면·맥락 | 형태 | 색 클래스 | 낱말(키 → 텍스트) | file:line)를 만들고 끝에 불일치 목록을 낸다.

| 키워드 | 차원 | 본다 |
|---|---|---|
| `state` | 상태 표현 | 동기화·Publish·연결·검토·미번역·보류·보관·만료 등 — §2.4 표와 어긋나는 곳 전부 |
| `wording` | 문구·용어 | 같은 개념의 동의어(held/paused/deferred), 같은 낱말의 다의어(Missing), 대소문자·마침표·줄임표·단복수, 버튼 동사(Close/Done/Cancel · Remove/Delete/Disconnect/Revoke), 날짜·시각 표기 |
| `actions` | 동작 배치 | 모달·Dialog 버튼 순서와 primary 개수, 헤더 우측·행 우측 동작, 파괴 동작의 variant와 확인 절차, 링크 vs 버튼, 외부 링크 표시 |
| `structure` | 구조 패턴 | 카드 머리(제목·개수·설명·동작), 행(글리프 칸·보조줄·chevron), 빈 상태, 로딩 골격, 에러 경계, 메타 줄 문법(`[배지…] 사실 · 사실`), 행 띠(`BannerLine`) |
| `tokens` | 시각 토큰 | 같은 자리의 raw 색·크기·radius·간격 갈림, 프리미티브 우회(손 조립 알약 · `IconTile` 덮기 · 인라인 `text-amber-*`), 아이콘 의미 충돌(같은 아이콘 다른 뜻 · 같은 뜻 다른 아이콘) |
| `judgments` | 판정 중복 | 같은 상태를 두 곳 이상에서 따로 판정하는 코드 — 판정 함수와 소비처를 짝지어 적는다 |
| `guide` | 가이드 ↔ 화면 | `guide/**` 본문의 라벨·순서·색 서술이 실제 화면과 다른 곳 |

에이전트에게 주는 규칙:
- **추정 금지.** 모든 항목은 file:line 근거가 있어야 한다.
- 클래스 문자열만 보지 말고 **variant → 실제 클래스 매핑**(`components/ui`)을 풀어서 비교한다.
- 테스트 파일은 "그 불일치를 고정하는 단언"이 있는지만 표시한다(고칠 때 같이 바뀔 곳).

### 3. 통합

차원 간 중복을 합친다(같은 결함이 상태·문구·토큰 셋에서 따로 잡힌다 — 근거 행으로 대조한다). 합친 항목에 원본 차원을 모두 적는다.

### 4. 리포트

리포트는 **스크래치패드에 md로** 쓴다(`docs/` 밖 — 원본 항목을 커밋하지 않는다). 대화에는 요약만 낸다.

- 차원별 인벤토리 표(원본 파일 — `1-state.md` … `7-guide.md`) + 통합 리포트(`REPORT.md`)
- 불일치 목록 — 심각도:
  - **🔴 사용자가 다른 상태로 읽는다** — 같은 상태가 두 화면에서 다른 톤·낱말이거나, 되돌릴 수 없는 동작이 한 화면에서만 안전해 보인다. **🔴은 두 화면의 근거 행을 모두 채운다** — 한쪽만 쓸 수 있으면 🟡이다.
  - **🟡 같은 뜻인데 표현이 갈린다**
  - **⚪ 미세**
- 각 불일치에 **정본 제안**(톤·낱말·형태 하나)과 영향 파일 목록
- **결과를 받는 곳**: 🔴는 **이슈 후보**로 목록을 따로 낸다(제출은 사용자가 정한다) · 정본 제안은 **DESIGN §2.4 행 후보**로 낸다 · 테스트로 막을 수 있는 부류는 위 표의 어느 테스트를 넓히면 되는지 적는다
- **사용자 결정이 필요한 것**을 맨 앞 표로 — 두 정본(DESIGN 절끼리, DESIGN ↔ 코드)이 서로 다르게 말해 어느 쪽이 맞는지 코드만으로 정할 수 없는 것
- 끝에 한 줄 요약: 불일치 총수 · 🔴 수 · 가장 넓게 퍼진 부류 셋

### 5. 종료

여기서 끝. 사용자가 리포트를 보고 범위를 정한다(보통 `/feature`로 닫힌 목록을 만든다 — ux-drift-unify가 그 형이다).

## 금지 사항

- **빌드 / typecheck / test 실행 금지** — 정적 코드 읽기만.
- **자동 fix 금지** — 리포트만. **커밋·staging 안 함.** 이슈를 스스로 제출하지 않는다.
- **추측성 발견 남발 금지** — 정본(DESIGN·사전·프리미티브)이나 실제 두 화면의 근거 행을 댈 수 있는 것만.
