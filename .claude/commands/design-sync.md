**시안이 정본이고 구현이 그것을 따라간다.** 이 루프가 존재하는 이유는 2026-09-13에 새 프로젝트 모달에서 확인됐다 — 핸드오프가 px 단위로 확정돼 있었는데 구현이 **29곳** 어긋나 있었고, `pnpm test` 3,000개가 전부 green이었다. **값은 맞고 표현이 틀린 부류는 단위 테스트가 원리적으로 못 본다.**

## 사용

- `/design-sync <화면 이름>` — 그 화면의 핸드오프를 SoT로 한 바퀴.
- `/design-sync <화면 이름> --audit` — **고치지 않고** 대조 리포트만 낸다 (1~2단계까지).

## 언제 쓰나

- **핸드오프가 새로 왔을 때** — 구현 전에 이 루프로 대조표를 먼저 만든다
- **시안이 갱신됐을 때** — 바뀐 것이 무엇인지는 캔버스가 답한다
- **"디자인대로 안 됐다"는 제보를 받았을 때** — 감이 아니라 computed style로 가른다

**안 쓰는 때**: 시안이 없는 화면. 그때 정본은 `docs/DESIGN.md`이고 이 루프는 돌 근거가 없다.

## 전제 조건 (착수 전 확인 — 하나라도 어긋나면 중단)

1. **워킹 트리가 clean하고 `pnpm test`가 green이다.** 섞인 변경 위에서 실측하면 무엇이 원인인지 못 가린다.
2. **`dev` 서버가 떠 있고 그 브라우저가 로그인 상태다.** `ego-browser`가 사용자의 세션을 쓴다 — 로그인 화면이 나오면 거기서 멈추고 사람에게 넘긴다.
3. **대상 화면에 도달할 데이터가 있는가.** ⚠️ **예외 상태가 특히 막힌다** — 후보 0개 화면은 설치된 리포가 전부 로케일 리포라 못 밟았고, 그래서 `i18n-none`을 포크해 붙였다(CLAUDE.md). **못 밟는 갈래는 "검증했다"고 적지 않는다.**

## 절차

### 1. SoT 확보 — 캔버스를 직접 읽는다

```
DesignSync list_files  → 프로젝트의 핸드오프 폴더를 찾는다
DesignSync get_file    → README.md, <화면>.dc.html
```

- ⚠️ **`.dc.html`의 인라인 스타일이 진짜 값이다.** README는 그 요약이고 **둘이 어긋나면 캔버스가 이긴다** — 실제로 README가 `1fr 1fr`인 표가 캔버스에선 폭 결정과 함께 바뀌어 있었다.
- ⚠️ **캔버스는 100KB를 넘는다.** `get_file` 결과가 컨텍스트를 먹으므로 **받자마자 스크래치패드에 저장**하고, 이후에는 `grep -n 'id="1a"'` → `sed -n 'N,Mp'`로 **아트보드 구역만** 읽는다.
- ⚠️ **서브에이전트에는 `DesignSync`가 없다.** 추출을 위임하면 "도구가 없다"로 돌아온다 — **상위 에이전트가 직접 받는다.**
- 아트보드 id는 README의 `## Files`가 적는다(`1a` 기본 / `2a` 로딩 / `4a~` 예외 …). **예외 아트보드를 빼먹지 않는다** — 이번에 놓친 것이 거기 있었다.

### 2. 대조표 — 캔버스 값 ↔ 현재 구현

캔버스에서 뽑을 것: 치수·radius·색·padding·gap·font-size/weight/letter-spacing·line-height·구분선 색 규칙·hover·선택 상태.

- ⚠️ **문서화된 이탈을 이탈로 세지 않는다.** 기능 설계가 시안을 의도적으로 뒤집은 자리가 있다(폭 800→960, 좌측 300→240 …). 그 근거는 기능 문서나 `docs/DESIGN.md`에 있고, **없으면 그것이 진짜 이탈이다.**
- ⚠️ **프리미티브와 어긋나면 프리미티브가 이긴다** — 한 화면만 다른 폼이 되면 안 된다. 단 **시안이 모든 화면을 같은 값으로 그렸다면** 프리미티브를 옮긴다(그때 다른 화면이 함께 움직이는 것을 보고에 적는다).

`--audit`이면 여기서 멈추고 표를 낸다.

### 3. 수정

- ⚠️ **일괄 치환은 `assert`로 강제한다.** 파이썬 `str.replace`는 대상이 없어도 조용히 지나가고, 그 상태로 "고쳤다"고 보고하면 **거짓 보고**가 된다 — 이번 루프에서 실제로 한 번 냈다.
- ⚠️ **주석에 "왜"를 남긴다.** 시안 값을 옮겨 적는 것이 아니라 **그 값이 아니면 무엇이 깨지는지**를 적는다. 다음 사람이 지우지 않을 근거가 거기 있다.
- ⚠️ **안 본 화면의 표현을 바꾸지 않는다.** 공용 프리미티브의 기본값을 손대면 이 루프가 보지 않은 화면이 함께 움직인다 — 필요하면 호출부로 내리고, 그 사실을 `docs/DESIGN.md`에 남겨 다음 사람이 이어받게 한다.

### 4. 런타임 실측 — 눈이 아니라 computed style

```js
// ego-browser: 화면까지 이동한 뒤
await page.evaluate(() => getComputedStyle(el).getPropertyValue("padding"))
```

- ⚠️ **스크린샷으로 판정하지 않는다.** `#f5f5f5`와 `#fff`는 압축된 PNG에서 구별되지 않는다 — **색·치수는 값으로 읽는다.** 스크린샷은 구조(무엇이 어디 있나)를 보는 데만 쓴다.
- ⚠️ **접근성은 CDP로 잰다.** jsdom의 accname 계산은 브라우저와 다르다 — `Accessibility.getPartialAXTree`가 실제 값을 준다. 실제로 jsdom이 `"Branch"`를 내는 자리가 Chrome에서는 `"Branch main"`이었다.

  ```js
  const { nodeId } = await page.cdp("DOM.querySelector", { nodeId: root.nodeId, selector });
  const { nodes } = await page.cdp("Accessibility.getPartialAXTree", { nodeId, fetchRelatives: false });
  ```

- ⚠️ **비동기 값은 같은 시점에 함께 찍는다.** 로드 직후에 재면 Radix가 값을 채우기 전이라 `value: ""`가 나오고, 그것을 결함으로 오진한다.
- ⚠️ **스크롤·hover·선택 상태를 실제로 만들어서 잰다.** `sticky` 헤더가 반투명인 것은 **스크롤시켜야** 보인다.
- **불일치가 하나라도 있으면 3단계로 돌아간다.** 전부 일치할 때까지 이 루프를 돈다.

### 5. 리뷰 — 서브에이전트

실측이 전부 통과하면 리뷰를 건다. **화면에도 테스트에도 안 나타나는 회귀는 여기서만 잡힌다.**

- 프롬프트에 **캔버스 값과 실측값을 표로** 넣는다. 근거 없이 "맞췄다"고 하면 리뷰가 확인할 수 없다.
- **CLAUDE.md를 읽고 그것을 기준으로 보라고 명시한다** — 한국어 주석·`any` 금지·프로토타입·라이트 단일·외과적 변경.
- **못 검증한 것을 숨기지 않는다.** "이 갈래는 브라우저로 못 밟았고 단위 테스트로만 섰다"를 적으면 리뷰가 그 자리를 본다.
- ⚠️ **같은 에이전트를 `SendMessage`로 이어간다.** 새로 띄우면 앞선 판정 맥락이 사라지고, **리뷰가 자기 지적을 정정하는 일**이 실제로 일어난다(이번에 `aria-label`에 대한 1차 지적이 2차에서 뒤집혔고, 그 정정이 없었으면 접근 이름을 0으로 만든 채 끝났다).
- **리뷰 지적이 있으면 3단계로 돌아간다.** 없을 때까지 돈다.

### 6. 방어선 — 실측으로 잡은 것을 테스트로 고정한다

⚠️ **실측은 이번 한 번이고 테스트는 다음에도 돈다.** 브라우저로 잡은 회귀는 **소스 스캐너나 DOM 테스트로 박는다** — 그러지 않으면 다음 리팩터가 같은 자리를 지운다.

- 값이 아니라 **구조**를 센다. 클래스 문자열을 박으면 스타일을 바꾸는 순간 green인 채 결함만 돌아온다.
- ⚠️ **스캐너를 만들었으면 일부러 깨뜨려 red를 확인한다.** 매칭이 0인 스캐너는 방어선이 아니라 장식이다.

### 7. 정본 반영과 커밋

- `docs/DESIGN.md`에 **측정값과 근거**를 올린다. ⚠️ **새 raw 색·새 토큰은 §6.2 등재가 규칙이다.**
- ⚠️ **문서가 코드보다 앞서가지 않는다.** 아직 참이 아닌 것을 사실로 적으면, 그것을 믿은 사람이 의심해야 할 곳을 의심하지 않는다.
- 게이트: `pnpm typecheck` → `pnpm test` → `pnpm build`. **셋 다 green이어야 커밋한다.**
- 커밋은 코드 하나 + **문서별로 하나씩**(CLAUDE.md 규칙).

## 이 루프가 실제로 잡은 것 (2026-09-13, 새 프로젝트 모달)

리뷰가 낸 22건 중 **넷이 이 루프가 만든 회귀**였고, 전부 화면에도 3,100개 테스트에도 안 나타났다:

| 무엇 | 왜 안 보였나 |
|---|---|
| `asChild`가 `<ul>`의 list role을 덮어써 `<li>`가 고아가 됐다 | 시각 동일. 접근성 트리에만 나타난다 |
| `role="combobox"`에 name-from-content가 없어 접근 이름이 **빈 문자열**이 됐다 | 이름을 단언하는 테스트가 하나도 없었다 |
| `sticky` 헤더가 2% 반투명이라 스크롤한 행이 비쳤다 | **스크롤시켜야** 보인다 |
| `<strong>`을 지워 되돌릴 수 없는 경고의 시맨틱이 사라졌다 | 색으로는 남아 있어 화면이 같다 |

⚠️ **그래서 4·5단계를 건너뛰지 않는다.** 3단계만 돌면 "고쳤다"는 보고가 사실이 아닐 수 있다.
