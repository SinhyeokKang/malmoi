## 구현·런타임 기록 — 2026-09-12

- 최종 변경: 페이지 클래스 둘, Dialog Overlay·Content의 z-50, ContentPanel 주석.
  정보 구조·폭·스크롤·이벤트·권한·오류 위치는 유지했다. 새 함수·추상화·스키마는 없다.
- 브라우저 업데이트 후 캡처 장애가 해결됐다. 이전 DOM 실측과 캡처 실패를 완료 근거로 세지 않고
  최신 `10ce111`의 보조 글자 13px 기준(정본 보완 `598d499`)으로 1280×900·1920×1080을 다시 비교했다.
- 정상 일곱 화면과 목록·번역·로그인 기준, 빈 Home/로케일/이력, 고아 로케일, 긴 키·설명·번역,
  실패·경고 이력, OWNER 보관·미준비, 실제 EDITOR 멤버·로케일을 캡처했다.
  프로젝트 화면은 오른쪽 320px 패널을 포함한다. 수정 없는 화면은 기존 primitive와 밀도 차이를 유지한다.
- 멤버는 실제 OWNER·EDITOR 모두 제목 행 36px. EDITOR에게 초대·역할 변경·삭제 조작이 없다.
  초대 Dialog의 입력·Enter 제출(기존 멤버 오류)·Escape·트리거 포커스 복귀를 확인했다.
- Dialog 실물에서 관리 표의 sticky z-10 헤더가 입력 라벨 위로 비치는 결함을 발견했다.
  포털 메뉴와 같은 z-50을 배경·본문에 지정했다. `dialog-layer.test.tsx`가 수정 전 red였고,
  수정 후 두 해상도 캡처와 hit test로 표 머리보다 위에 표시되는 것을 확인했다.
- 수동 온보딩은 기존 리포의 **탐지만** 실행했다. 두 해상도에서 `en-GB` 입력, sans 14px/20px·36px,
  포커스 링, 다음 필드로 Tab 이동을 확인했다. 프로젝트 생성·첫 적재는 실행하지 않았다.
- 계정·설정의 `?e=denied` Alert와 연결 없음, 미준비 설정, 잘못된 초대 링크를 비교했다.
  기존 disabled 로케일 폼과 온보딩 조작, 초대 제출 pending을 확인했다. 공유 Input·Button 구현은 그대로다.
