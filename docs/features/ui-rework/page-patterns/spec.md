# 페이지 톤앤매너 통일 — spec

상태: **구현·런타임 비교 완료, 리뷰 대기**. 2026-09-12, 설계 기준 `0645bad`.

## 판정

**전체 페이지의 톤앤매너 통일은 지금 진행할 수 있다.** 로그인·프로젝트 목록·번역·앱 셸에서
확정된 시각 표현을 나머지 일곱 화면에도 적용한다. 새 본문 시안은 이 작업의 선행 조건이 아니다.

**2026-09-12 사용자 범위 확정: “전체적인 톤앤매너를 맞추는 작업”.** 기존 정보 구조와 동작을
유지하고 색·서체·여백·테두리·모서리·그림자·컨트롤·상태 표시의 시각적 일관성을 맞춘다.
새 디자인 시스템이나 별도 SaaS 단계를 만들지 않는다.

## 목표 톤앤매너

| 축 | 맞출 인상과 구체적 기준 |
|---|---|
| 표면 | 중립적인 회색 캔버스 위 흰 콘텐츠. 옅은 테두리와 낮은 그림자로 구분하고 장식색을 늘리지 않는다 |
| 글자 | Pretendard, 본문 400·제목/라벨 500. 크기와 보조 텍스트의 명도로 계층을 만들고 굵기로 과장하지 않는다 |
| 여백·밀도 | 같은 역할의 제목·설명·필드·행은 같은 간격 체계를 쓴다. 페이지 머리와 본문의 시작선, 섹션 간격을 정돈한다 |
| 선·모서리 | 기존 토큰과 프리미티브의 border·radius·shadow를 사용한다. 패널·카드·입력의 서로 다른 역할은 유지한다 |
| 조작 | 같은 크기·역할의 버튼과 입력은 높이·모서리·아이콘·hover·focus의 시각적 무게가 같다 |
| 상태 | 기존 의미에 맞는 배지·Alert·토스트의 색과 서체를 사용한다. 평상시 정보보다 경고·오류가 먼저 읽힌다 |

## 사용자와 문제

사용자는 번역 편집자와 프로젝트를 연결·관리하는 개발자다. 화면을 이동해도 같은 제품의 시각 언어가
이어져야 한다. 기능이나 화면 구성이 달라도 표면·글자·조작의 표현은 일관돼야 한다.

neutral 토큰, 400·500 weight, 기본 컨트롤 36px, 셸과 패널 머리는 이미 공통 적용돼 있다.
이번 작업은 이 기반을 다시 만드는 것이 아니라 **나머지 화면의 개별 스타일과 조합을 대조해 남은
차이를 맞추는 것**이다. 같은 토큰을 쓰더라도 페이지에서 덧댄 간격·글자·border가 다르면 인상이 갈린다.

코드에서 확인한 후보는 수동 온보딩 기준 로케일 입력의 mono, 멤버 제목 행이 Invite 버튼 유무에
의존하는 높이, 현재 구현과 다른 여백 주석이다. 실물 비교에서 Dialog 겹침 순서도 추가로 수정했다. 코드 근거와 기준은 [design.md](./design.md)에 있다.

## 범위 게이트

[MVP §2·§7](../../../MVP.md)와 [SAAS §4.2·§4.3·§8](../../../SAAS.md)를 대조했다.
기존 편집·관리 UI의 디자인 정렬이므로 통과한다. 병합·키/로케일 CRUD·새 권한·알림 시스템을 요구하지 않는다.
정본은 SAAS(범위), DESIGN(시각 규칙), ARCHITECTURE(경계)이고 이 문서는 적용 계획과 근거다.

## 완료 조건

### 이번 문서화

1. 기준 화면의 패턴마다 코드 출처·전역/전용 구분·적용 대상이 있다.
2. 나머지 일곱 화면의 유지 사항과 변경 후보가 명시돼 있다.
3. 이미 구현된 기반을 신규 태스크로 재설계하지 않는다.
4. 아래 구현 완료 조건을 검사하는 배송 순서와 커밋 경계가 있다.

### 후속 공통 적용

1. 정상 셸 화면은 `ContentPanel`/`main` 하나, 머리와 본문은 형제이며 본문만 스크롤한다.
2. 정상 셸 페이지 제목은 `text-xl font-medium`, 조작 유무·권한과 무관하게 제목 줄 최소 36px다.
   limited/fluid 각각 안에서 머리와 본문의 왼쪽 기준선이 일치한다. 상태 전용 화면은 제목을 억지로 추가하지 않는다.
3. `Input`·`Select`와 기본 버튼은 36px, 작은 행 액션은 기존 `sm`, 인증 버튼만 `lg`다.
   `Textarea` 자동 높이와 번역 셀의 별도 포커스 표면을 보존한다.
4. 새 필터나 통계를 추가하지 않고 기존 URL·권한·조회 결과의 의미를 보존한다.
5. 배지·Alert·빈 상태의 서체·색·간격을 기준 표현에 맞춘다. 현재 표시 위치와 의미, 복구 방법·진단은 유지한다.
6. **1280×900·1920×1080 실제 브라우저**에서 각 배송 대상의 정상·빈 상태·긴 내용·오류를 검증한다.
   프로젝트 축은 오른쪽 320px 패널을 켠 상태로 잰다. 소스/DOM 테스트만으로 시각 검증 완료를 선언하지 않는다.
7. 두 뷰포트에서 기준 화면과 대상 화면을 나란히 비교해 위 여섯 축의 차이를 설명할 수 있어야 한다.
   역할상 필요한 차이는 design에 기록하고, 이유 없는 개별 스타일은 남기지 않는다.
8. 대상 테스트·`pnpm test`·`pnpm typecheck` 통과와 해당 배송의 실물 기록이 있어야 구현 완료다.
   문서에 체크박스만 채운 상태는 완료가 아니다.

## 비목표

- 모든 페이지의 본문을 단일 템플릿으로 만들기, 범용 페이지 빌더·필터 엔진·폼 엔진 도입.
- 테마·폰트·색·radius·간격 토큰 재설계, UI 라이브러리 추가, 모바일·다크모드·가상화 도입.
- 카드 제거·섹션 순서·폭 등급·스크롤 구조 변경, 새 통계·필터·행동 추가, 인가나 데이터 모델 변경.
- Alert↔토스트 전환, 오류 위치·표시 시간·상태 전이 변경. 기존 피드백의 외형만 맞춘다.
- 8-P의 서버 diff 능력, Publish 이동, 사이드바의 추가 카운트.
- 승인된 모든 예외를 일괄 소거하거나 기존 문서 전체를 감사하기.

## 검증 기록과 한계

브라우저 업데이트 후 두 해상도에서 일곱 대상과 기준 화면을 다시 캡처·비교했다.
실제 OWNER·EDITOR 세션, 긴 내용·빈 데이터·오류·Dialog 조작을 확인했고, 표 머리가 Dialog를
덮는 결함을 추가 수정했다. 상세 근거·로컬 캡처 위치·자동 검사 결과는 [tasks](./tasks.md)에 있다.
최초 인증 부재·캡처 실패 기록은 완료 근거로 세지 않는다.

DB 전면 장애와 외부 쓰기 왕복의 모든 조합을 재현한 E2E는 아니다. 기존 구조·동작은 유지했고
변경한 표시 영역과 관련 상태를 검증했다. Figma 원본 재확인이나 새 시안 생성은 하지 않았다.
