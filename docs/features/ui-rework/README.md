# ui-rework — SaaS 8단계 UI 재작성

**태스크와 완료 게이트의 정본은 [docs/SAAS.md](../../SAAS.md) §8이다.** 이 디렉터리는 그 단계를
**배송 단위로 쪼갠 산출물**이고, 배송 하나가 디렉터리 하나다(`spec.md`·`design.md`·`tasks.md`).

6단계 `translation-ui/`가 화면 열 개를 한 디자인 시스템 위에 세웠고, 8단계는 그 위에 **Figma 시안을
입힌다.** 폴리싱이 아니라 재작성인 이유는 SAAS §8 첫 항목이다 — 번역 표의 축이 바뀐다.

## 작업 규약 — 8단계 전체에 적용 (2026-09-10 사용자 결정)

**아홉 개다.** 대화에만 두면 낡으므로 여기 고정한다. 시안을 읽을 때마다 이 목록을 지난다.

### 1. 시안의 토큰은 무시하고 리포 토큰에서 가장 유사한 값을 찾는다

시안은 자체 토큰 체계(`color-semantic/*`·`radius-semantic/*`·`size-scale/*`)를 쓴다. **그것을 이식하지
않는다** — 리포의 단일 출처는 `app/globals.css`이고(DESIGN §2) 두 체계가 공존하면 값의 진실이 둘이 된다.

### 2. 에셋은 사용자에게 요청한다

로고·심볼·키비주얼처럼 **에셋으로 관리할 것**은 사용자가 export 해서 준다. 에이전트가 Figma에서 임의로
뽑지 않는다 — 어느 노드가 "에셋"인지는 디자이너가 정한다.

⚠️ **`public/`에 생성물 아닌 바이너리를 두지 않는다는 규칙이 여기서 깨진다** — `public/fonts/`는
`scripts/copy-fonts.mjs`가 만드는 생성물이고 gitignore돼 있는데, 브랜드 에셋은 **커밋된 원본**이다.
`public/brand/`를 새로 열고 그 구별을 DESIGN에 등재한다.

### 3. 모바일 대응을 생략한다 — 최소 대응 너비 **1280px**

그 이하 뷰포트에서는 **가로 스크롤이 발생하는 것이 정상**이다. `sm:`·`md:` 분기를 새로 만들지 않는다.

⚠️ **기존 화면에 남아 있는 `lg:` 분기는 그 화면의 배송에서 정리한다** — 지금 로그인 화면이
`lg:grid-cols-2`이고 `lg` 미만에서 장식이 사라지는데, 1280px 고정에서는 그 분기가 죽은 코드다.

### 3.5 공통 레이아웃 — **바깥 padding 8 · 패널 간 gap 8** (시안 전체의 규칙)

**화면은 배경 위에 패널이 떠 있는 구조이고, 그 여백이 패널의 경계를 만든다.** 시안 둘에서 좌표로
검산했다 — 로그인과 번역 화면이 **같은 규칙**을 쓴다.

```
/signin (222:2371)                     /project/:slug/translations (212:937)
frame 1920×1080                        frame 1920×1080
└ body   x=8 y=8   1904×1064           ├ header x=8 y=8   1904×48
  ├ tab  x=0       948                 └ body   x=8 y=64  1904×1008     ← 8+48+8
  └ tab  x=956     948                   ├ lnb              240×1008
    948 + 8 + 948 = 1904 ✓               └ wrapper x=248    1656        ← 240+8
                                            ├ tab body       x=0    1328
                                            └ project global x=1336 320 ← 1328+8
```

- **바깥 padding 8** · **모든 패널 경계 gap 8**. 예외를 만들지 않는다
- 각 패널은 **radius 12**(리포에서는 `rounded-xl` — `--radius`를 12px로 올린 뒤 **16px**다, 규약 6) · 옅은 border · 낮은 shadow
- **바깥 배경은 `#f5f6f7`**(시안 `paper/surface-medium`), 패널은 **true white** — 그 대비가 없으면
  흰 패널과 흰 배경이 붙어 **경계가 통째로 사라진다**
- ⚠️ **border(`--border-subtle`)가 배경과 같은 값이다** — 시안에서 `divider/low`와
  `paper/surface-medium`이 둘 다 `#f5f6f7`이라, 그 선은 **흰 패널 위에서만 보인다**. 경계를 만드는
  것은 흰색 대비와 `shadow-low`이고 border는 가장자리를 정리한다
- ⚠️ **장식 패널의 base도 페이지 배경색이다** — 그라데이션이 없으면 배경과 구분되지 않아
  **로그인 패널만 떠 있는 그림**이 된다. 그것이 의도이므로 그라데이션 위쪽이 그 색으로 수렴한다
- ⚠️ **컬럼을 화면에 꽉 채우지 않는다.** 8-1b 초안이 `grid-cols-2`로 꽉 채웠다가 padding·gap·
  radius·border·shadow가 **한꺼번에** 빠졌다 — 하나가 아니라 구조 전체가 사라지는 실수다

**셸 치수** (8-2가 쓸 값 — 번역 화면 시안에서 읽었다):

| | 값 |
|---|---|
| header | **전폭 × 48** — 로고 32 좌측(x=4 y=8) · 아바타 32 우측 |
| lnb | **240** (내부 padding 4 → 콘텐츠 232) · 항목 높이 ~29-31 · 아이콘 16 |
| project global panel | **320** — SAAS §8이 예고한 그것이 시안에 실재한다 |
| 콘텐츠 | 나머지 (1920에서 1328) |

⚠️ **SAAS §8은 "top bar가 사라진다"고 적었는데 시안에는 48px 헤더가 있다.** 사라지는 것은 **지금의
top bar**이고 그 자리에 **전폭 48 헤더**가 온다 — 8-2가 그 문장을 정정한다.

### 4. shadcn을 설치해 쓰되, 없으면 radix를 직접 커스터마이즈한다

⚠️ **이것은 2026-09-08(6a T5)의 결정을 뒤집는 것이다.** 그때 shadcn CLI를 버리고 `components/ui/`를
리포가 소유하기로 하면서 생성물 4개와 `components.json`을 삭제했다. 그 결정에 **테스트 방어선 넷이
매달려 있어서**, 생성물을 그대로 넣으면 즉시 red다:

| 방어선 | 왜 깨지나 |
|---|---|
| `components/__tests__/focus-ring.test.ts` | shadcn은 `focus-visible:*`을 cva 베이스에 넣는다. 스캐너는 **여는 태그의 소스**를 읽으므로 그 파일을 통째로 못 본다 |
| 같은 파일 (raw 태그 0개) | shadcn `Button`의 `asChild`(Slot) 한 겹이 `<button>` 태그를 지운다 — `ButtonLink`가 따로 있는 이유가 그것이다 |
| `lib/__tests__/globals-css.test.ts` + 라이트 고정 | shadcn 토큰 세트는 `.dark` 블록과 `dark:` 변형을 들고 온다 (DESIGN §3, 현재 `dark:` 0곳) |
| (테스트 아님 — 실측 사고 계보) | shadcn 생성물은 `@radix-ui/react-*` **개별** 패키지를 import한다. 리포는 `radix-ui` **통합** 하나라, 섞으면 Radix 인스턴스가 두 벌이 되고 Provider 컨텍스트가 갈린다 (POSTMORTEM 2026-09-08 툴팁 provider와 같은 계보) |

**그래서 정착 규칙이 붙는다 — CLI는 *소스 획득 수단*이고 생성물을 그대로 두지 않는다.** 넣은 직후:

1. **포커스 링 셋**(`focus-visible:ring-ring` · `focus-visible:ring-[3px]` · `focus-visible:outline-none`)을 **여는 태그에 리터럴로** 끌어내린다
2. `.dark` 블록과 `dark:` 변형을 **제거**한다
3. import를 **`radix-ui` 통합 패키지**로 바꾼다
4. `asChild`는 **실제로 필요한 자리만** 둔다. 두면 `{children}`을 `Slot.Slottable`로 감싼다
   (POSTMORTEM 2026-09-09 — 형제를 붙이면 Slot이 던져 셸이 죽는다)

그 뒤 **`components/ui/`가 계속 소유한다.** CLI를 다시 돌려 덮어쓰지 않는다.

### 5. CSS는 Tailwind로 간다

인라인 `style`·별도 CSS 파일을 새로 만들지 않는다. `@theme` 토큰 + 유틸 클래스가 경로다.

⚠️ 예외는 **Canvas로 그리는 것**이다(8-1의 도트 필드) — JS가 픽셀을 그리므로 Tailwind의 축이 아니다.

### 6. 치수는 **기존 스케일에 맞추고**, 자간·행간은 Tailwind 기본을 쓴다

**2026-09-10에 방향이 바뀌었다.** 초안은 "시안 크기에 맞추고 없는 값은 `@theme`에 토큰으로 등재"였는데,
signin 하나에서만 **새 토큰 하나 + twMerge 등록 + DESIGN 예외 둘**이 딸려 나왔다. 사용자 판정:
**시안과 2px씩 어긋나더라도 기존 스케일에서 가장 가까운 값을 쓴다.** 차이는 런타임 목측에서 본다.

| 시안이 요구하는 것 | 쓰는 값 | 안 만드는 이유 |
|---|---|---|
| radius 12px | `rounded-xl` = **16px** | 파생은 8·10·12·16이고, `rounded-lg`(12px)는 버튼·카드가 이미 쓴다 |
| 높이 38px | `h-10` = **40px** | 리포의 임의 치수가 `ring-[3px]` 하나뿐이다 |
| 아이콘 20px | **16px** | §6.8이 *"크기는 셋뿐(16·12·24), 그 밖을 만들지 않는다"* |
| 28px 문구 | `text-3xl` = **30px** | Tailwind는 24 → 30이고 그 사이가 없다 |

⚠️ **커스텀 `text-*` 토큰을 만들면 `lib/utils.ts`의 twMerge `classGroups` 등록이 딸려온다.**
안 하면 twMerge가 그것을 **text-color로 오분류**해 `cn("text-28", "text-foreground")`에서 조용히
사라진다 — DESIGN §4.2가 `text-mono`를 그 이유로 등록해 뒀고 bugshot-2가 실제로 밟았다.
**토큰 하나의 진짜 비용이 그것이다.**

⚠️ **정말 필요하면 만든다** — 금지가 아니라 기본값이다. 만들 때는 twMerge 등록 + DESIGN §4 등재를
같은 커밋에 넣는다.

### 7. 팔레트는 **neutral**이다 — 목측이 slate 유지를 뒤집었다

⚠️ **이 규약은 하루 안에 한 번 뒤집혔다.** 처음 판정은 *"slate 토큰으로 매핑하고 브라우저에서
보고 판단한다"*였는데(파급이 화면 열 개라 팔레트 교체를 미뤘다), **8-1b의 목측이 그 판단을
되돌렸다**: 시안의 회색이 전부 중립(`#090b0c`·`#6f6f6f`·`#f5f6f7`)인데 slate는 푸른 틴트라,
패널·배경·보조 텍스트가 나란히 놓이자 **화면 전체가 시안보다 파랗게** 보였다. 색을 하나씩
맞추는 것으로는 틴트가 안 없어진다.

**`app/globals.css`의 `:root`가 neutral 값을 든다**(DESIGN §0·§2). 파급은 예상대로 전 화면이고,
그래서 **8-2 이후의 화면은 이미 중립 위에서 시작한다.**

blue 계열은 리포 토큰에 **없다** — Tailwind `blue-600` 유틸을 쓴다. DESIGN §6.2·§6.3이 그것을
**외부 링크 색으로** 등재해 뒀다.

⚠️ **`blue-500`은 선례가 아니다** — 리포 전수 **0건**이고 §6.2의 마지막 문장이 *"등재된 것이
전부다 — amber · destructive, 그리고 §6.3의 외부 링크 blue-600"*이다. 쓰려면 §6.2 등재가 함께 간다.

⚠️ **Canvas·JS에 hex를 박지 않는다** — 리포에 tsx 내 hex 리터럴이 0건이다. CSS 커스텀 프로퍼티에서
읽어 값의 집을 하나로 둔다.

### 7.5 인라인 하이퍼링크에 **밑줄을 쓰지 않는다** (2026-09-10)

색(`text-blue-600`)과 외부 링크 아이콘으로 구별한다. `underline`·`hover:underline`·`underline-offset-*`
전부 대상이다 — 8-1b에서 소스 13곳을 걷어냈고 DESIGN §6.3이 반대로 적고 있던 것을 함께 고쳤다.

`grep -rn "underline" app components --include='*.tsx' | grep -v __tests__` → **0건**이어야 한다.

### 8. 피드백은 **토스트**다 — 인라인 에러를 피한다 (2026-09-10)

⚠️ **2026-09-08이 `sonner`를 사용 0으로 제거하며 반대로 판정한 자리다** — 그 근거는 *"피드백은 셀
인라인(저장)과 `Alert`(Publish)이고 토스트는 그것을 둘로 가른다"*였다. 8단계는 **토스트로 통일**한다.

- `sonner` 재도입 + `components/__tests__/client-graph.test.ts` 금지 목록에서 제거
- **`<Toaster theme="light" />`** — 테마 감지를 끄지 않으면 OS 다크에서 토스트만 어두워진다
- **조치가 필요한 정보는 `duration: Infinity` + 닫기** — 인증 거부 사유가 3초 뒤 사라지면 화면에
  설명이 0이 된다
- **`id`를 고정한다** — StrictMode에서 effect가 두 번 돌아 토스트가 둘이 된다
#### 경계 — 무엇이 토스트가 아닌가 (2026-09-10 확정)

⚠️ **초안에는 경계가 없었고, 그래서 8-3에서 지킬 수 없는 규칙이었다** (CDO Q1). 이 리포의 피드백은
네 부류이고 **셋은 토스트로 옮길 수 없다.**

| | 무엇 | 어디 |
|---|---|---|
| **토스트** | **전역 결과를 내는 이벤트** — 대상이 화면 전체이고, 읽고 나면 사라져도 되는 것 | 로그인 거부 · 세션 회수 완료 · ~~Publish 결과~~(아래 한시 예외) |
| 인라인 | **대상이 있는 판정** — 어느 행·어느 셀이 거부됐는지가 정보의 절반이다 | 셀 저장 상태 4종(903행×3로케일) · 멤버 행 옆 거부(§6.65: *"상단으로 올리면 어느 행이 거부됐는지 사라진다"*) |
| 인라인 | **지속되는 조건** — 할 일이 남은 동안 계속 참인 것 | 편집 손실 배너(닫기 키가 `lastPulledAt`이다) · base 대기 배너 |
| 인라인 | **페이지 콘텐츠 자체** — 그것을 빼면 화면이 빈다 | 초대의 `not-found`·`expired`·`already-accepted` · 보관된 프로젝트 |

**첫 시험 사례가 초대 화면이다**: Layer A(위 넷)는 인라인 유지, `?e=`(버튼을 눌러서 나는 거부)만 토스트.

- ⚠️ **한 화면 안에서 병행하지 않는다** — 경로가 둘이면 하나가 낡는다. 위 표는 *부류*가 갈리는 것이지
  같은 사건을 두 곳에 내는 것이 아니다
