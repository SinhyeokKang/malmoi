# 모든 기기에서 로그아웃 — sec-audit-2 #38

상태: 로컬 구현·자동 검증 완료, 검수 기록은 태스크 참조. 실제 공급자·운영 전환 대기. [설계](./design.md) · [태스크](./tasks.md). 2026-09-10 사용자 승인. #37 repo admin 추가 요구는 구현 범위에서 제외한다.

## 사용자와 문제

개발자와 번역 편집자가 유출이 의심되는 모든 말모이 세션을 회수할 수 있어야 한다. 기존 로그아웃은 현재 세션만 지웠으며, 24시간은 활동으로 연장되는 수명이므로 자연 만료가 사고 대응을 대신하지 못한다.

## 완료 조건

1. `/account`의 `Sign out everywhere`에서 현재 기기를 포함한다고 설명하고 본인 확인을 시작한다. 기존 로그인 공급자를 서버가 선택한다.
2. 새 OAuth 왕복의 state와 현재 브라우저·세션, 5분짜리 일회용 확인 요청을 묶는다. 공급자와 providerAccountId가 시작 시 계정 및 현재 DB 계정 소유권과 일치해야 한다. 이메일 일치는 대체 조건이 아니다.
3. 다른 계정·공급자, 만료/없는/재사용된 확인 요청, 다른 state·세션은 회수 0건이다. 재인증 경로에서 계정 연결·가입·이메일 갱신을 수행하지 않는다.
4. 확인 요청 소비와 해당 userId의 모든 Session 삭제가 한 트랜잭션이다. DB 실패는 성공 문구로 표시하지 않는다. 다른 사용자의 세션·멤버십·초대·GitHub 연결은 보존한다.
5. 성공 후 현재 세션 쿠키와 확인 쿠키를 지우고 로그인 화면에 완료 문구를 보여 준다. Auth.js가 callback 후 새 세션을 만들지 않는다. 기존 세션은 다음 인증부터 거부되며 삭제와 갱신 경합으로 부활하지 않는다.
6. 취소·만료·잘못된 계정·장애를 구별해 재시작 경로를 제공한다. 실제 공급자 왕복·키보드 검증과 로컬/격리 DB 테스트 완료는 별도로 기록한다.

## 경계

새 OAuth 인가와 같은 공급자 계정의 통제를 확인한다. 공급자 SSO를 허용하므로 비밀번호 재입력/MFA 강제를 보장하지 않는다. 제공자가 지원하는 `prompt=select_account`로 계정을 선택하게 한다. 회수 트랜잭션 이후 별도로 로그인해 만든 새 세션은 정상이다. 이미 인증을 끝내고 실행 중인 요청을 중단하는 기능은 아니다.

기기/IP 목록, 개별 세션 관리, 관리자에 의한 타인 회수, 공급자 자체 로그아웃·토큰 폐기, 계정 통합은 이번 범위가 아니다. credential 저장 보호 위에서 구현하며 현재 배포·운영 전환 완료를 뜻하지 않는다.
