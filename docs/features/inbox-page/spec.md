# inbox-page — spec

헤더 Inbox 드롭다운(attention-inbox, 2026-10-05)과 **같은 모델**을 전용 라우트 `/inbox`에서 본다. 사이드바 사용자 구역의
`Projects` 바로 아래에 `Inbox` 항목을 두고 안 읽음 수 배지를 단다. 요청: 2026-10-09 사용자. 결정 기록(같은 날 사용자 확인):
읽음은 서버 렌더 + 마운트 뒤 기록 · 사이드바 배지 있음(실제 수, 안 읽음 수) · 드롭다운 `View all` 없음 · 사용자 메뉴에도 항목 ·
묶음은 프로젝트 단위 · 헤더 트리거 이름을 `Inbox`로 · Home 카드 행도 공유 조각으로 이관 · 디자인 시안 없음(기존 프리미티브 조립).

## 사용자

**둘 다** — 개발자(OWNER: 설정 미완·적재 실패 재시도)와 번역 편집자(EDITOR: 검토 대기·빈 로케일·미전달 편집). 판정은
이미 역할별로 갈려 있고(`planInbox`) 이 기능은 그 판정을 바꾸지 않는다.

## 문제 (관측된 사실)

- Inbox는 헤더 드롭다운 하나뿐이다. 그릇이 폭 360 · 높이 `min(560px, 가용)`이라 항목이 많으면 메뉴 안 스크롤로만 본다.
  문장 칸이 226이고 시각이 짧은 형(`12m ago`)으로 접힌다(`components/shell/attention-inbox.tsx` Row 주석, #190).
- 목록에 URL이 없다 — 뒤로 가기로 돌아오거나 새 탭에서 열 자리가 없다. 메뉴는 행을 누르면 닫히므로 항목을 하나씩 처리하려면 매번 트리거를 다시 연다.
- 사이드바 사용자 구역(`navWorkItems`: Projects · MCP connector · Preferences · Account)에 Inbox로 가는 길이 없다.
- 같은 목적지의 이름이 갈린다 — 헤더 트리거의 접근 이름은 `Needs your attention`(`messages/en.tsx` `inbox.label`)이고, 새 사이드바·페이지는 `Inbox`다(DESIGN §6.5 "한 곳을 가리키는 이름이 둘이면 하나가 낡는다").

## 완료 조건 (검증 가능한 문장)

1. 로그인 사용자가 `/inbox`를 열면 헤더 드롭다운과 **같은 `InboxPlan`**(같은 `loadAttentionInbox` · 같은 프로젝트 묶음·정렬·역할 판정)이
   **프로젝트마다 카드 하나**로 보인다. 행 문장·타일·링크는 드롭다운·Home 카드와 같은 공유 행 조각이 만든다.
2. 비로그인 `GET /inbox`는 1차 차단(`isProtectedPath`)에서 `/signin`으로 307되고, 페이지는 최상단 `requireUser`를 지난다.
3. 사이드바 사용자 구역 순서가 `Projects · Inbox · MCP connector · Preferences · Account`이고, `/inbox`에서 Inbox 항목이
   `aria-current="page"`다. 같은 `navWorkItems`를 읽는 세 자리에도 Inbox가 생긴다 — **의도다**: 헤더 사용자 메뉴(앱 셸·공개 셸 둘 다, 배지 없음) ·
   전역 검색 Pages 색인(`lib/search/nav-index.ts`) · 랜딩 목업 LNB(`components/landing/mockup/app-frame.tsx`).
4. 페이지를 보면 읽음 워터마크가 드롭다운을 연 것과 **같은 계약**으로 움직인다 — 조회 전 서버 시각 · 단조(`lt`) 조건부 쓰기 ·
   쓰기 실패는 목록은 보이고 워터마크·배지는 그대로.
5. 이번 방문의 안 읽음 점은 이번 화면에 남고, **다음 방문(또는 드롭다운 열기)부터** 사라진다. 브라우저 뒤로 가기로 돌아온 화면은 라우터 캐시라
   옛 점이 다시 보일 수 있고, 이것은 "같은 방문"으로 간주한다(쓰기는 단조라 무해).
6. 페이지가 읽음을 기록하면 **같은 탭의 헤더 Inbox 배지와 사이드바 Inbox 배지가 페이지 이동 없이 0이 된다**. 그 뒤에 도착한 배지 조회 응답이 0을 되살리지 않고,
   이미 받아 둔 드롭다운 목록을 다시 열어도 응답 전에 옛 점이 서지 않는다(#191과 같은 부류).
   공개·앱 셸 전환으로 해제된 헤더의 응답과, 페이지 읽음 신호 전에 시작한 드롭다운 목록 응답도 배지·점을 되살리지 않는다.
   읽음 신호 이후 새로 시작한 목록 조회의 실제 안 읽음은 정상 표시한다.
6a. 사이드바 Inbox 항목은 **안 읽음 수 n**을 `CountBadge`로 보인다 — 헤더 배지와 **같은 n**이고 표시만 다르다(헤더는 `9+`로 접고, 사이드바는 다른 사이드바 배지처럼 실제 수).
   0이면 서지 않는다. sr 문장은 `{n} unread`. 배지 수를 위한 Action 호출이 늘지 않는다(헤더가 이미 부르는 `loadAttentionBadgeAction` 한 번).
   서버 렌더에서는 배지가 없고 하이드레이션 뒤 헤더의 응답이 오면 선다. 접힌 레일(40)에서는 다른 배지처럼 투명해진다(헤더 배지가 남는다).
7. 헤더 트리거의 접근 이름이 `Inbox` / `Inbox, {n} unread`다. Home 카드 제목 `Needs your attention`은 그대로다.
8. 빈 목록이면 드롭다운과 같은 빈 상태 문구(`home.attention.empty.title` + `inbox.emptyDescription`)가 카드 형(`EmptyState placement="card"`)으로 선다.
   조회 실패는 `(edit)/error.tsx` 경계로 간다. `loading.tsx` 골격은 실물과 같은 카드·행 배치다.
9. 페이지 렌더(GET)는 아무것도 쓰지 않는다 — 쓰기는 클라이언트 마운트 뒤 Action이 한다.
10. 개인정보 방침(en 본문 · ko 본 `messages/ko-privacy.tsx`)의 Inbox 열람 기록 서술이 "헤더 목록을 열 때"에서 "Inbox를 열거나 볼 때"로 바뀌고 개정 이력·시행일이 붙는다(`policy-gate.test.tsx` green).
11. 화면 문구는 세 사전(en·ko·es)을 지나고 새 키는 같은 커밋에 세 사전에 들어간다.
12. `pnpm gate` green — 커밋 경계마다.

## 비목표

- **실시간 갱신·폴링** — 드롭다운과 같다(PRODUCT §4.1 · DESIGN §6.545). 다시 방문해야 새 항목이 보인다. 다른 탭의 배지도 다음 마운트까지 옛 값이다.
- **항목별 읽음·숨기기·처리 완료 버튼** — PRODUCT §4.2 "범용 알림 시스템" 비범위에 든다(읽음은 사용자당 시각 하나).
- **필터·정렬 옵션·페이지네이션·날짜 묶음** — 드롭다운과 같은 순서다. 날짜 묶음은 Inbox가 사건이 아니라 현재 상태라 맞지 않는다(2026-10-09 결정).
- **드롭다운 안 `View all` 링크** — 요청 밖이다(2026-10-09 사용자 확인). 드롭다운 시안 H1–H3은 이름 변경 외 그대로다.
- **접힌 레일의 안 읽음 표시** — 헤더 배지가 든다(2026-10-09 수용).
- **공개 셸 안의 `/inbox`** — 앱 셸 페이지다. 공개 셸 헤더의 Inbox 드롭다운·사용자 메뉴 항목은 그대로 쓴다.
- **좁은 폭 대응** — 이 기능은 현재 셸 하한(1280)을 따르고, `responsive-app` spec A-07에 `/inbox`·LNB Inbox 배지를 등재했다(같은 커밋).
- **디자인 시안** — 새 표면이지만 Home 카드(`Card` + `ListRow`)·사이드바 `CountBadge`·`/preferences` 골격의 조립이라 시안 없이 DESIGN.md와 Home 카드 실측으로 대조한다(2026-10-09 사용자).
