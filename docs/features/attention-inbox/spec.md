# attention-inbox — spec

헤더의 Inbox 트리거에서 **멤버로 속한 모든 프로젝트의 "지금 손볼 것"**을 드롭다운 하나로 본다. 발송(이메일·브라우저 푸시)은 없다.

**시안 (첫 구현 SoT — `/design-sync` 대상)**: https://claude.ai/design/p/b99d54cd-3034-44f1-8446-0a864da9d767?file=Attention+Inbox.dc.html

  - DESIGN :871·:2230의 "헤더 카운터" 금지를 "Inbox 안 읽음 배지 하나만 예외(사용자 결정 2026-10-05)"로 고친다.

## 사용자

**둘 다**다. 항목 종류에 따라 갈린다.

- **번역 편집자(비개발자 동료)** — 검토 대기·빈 로케일이 주 대상이다.
- **개발자(OWNER)** — 적재 실패·설정 미완·미전달 편집이 주 대상이다.

## 문제 (관측된 사실)

- `Needs your attention`은 **프로젝트 Home 안에만** 있다(`lib/home/attention.ts`). 프로젝트가 둘 이상이면 각 Home을 열어 봐야 하고,
  번역 화면에서 작업하는 동안에는 다른 프로젝트에 새 일이 생겨도 보이지 않는다.
- `/projects` 목록 띠는 검토 대기·미전달·설정 미완을 프로젝트 단위로 보이지만(`rowBanner` — `lib/projects/list.ts`, 원격 신호 `repoAheadFiles` 포함 — GitHub 호출),
  **목록 화면을 열어야** 보이고 **빈 로케일은 목록 띠에 없다**(Home에만 있다). 셸 어디에서도 상시로 보이지 않는다.
- "지난번 이후로 새로 생긴 것"을 알 길이 없다 — Home 카드는 언제나 현재 상태 전부를 보인다.

## 완료 조건 (검증 가능한 문장)

1. 편집 셸(`(edit)` 레이아웃) 헤더 우측, **세로선 오른쪽·사용자 메뉴(아바타) 왼쪽**에 Inbox 아이콘 버튼이 선다 → `[+ New project] | [Inbox] [avatar]`.
   접근 이름은 하나로 합쳐진다 — 안 읽음 0이면 `Needs your attention`, n이면 `Needs your attention, {n} unread`(숫자 배지는 `aria-hidden`).
2. 버튼을 누르면 드롭다운이 열리고, **비보관 멤버 프로젝트 전체**의 항목이 프로젝트별로 묶여 **상한 없이** 보인다(메뉴는 최대 높이까지 커지고 그 안에서 스크롤). 항목 종류는 다섯이다:
   적재 실패 · 검토 대기 · 빈 로케일(Home 세 종과 같은 판정) + 미전달 편집 · 설정 미완(목록 띠와 같은 판정, DB만).
3. 설정 미완은 **OWNER에게만** 보인다. 적재 실패는 Home처럼 두 역할 모두에게 보이고 EDITOR에게는 "Owner가 재시도한다" 꼬리를 단다.
   ⚠️ 목록 띠는 설정 미완을 EDITOR에게도 `ownerOnly` 문장과 함께 보인다 — **목록은 프로젝트 상태를 보이는 표면이고 Inbox는 "내가 손볼 것"이라** 할 수 있는 일이 없는 항목은 배지 소음이 된다. 이 차이는 의도다.
4. 항목을 누르면 Home 카드·목록 띠와 **같은 목적지**로 간다(같은 href 함수를 공유 — 테스트가 같은 값을 단언한다).
5. 헤더 버튼의 배지는 **안 읽은 항목 수**다(0이면 배지 없음, 10 이상은 `9+`). **검토 대기는 안 읽음·배지 계산에서 빠진다** — 목록에는 보인다.
   ⚠️ 이유: 검토 대기의 시각 출처는 셀 `updatedAt`뿐인데 push가 리포에 있는 모든 셀의 `updatedAt`을 덮어(`lib/push/apply.ts:485`) CI·야간 동기화마다 다시 안 읽음이 된다.
6. 드롭다운을 열면 **서버가 조회 시작 전에 잡은 시각**까지 읽음으로 기록되고 배지가 0이 된다. 열자마자 닫아도(목록 도착 전 포함) 읽음이다 — 여는 것이 곧 읽음이다.
   읽음 기록이 실패하면 배지는 그대로 남는다(서버 워터마크가 안 움직였으므로).
7. 읽음 이후 새로 생기거나 시각이 앞으로 움직인 항목만 다시 안 읽음이 된다. 해결된 항목은 목록에서 사라진다(읽음 여부와 무관).
   이번 열람 동안 행의 안 읽음 표시는 유지되고 다음 열람부터 사라진다.
8. 같은 DB 상태 + 같은 읽음 시각 → 같은 목록·같은 배지(순수 함수 `planInbox` 단위 테스트로 고정).
9. 항목이 0이면 빈 상태 문장(Home과 같은 낱말 `Nothing needs you`), 조회 실패면 오류 문장 + 메뉴 항목 `Try again`이 보인다. 하위 조회 하나의 실패는 목록 전체의 오류다. 실패는 셸을 죽이지 않는다.
10. 응답에 `projectId`와 원문 이메일이 실리지 않는다(행위자는 마스킹 라벨만 — POSTMORTEM 2026-09-29).
11. `User.attentionSeenAt`이 `lib/privacy/collected.ts`에 등재되고 `/privacy` 본문이 새 목적(안 읽음 표시)에 대해 참이다(고치면 개정 이력·시행일 — `policy-gate`).
12. 라이트·다크 두 테마, en·ko·es 세 사전에 같은 커밋으로 들어간다. 가이드의 헤더 설명이 갱신된다(`/guide`).
13. `pnpm gate` green(`pnpm test:projects:postgres` 포함 — T4가 `lib/keys/`를 건드리므로 gate가 스스로 붙인다).

## 수용하는 대가

- 설정 미완의 시각은 `Project.createdAt`이라, 방금 프로젝트를 만든 OWNER에게도 안 읽음 하나가 뜬다.
- 자기 편집으로 생긴 `unsent`도 안 읽음이 된다(행위자로 거르지 않는다 — 그 판정은 공유 술어 밖의 새 규칙이다).
- 클릭 사이에 멤버에서 제거되면 목적지 페이지의 `requireProjectAccess`가 받는다(Inbox가 따로 막지 않는다).

## 비목표 (이번에 안 함)

- 이메일·브라우저 푸시·웹 푸시·소리, 구독·알림 설정(뮤트), 실시간 갱신(SSE·폴링 타이머·창 focus 재조회).
- **항목별 읽음·닫기(dismiss)** — 읽음은 사용자당 시각 하나다.
- **사건 기반 알림**(누가 초대했다·PR이 머지됐다·누가 번역을 고쳤다·새 버전) — `ProjectEvent`를 알림으로 돌리는 것은 범위 밖이다.
- **원격 신호**(`repo_ahead`·`pr_open`·`pr_check_failed`·App 설치 해제 같은 원격 연결 끊김) — 헤더에서 GitHub을 부르지 않는다. 연결 끊김은 Home·설정에서만 보인다.
- **`needs_reconnect`**(`repositoryId === null`) — sec-audit-2 이전 행의 유산이라 새로 생기지 않는다(생산자 없는 갈래를 두지 않는다 — `lib/projects/list.ts:97`).
- 공개 셸·MCP 도구·`/projects` 목록·Home 카드의 동작 변경.
- 보관된 프로젝트의 항목.
