# ui-locales — 화면 언어 ko·es 추가 + Preferences 페이지 + 언어별 가이드

## 사용자

**번역 편집자(비개발자 동료)가 주 대상이다.** 개발자는 영어 화면으로 충분하지만, 편집자는 초대 링크로 처음 들어와
영어 화면에서 Sync·Publish·Sources를 읽어야 한다. 편집자의 모국어가 ko·es이면 첫 진입부터 그 언어를 고를 수 있어야 한다.
두 사용자의 요구는 여기서 충돌하지 않는다 — 기본값은 여전히 영어다.

**지금 여는 근거는 사용자 판단이다**(2026-10-04) — 막힌 편집자·요청 이슈 같은 관측된 수요는 아직 없다. PRODUCT §10은 여는 계기를
"8단계(dogfooding)가 답을 요구할 때"로 적었지만 이 기능은 dogfooding을 비목표로 두고 먼저 연다. es를 원어민 검수 없이 내는 것,
설정 화면을 `/account`와 나눠 `/preferences`로 두는 것도 같은 날 사용자가 확정했다.

## 문제 (관측된 사실)

- 화면 문구가 영어 하나다. 출처는 `messages/en.tsx` 하나(3,840줄)이고, 소비 파일 166곳이 상수 `m`을 직접 import한다
  (클라이언트 컴포넌트 67곳 · `lib/` 40곳 · 나머지는 서버 컴포넌트·Action).
- PRODUCT §10 "UI를 ko로 여는 시점"이 미결이다 — **언제 여는가**와 **locale을 무엇이 정하는가**가 비어 있다. 이 기능이 둘 다 정한다:
  지금 연다 · 계정 설정 > 기기 쿠키 > 영어.
- `<html lang="en">`이 고정이고, 날짜(`lib/utc-time.ts`의 월 약어)·상대 시각(`Intl.RelativeTimeFormat("en")`)도 영어 고정이다.
- 개인 설정을 담을 화면이 없다. `/account`는 신원·로그인 수단·세션이고 설정이 아니다.

## 결정 (2026-10-04 사용자 확정)

| 항목 | 결정 |
|---|---|
| 추가 언어 | **ko · es** — 지원 집합은 `en · ko · es` |
| 폴백 순서 | **계정(`User.uiLocale`) > 기기 쿠키(`malmoi-ui-locale`) > `en`**. `Accept-Language`는 보지 않는다 — **처음 온 사용자는 항상 영어다** |
| "로컬" 층 | **http-only 쿠키**다. localStorage는 서버가 읽을 수 없어 서버 컴포넌트 문구(페이지·레이아웃 약 60곳)를 번역할 수 없다(사용자 확인) |
| 공개 페이지 | 푸터의 텍스트 버튼 → 언어 목록 |
| 앱 안 | 새 페이지 **`/preferences`**의 Language 섹션 |
| 로그인한 사용자가 푸터에서 바꾸면 | **쿠키와 계정에 함께 저장한다** — 쿠키에만 쓰면 계정 값이 우선이라 고른 언어가 무시되어 푸터가 고장 난 것처럼 보인다 |
| 개인정보 처리방침(`/privacy`) | **en + ko 두 벌**(2026-10-04 사용자). ko 화면이면 ko 본문, **그 밖의 언어(en·es)는 en 본문**이다. ko 본문은 에이전트 초안 → 사용자 검수 |
| 가이드(`/docs`) | **언어별 원고를 준비한다**(2026-10-04 사용자, feature-review에서 범위 수정) — `guide/en·ko·es/` 대칭 트리. **스크린샷 이미지만 en을 공유**하고 문구는 언어별이다. 검수는 사전과 같다(ko 사용자 검수 · es 에이전트 초안 그대로) |

## 완료 조건 (검증 가능한 문장)

각 조건 끝의 `[자동]`은 `pnpm test`·`pnpm typecheck`가 판정하고, `[수동]`은 이 리포에 e2e가 없어 `/runtime-test`(tasks H4)가 눈으로 판정한다.

1. 쿠키도 계정 설정도 없는 첫 방문자는 모든 화면을 영어로 보고, `<html lang="en">`이다. `Accept-Language: ko`를 보내도 같다. `[자동]` 판정 함수 · `[수동]` 화면
2. 비로그인 사용자가 공개 페이지 — `PublicFooter`를 렌더하는 전부: 공개 셸(`/` · `/docs` · `/changelog` · `/privacy`)과 `AuthLayout`(`/signin` · `/invite/:token` · `/oauth/authorize` · `/signin/link/:challenge`) —
   푸터에서 ko를 고르면 **같은 페이지가 새로고침 없이 ko로 다시 그려지고**, 이후 첫 요청부터 서버가 ko로 렌더한다(영어가 잠깐 보였다가 바뀌지 않는다).
   `<html lang="ko">`. `[수동]`
3. 로그인한 사용자가 `/preferences`에서 es를 고르면 앱 전체가 es가 되고, **다른 기기에서 로그인해도** es다(쿠키가 en이어도 계정이 이긴다). `[자동]` 판정·쓰기 계획 · `[수동]` 두 기기
4. 로그인한 사용자가 푸터에서 언어를 바꾸면 `/preferences`에도 같은 값이 보인다 — 로그인한 사용자에게 푸터가 서는 `/` · `/docs` · `/changelog` · `/privacy` · `/invite/:token`에서 성립한다(`/signin`은 로그인 사용자를 `/projects`로 보낸다). `[수동]`
5. 로그아웃한 뒤에는 그 기기의 쿠키 값(마지막으로 고른 언어)이 적용된다. `[자동]` 판정 · `[수동]` 화면
6. 쿠키·DB에 지원하지 않는 값(`fr`, `__proto__`, 빈 문자열)이 있으면 다음 층으로 넘어가고, 어느 경우에도 화면이 깨지지 않는다. `[자동]`
7. `messages/ko.tsx`·`messages/es.tsx`가 en과 **키 집합·함수 시그니처가 같다**(영어 고정 네임스페이스는 `Messages`에서 빠진다 — design §2) — 하나라도 빠지거나 남으면 `pnpm typecheck`가 red다. `[자동]`
8. ko·es 사전에서 en과 **같은 문자열**인 값은 허용 목록(**키 경로** 기준 — 고유명사·코드)에 있는 것뿐이다 — 번역 누락을 `pnpm test`가 잡는다. `[자동]`
9. 절대 날짜는 언어별 형식으로 나오고 **여전히 UTC라고 말한다**(`2026년 9월 27일` · `27 sept 2026` · `Sep 27, 2026`). 상대 시각과 언어명(`Intl.DisplayNames`)도 그 언어다. `[자동]` 헬퍼 · `[수동]` 화면
10. en 사용자의 클라이언트 JS가 이 기능 전 대비 gzip 기준 +2KB 이내다. ko·es 사전은 그 언어를 고른 사용자만 받는 별도 청크다. 기준선은 착수 전에 잰다(tasks A0). `[수동]` 실측
11. 영어로 고정되는 표면은 바뀌지 않는다 — MCP 도구 응답, 초대 메일, SEO 메타·탭 제목(`metadata`)·`llms.txt`·`llms-full.txt`(en 가이드)·sitemap, `/api/*` JSON(검색 색인은 언어별 정적 파일 — 14), cron·서버 로그, CLI 출력, 가이드 스크린샷,
    방침 본문(ko 화면 제외 — 조건 12), changelog 본문(GitHub Release), 숫자 형식(`en-US`), `/signin` 키비주얼 PNG, zod 검증 메시지, `global-error`(`lang="en"`). `[자동]` 소스 검사(tasks B1⑦·⑧)
12. `/privacy`가 새 쿠키와 `User.uiLocale`을 말하고 개정 이력이 붙는다(`policy-gate.test.tsx` green). ko 화면은 ko 본문, en·es 화면은 en 본문이다.
    두 본문은 **절 id·수집 항목 표(`collected.ts`)·쿠키 표·개정 이력 항목과 시행일**이 같지 않으면 `pnpm test`가 red다 — 한쪽만 고치면 게이트가 막는다. `[자동]`
13. `/preferences`는 보호 경로다 — 비로그인 요청은 `/signin`으로 간다. robots.txt가 그 경로를 거부한다. `[자동]`
14. `/docs`는 화면 언어의 원고를 보여 준다 — ko 사용자는 `guide/ko/`의 본문·목차·문서 내비·검색 결과(공개 검색 색인)를 그 언어로 본다. 이미지는 세 언어가 같은 `public/guide/*.webp`(en 화면)를 쓴다. `[자동]` 로더·색인 · `[수동]` 화면
15. 세 언어 원고가 **구조 동형**이다 — 파일 집합·SUMMARY 순서·절 id(`{#anchor}`)·이미지 참조·번호 단계 수가 같지 않으면 `pnpm test`가 red다. 가이드 본문이 부르는 화면 라벨은 그 언어 사전의 값과 같다(`terminology.test.ts`를 언어별로). `[자동]`

## 비목표

- **타임존·테마** — Preferences에 이어 붙일 예정이지만 이번에는 섹션도, 빈 자리도, 설정 저장소 추상화도 만들지 않는다(확장성 선반영 금지).
  각각 따로 `/feature`가 필요하다. ⚠️ 테마는 DESIGN §3.1의 "라이트 단일, `dark:` 금지"와 `@custom-variant dark` 고정을 뒤집는 결정이고,
  타임존은 "절대 시각은 UTC로 말한다"(CLAUDE.md 코드 컨벤션)를 뒤집는 결정이다.
- **로케일 URL**(`/ko/...`)·`hreflang`·언어별 색인 — 크롤러는 쿠키가 없으므로 영어만 본다. 공개 페이지의 SEO 메타는 영어 그대로다.
- **`Accept-Language`·지역 기반 자동 감지** — 사용자 결정으로 뺀다(처음 온 사용자는 항상 영어).
- **changelog 본문 번역** — 화면 틀만 번역하고 본문(GitHub Release)은 영어다. (가이드는 세 언어, 방침은 en·ko — 결정 표.)
- **방침 es 본** — 법적 문서를 원어민 검수 없이 낼 수 없어 es 화면은 en 본문을 보여 준다. 두 본 중 어느 쪽이 우선한다는 조항은 이번에 두지 않는다(두 본이 게이트로 같은 사실을 말한다).
- **언어별 스크린샷** — 가이드 이미지는 en 화면 한 벌을 세 언어가 공유한다. ko 가이드 본문은 `게시`라고 부르는데 그림 속 버튼은 `Publish`다 — **수용한 대가다**(2026-10-04 사용자).
- **가이드 원고 내용 드리프트 탐지** — 세 언어의 구조 동형(9b)만 게이트하고, en 문장을 고친 뒤 ko·es 문장이 뒤처지는 것은 `/guide`가 세 언어를 같은 커밋에서 고치는 규칙으로 막는다(원본 해시 같은 장치는 두지 않는다).
- **이 리포의 사전을 Malmoi로 관리(dogfooding)** — 사전 값에 함수·ReactNode가 섞여 있어 `ts-dict` 어댑터의 문자열 사전과 맞지 않는다. 별도 판단이 필요하다.
- **로그인할 때 쿠키 값을 계정으로 옮기기** — 계정 값이 비어 있으면 폴백으로 쿠키가 적용되므로 결과는 같다. 옮기지 않는다.
- **"기기 설정 따르기" 옵션**(계정 값을 비우는 선택지) — 세 언어 중 하나만 고른다.
- **화면 밖 영어 표면의 번역** — 탭 제목·숫자 형식·키비주얼 PNG·zod 메시지는 영어로 둔다(완료 조건 11). 탭 제목은 크롤러가 보는 `metadata`와 같은 축이라 `generateMetadata`로 바꾸지 않는다.
- **다른 탭의 언어 동기화** — 탭 A에서 언어를 바꾼 뒤 탭 B가 클라이언트 내비게이션을 하면, 루트 레이아웃(`<html lang>`·provider)은 옛 언어로 남고 새 페이지의 서버 문구만 새 언어로 섞일 수 있다. 다음 새로고침에서 풀린다. **수용한다**(탭 간 알림 장치는 선반영이다). H4에서 확인만 한다.
- **기존 가이드 스크린샷 재촬영** — 사이드바의 `Preferences`·푸터 스위처로 셸·공개 페이지 샷이 stale 후보가 되지만 이번 범위가 아니다(다음 `/guide-shots`). 가이드 원고를 `guide/en/`으로 옮겨도 이미지 경로(`public/guide/`)는 그대로다.
- ko·es 외 다른 언어. 오른쪽에서 왼쪽으로 쓰는 언어(RTL).
