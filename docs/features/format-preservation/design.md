# 원본 포맷 보존 — design

## 영향 받는 흐름

| 흐름 | 바뀌나 | 무엇이 |
|---|---|---|
| **push** (코드 → DB) | **아니다** | 표현을 DB에 저장하지 않으므로 페이로드·`Project` 컬럼·`read`가 그대로다 |
| **편집 UI** | **아니다** | UI 동결 (MVP §8.3). 화면에 노출할 것이 없다 |
| **pull** (DB → PR) | **그렇다** | 재생성 어댑터도 원본 blob을 받고, writer가 거기서 **표현만** 읽는다 |
| (실측) `lib/survey/` | 그렇다 | 같은 배선을 안 하면 지표가 개선을 못 본다 |

## 설계의 중심 질문 — 표현을 어디서 관측하고 어떻게 나르나

세 안이 있고 **A안(pull 시점에 원본에서 관측)** 으로 닫는다.

### A안 (채택) — write 시점에 원본 텍스트에서 관측한다

`DetectedFormat.currentFiles`를 **재생성 어댑터에도 넘긴다.** writer는 그 텍스트에서 스타일을
관측해 직렬화에 쓰고, 없으면 지금의 기본값으로 떨어진다.

- **새 필드가 없다.** `currentFiles`가 이미 있고 타입이 그대로다 — 주석의 "수술적 치환 어댑터가
  필요로 하는"만 넓힌다.
- **스키마 변경이 0이다.** ②번 세션의 `prisma/`와 충돌하지 않는다.
- **드리프트가 없다.** 리포를 4칸으로 재포맷하면 다음 pull이 저절로 따라간다. 저장된 값은 그
  순간부터 거짓이 될 수 있지만 관측은 그럴 수 없다.
- **표현 충실도가 완전하다.** "어느 컨테이너가 한 줄이었나"는 파일 안 위치마다 다른 값이라
  **어떤 요약 레코드로도 손실 없이 인코딩할 수 없다.** 텍스트를 들고 있어야만 정확하다.

**대가는 blob 읽기다.** 1층(DB 측 스킵)을 통과한 pull이 재생성 프로젝트에서 로케일 파일 수만큼
blob을 더 읽는다. 지금 그 최적화를 두고 있는 자리가 `lib/pull/run.ts`의
`if (writeStrategy === "surgical")`이고, 이 기능이 그 조건을 넓힌다.

받아들이는 근거:

- **1층이 이미 대부분을 거른다.** 야간 cron이 매일 도는데 편집이 없는 날은 GitHub을 **한 번도**
  부르지 않는다 (ARCHITECTURE §2). 늘어나는 것은 "편집이 있었던 날"의 비용뿐이다.
- **어댑터 5개 중 3개가 이미 그 비용을 낸다.** 새로 만드는 비용 구조가 아니라 나머지 둘을 같은
  구조로 맞추는 것이다.
- **로케일 수만큼이고 키 수와 무관하다.** 실측 최대가 jellyfin-web 107이고 App installation
  레이트 리밋은 시간당 5,000이다. (mastodon 106은 `yaml-catalog`라 **이미** 그 비용을 낸다 —
  새 비용의 사례가 아니다.)
- ⚠️ **레이트 리밋이 아니라 벽시계가 제약이다.** `/api/pull`은 `maxDuration = 60`이고
  `lib/pull/run.ts`의 blob 읽기는 **순차 `await`** 다. 로케일 100개 재생성 프로젝트에서 편집이
  있는 날 blob GET 100여 회가 60초 예산 안에 들어가야 한다. **지금 그런 프로젝트가 우리 도입
  대상에 없고**(bugshot-2 3로케일) 실측 상한이 107이라 이 회차에서는 병렬화하지 않는다 —
  ARCHITECTURE §8이 이미 "로케일이 늘어나면 blob 생성을 병렬화한다"로 예고한 자리다.

### B안 (기각) — read가 관측해 DB에 저장하고 pull이 되살린다

`Project.nestedByPath`의 배선을 그대로 복제한다 (ARCHITECTURE §1.35의 5홉 표).

기각 이유 셋:

1. **스키마 변경이 필요하고 그건 이 세션의 범위 밖이다.** 마이그레이션이 dev = prod DB를 직접
   친다 (CLAUDE.md).
2. **요약 레코드가 원리적으로 손실이다.** 들여쓰기·이스케이프는 파일당 값 하나로 접히지만, 한 줄
   컨테이너는 **컨테이너마다** 다르다. 경로 집합을 통째로 DB에 넣으면 그건 원본을 저장하는
   것이지 요약이 아니다.
3. **홉이 다섯이고 이 리포의 반복 실패 유형이 정확히 그것이다.** `nestedByPath`는 고친 뒤에도
   **프로덕션 경로에 닿지 않은 채였다** — 어댑터와 survey만 새 값을 쓰고 push 페이로드·
   `Project`·`formatFromProject`가 포맷 단위 boolean만 날랐는데, write가 조용히 폴백해서 아무도
   몰랐다 (2026-09-02 도입 → 2026-09-04 해소, ARCHITECTURE §1.35). 기간은 이틀이지만 **그 이틀 동안
   아무 게이트도 안 빨개졌다는 것이 논점이다.** 같은 축의 선례가 넷이다 (POSTMORTEM 2026-09-02 ×3,
   2026-09-03 ×1). A안의 홉은 셋이고 전부 이미 존재하는 분기를 넓히는 것이다.

> ⚠️ **A안이 뒤집히면 구현하지 말고 보고한다.** 스펙 비목표에 그대로 적어 뒀다.

### C안 (기각) — 리포당 스타일 하나를 base 파일에서 추론

blob 1회로 끝난다. 기각: `nestedByPath`가 정확히 그 이유로 실패했다 — **포맷 단위 값이 형제
파일을 오염시킨다** (musicblocks 84로케일 중 81개). 표현 축의 오염은 값 손실이 아니라 diff
노이즈라 덜 치명적이지만, **아낄 수 있는 것이 blob N−1회뿐**이라 그 위험을 살 이유가 없다.

## 순수 함수로 분리 가능한 부분 (= `/tdd` 대상)

전부 I/O가 없다. 새 모듈 하나에 몰고, 기존 모듈은 그것을 부르기만 한다.

### `lib/adapters/json-style.ts` (신규)

```ts
/** 원본 JSON 텍스트에서 읽어낸 표현. 관측 실패는 없다 — 못 읽으면 DEFAULT로 떨어진다. */
export type JsonStyle = {
  /** 한 단계 들여쓰기 문자열. "  " | "    " | "\t" 등 원본 리터럴 그대로. */
  indent: string;
  /** 원본이 비ASCII를 \uXXXX로 적었는가. */
  escapeNonAscii: boolean;
  /** 원본에서 **한 줄에 담겨 있던** 컨테이너의 평탄화 경로. 루트("")는 담지 않는다. */
  compactPaths: ReadonlySet<string>;
};

export const DEFAULT_JSON_STYLE: JsonStyle;

/** 원본 텍스트 → 스타일. 파싱 실패·관측 불가면 DEFAULT를 준다 (던지지 않는다). */
export function observeJsonStyle(text: string | undefined): JsonStyle;

/** 스타일대로 직렬화한다. 끝 개행 정확히 1개. */
export function serializeJson(value: unknown, style?: JsonStyle): string;
```

- **`serializeJson(v, DEFAULT_JSON_STYLE)`은 지금의 `serialize(v)`와 바이트 동일해야 한다.**
  이게 회귀 방어선이고 단위 테스트의 첫 줄이다 — 기본 경로가 안 바뀌어야 `clean` 부분집합의
  0.000이 유지된다 (완료 조건 ②).
- `shared.serialize`는 **지우지 않고** `serializeJson(value)`로 위임한다. ②번 세션과 겹치는
  파일이므로 diff를 한 줄로 줄인다.

#### 왜 `JSON.stringify`를 못 쓰나

`replacer`·`space`로는 **컨테이너마다 다른 펼침**과 **비ASCII 이스케이프**를 낼 수 없다. 직렬화를
직접 짜되 범위를 좁게 잡는다:

- 문자열 이스케이프는 **`JSON.stringify(s)`에 맡긴다** — 직접 풀면 서로게이트 쌍·제어문자에서
  어긋난다 (`json-shape.ts`가 같은 이유로 파서를 안 짰다). `escapeNonAscii`면 그 결과에서 코드
  유닛 > `0x7f`만 `\uXXXX`로 한 번 더 치환한다. 그게 정확히 원본이 하던 일이다.
- ⚠️ **리프가 항상 문자열은 아니다.** `json-catalog`은 그렇지만 **chrome `placeholders`는 해석하지
  않은 임의 JSON**이고 학습 chrome 33개 중 **12개**가 들고 있다 (§11.4). 직렬화기는 객체·배열·
  숫자·불린·`null`을 다뤄야 하고 **`placeholders` 내부 키 순서를 원본대로 보존**해야 한다 —
  "우리가 만든 구조가 아니다"(`types.ts`). `key-order-golden.test.ts`의 `CHROME_FULL`이 그 축의
  골든이다.

#### 축별 관측 규칙

| 축 | 관측 | 근거·함정 |
|---|---|---|
| 들여쓰기 | **첫 들여쓴 줄**의 선행 공백. 들여쓴 줄이 없으면 DEFAULT | `json-shape.ts`의 `indentOf`와 **같은 규칙**이다 — 깊은 층의 배수(4칸 파일의 2층은 8칸)에 안 흔들리려면 첫 층만 본다. 그 함수를 프로덕션으로 승격한다 |
| 이스케이프 | **문자열 리터럴 안에서** `\uXXXX` 중 코드포인트 > `0x7f`가 하나라도 있으면 true | 🔴 **`hasEscapedNonAscii`를 그대로 쓰면 고정점이 깨진다** — 문자열 문맥을 안 보는 전역 정규식이라, DB 값이 리터럴 6글자 `\u00e9`를 담으면 파일에 `"\\u00e9"`가 찍히고 재관측이 `false` → `true`로 뒤집힌다. 2차 write가 1차와 달라져 완료 조건 ⑤가 그 리포에서 red다. **관측을 `Scanner.string()` 안으로 옮긴다** — 그 메서드는 이미 `\\`를 정확히 건너뛴다. `\u0041`(A)까지 세면 거짓 양성인 것은 그대로다 |
| 한 줄 컨테이너 | 여는 괄호와 닫는 괄호 사이에 개행이 없는 **비어 있지 않은** 컨테이너의 경로 | 빈 `{}`·`[]`는 담지 않는다. **루트도 담지 않는다** — 파일 전체가 한 줄이면 들여쓰기 관측 불가와 같은 사건이고, 담으면 우리가 한 줄짜리 파일을 낸다 |

⚠️ **`compactPaths`의 키를 `.` 조인 문자열로 두지 않는다.** `Scanner`가 경로를 `${path}.${name}`로
만드는데, 원본에 점 든 키가 있는 리포 8개에서 `"a.b"`(단일 키)와 `a`→`b`(중첩)의 경로가 구별되지
않아 **엉뚱한 컨테이너가 한 줄로 나간다** — §1.35가 기록한 별칭 버그를 표현 축에서 재현하는 것이다.
고정점은 유지되지만 diff 노이즈다. **세그먼트 배열(또는 `JSON.stringify(segments)`)을 키로 둔다** —
`Scanner`가 이미 세그먼트를 들고 있어 비용이 0이다.

⚠️ **관측 스캐너를 새로 짜지 않는다.** `lib/survey/json-shape.ts`의 것을 `lib/adapters/json-style.ts`로
**옮기고** survey가 그것을 import한다 — 두 벌이 되면 지표와 프로덕션이 서로 다른 판정을 하게 된다
(ARCHITECTURE §1.35의 "`writeWithErrors`의 content가 `write`와 갈라지지 않는다"와 같은 축).

⚠️ **다만 실물이 설계보다 흩어져 있다.** `Scanner`는 셋 중 **`compactContainer` 하나만** 본다.
`indent`·`escapedNonAscii`는 `jsonShape()`가 부르는 **별도 모듈 프라이빗 함수**(`indentOf` ·
`hasEscapedNonAscii`)이고 **셋 다 export되지 않았다.** "옮긴다"는 선언부 변경을 포함하고,
`compactContainer`는 boolean이라 **경로 수집을 새로 넣는 작업**이다 — "옮기기"가 아니다.

### `lib/adapters/chrome-locales.ts` — 엔트리 필드 순서

원본 엔트리에서 `message`·`description`·`placeholders`가 나온 순서를 세어 **다수결**로 정한다.
동률·관측 불가면 지금의 `["message", "description", "placeholders"]`.

- **키마다 따로 두지 않는다.** 새 키에는 어차피 기본값이 필요하고, 300키짜리 맵을 나르는 값이
  아니다. 실측 1건이 Midnight-Lizard이고(§11.5) **파일 전체에서 균일한지는 §11.5에 적혀 있지
  않다** — 다수결이 그 경우에도 안전하다는 것이 근거이지 균일성이 근거가 아니다.
- **결정성**: 다수결은 원본 텍스트의 함수이고, 우리가 낸 파일은 그 순서로 균일해지므로 2차
  관측이 같은 답을 낸다. `dominantQuote`와 정확히 같은 논증이다 (ARCHITECTURE §1.4).

## 배선 — 홉이 셋이고 전부 기존 분기를 넓히는 것이다

| # | 위치 | 지금 | 바뀐 뒤 |
|---|---|---|---|
| a | `lib/pull/run.ts` | `if (writeStrategy === "surgical")`일 때만 blob을 읽는다 | 어댑터 종류와 무관하게 읽는다 (트리에 있는 경로만) |
| b | `lib/pull/render.ts` `renderLocaleFiles` | surgical일 때만 `currentFiles`를 싣고, 원본이 없으면 `content: null` | 재생성도 있으면 싣는다. **없어도 계속 쓴다** — 그 구분이 이 기능의 계약이다 |
| c | 어댑터 `write` | `serialize(out)` | `serializeJson(out, observeJsonStyle(<이 로케일 파일의 원본>))` — **경로로 조회한다**(아래) |
| d | `lib/survey/one.ts` `writePerLocale` | surgical일 때만 `currentFiles` | 재생성도 싣는다. **안 하면 7차 측정이 개선을 하나도 못 본다** |

**d를 표에 넣은 이유**: 이 리포에서 세 번 반복된 실패가 "판정 층은 멀쩡한데 공급 층이 끊긴 것"
이고, 그중 하나가 **지표가 반년째 구조적으로 0**이었던 건이다 (POSTMORTEM 2026-09-02). 프로덕션
경로(a·b·c)만 고치고 d를 빼면 7차 측정이 "안 고쳐졌다"고 말한다.

⚠️ **b의 갈림이 계약이다.** surgical은 원본이 없으면 파일을 만들지 않고(치환 대상이 없다),
재생성은 원본이 없어도 만든다(신규 로케일 파일). 이 줄이 뒤섞이면 **새 로케일이 PR에서 조용히
빠지거나**, 반대로 수술적 어댑터가 없던 파일을 만들어낸다.

### 원본이 없는 파일 — 형제에서 빌려 온다 (선택 태스크)

DB에 로케일이 새로 생기면 그 파일은 리포에 없다. 그대로 두면 4칸 리포에 2칸 파일 하나가 태어난다
— `quoteLiteral`이 "**삽입 줄만 튀면 맞춘 의미가 없다**"로 이미 결론 낸 문제다 (ARCHITECTURE §1.4).

**base 로케일 파일의 원본을 스타일 기증자로 넘긴다.** 그 파일의 값은 절대 읽지 않으므로 안전하고,
계약 테스트의 네거티브(아래)가 그것을 강제한다. 태스크를 따로 떼어 뒀다 — 위험이 낮고 이득도
작아서, 상위 태스크가 밀리면 뺄 수 있게.

## 불변식 영향

| 불변식 | 영향 | 보존 방법 |
|---|---|---|
| **export 결정성** (같은 입력 → 같은 바이트) | **입력의 정의가 넓어진다**: `같은 DB 상태` → `같은 DB 상태 + 같은 원본`. 수술적 어댑터가 이미 그 정의를 쓴다 (MVP §4.1 표) | MVP §4.1의 "입력" 열에서 재생성도 원본을 받는 것으로 개정. 원본이 없으면 DB 상태만으로 결정적이다 |
| **바이트 고정점** (2차 write == 1차 write) | **새로 위험해진다.** 출력이 원본에 의존하므로 관측이 진동하면 매일 빈 커밋이 쌓인다 | 세 축 전부 **고정점 성질**을 만족해야 한다: 우리가 낸 파일을 관측하면 같은 스타일이 나온다. 단위 테스트로 축마다 박고, 7차 측정이 코퍼스 100/100·16/16으로 확인한다 |
| **blob SHA 비교** (§2) | 값은 그대로. 다만 **비교 전에 blob을 읽는다** | 비교 자체는 안 바뀐다. `planPullChanges`는 손대지 않는다 |
| **키 순서 보존** (TASKS §9) | `orderedEntries`·`setDeep`·`normalizeArrays`를 **건드리지 않는다** — 직렬화 층만 바꾼다 | 기존 L1·L2 테스트가 그대로 green이어야 한다. red면 순서 층을 밟은 것이다. ⚠️ **`lib/pull/__tests__/run.test.ts`는 예외** — 홉 a가 blob 읽기를 넓히면 그 파일은 **정당하게 red**다(tasks §3). 이 단서가 없으면 정당한 red를 회귀로 오진한다 |
| **`orphaned` 제외 / 미번역 제외** | 없음 — `orderedEntries` 위층이다 | 계약 테스트가 그대로 |
| **인증 경계** (§6) | 없음 | — |
| **"병합 없음"** (코어 원칙) | 원본을 읽지만 **값은 읽지 않는다** | 계약 테스트 네거티브: 원본에 심은 센티넬 값이 출력에 나타나면 위반 |

### 고정점 논증 (축마다)

- **들여쓰기**: 출력의 첫 들여쓴 줄이 `style.indent`다 → 재관측이 같은 값.
  - ⚠️ 예외 하나: 원본이 한 줄 파일이라 `indent`가 관측 불가여서 DEFAULT(2칸)로 떨어진 경우.
    출력은 2칸이 되고 재관측이 2칸을 준다 — **값이 바뀌지만 한 번뿐이고 그다음이 고정점**이다.
    수술적 어댑터의 `>` → `>-` 전환과 같은 부류다 (ARCHITECTURE §1.4).
- **이스케이프**: `true`면 출력의 모든 비ASCII가 `\uXXXX` → 재관측 `true`. `false`면 `\uXXXX`가
  하나도 없다 → 재관측 `false`. **부분 이스케이프 원본은 첫 write에서 전부 이스케이프로 정규화되고
  그다음이 고정점**이다.
- **한 줄 컨테이너**: 출력에서 `compactPaths`의 경로만 한 줄 → 재관측이 같은 집합.
  - ⚠️ **DB에만 있는 새 키가 compact 컨테이너 안에 들어가면** 그 컨테이너는 여전히 한 줄이다
    (경로가 집합에 있으므로). 길어질 뿐 진동하지 않는다.
  - ⚠️ **집합에 있는 경로가 출력에 없으면** (그 키가 orphaned가 됐다) 그냥 안 쓰인다. 진동 없음.
- **필드 순서**: 출력이 다수 순서로 균일 → 다수결이 같은 답.
  - ⚠️ 예외: **원본이 동률이면** 기본값(message 선행)으로 떨어지고 출력은 균일해져 2차 관측이
    동률이 아니다. 들여쓰기 관측 불가·부분 이스케이프와 같은 **"한 번 바뀌고 그다음이 고정점"**
    부류다. 예외가 셋이라는 사실을 8차 측정에서 오진하지 않으려면 나란히 적어 둔다.

## POSTMORTEM에서 소환한 함정

- **2026-09-03 "값이 맞으면 통과하는 검증이 스타일 손실을 못 봤다"** — 이 기능과 **같은 계열**이다.
  거기서 얻은 규칙 둘을 그대로 적용한다:
  - *"수술적 치환에서 원본에 대응물이 있는 것은 그 대응물에서 읽는다."* → 이 기능이 그 문장에서
    "수술적 치환"을 뗀다.
  - *"픽스처의 스타일이 한 종류면 그 축은 검증되지 않은 것이다."* → 골든 픽스처를 **2칸·4칸·탭**,
    **펼침·한 줄**, **이스케이프·비이스케이프**로 양쪽 둔다. 지금 픽스처가 전부 2칸이라 이 축은
    한 번도 검증된 적이 없다.
- **2026-09-03 "고쳐 놓고도 지표가 낡아서 성공을 실패로 읽었다"** — `DiffCauses`에서 셋을 관측치로
  옮기지 않으면 34개 리포가 `clean` 분모에서 계속 빠진다. 완료 조건 ⑧이 그것이다.
- **2026-09-02 "지표 하나가 반년째 구조적으로 0이었다"** — 배선 홉 d. 순수 함수가 낸 값을 껍데기가
  안 넘기는 자리. grep: `grep -rn 'const { [a-z]' scripts/`.
- **2026-09-02 "껍데기가 파일을 안 골라 어댑터가 존재하지 않았다"** — 배선 홉 a·b. 만든 것이
  실제로 불리는지를 **진입점 테스트로** 묻는다 (완료 조건 ⑨).
- **2026-09-03 "주석이 동작한다고 단언했고 테스트의 이름만 그랬다"** — L1 테스트가 `runPull`을
  실제로 실행해 **커밋에 실린 바이트**를 본다. "함수가 존재한다"는 계약 검사가 아니다.
- **2026-09-04 audit #4 (`yaml-catalog` 재직렬화)** — 계약 테스트에 "값이 안 바뀌면 원본 바이트
  그대로"가 없어서 CST 재직렬화가 들여쓰기를 바꾸는 것을 못 봤다. **재생성에는 그 단언이
  성립하지 않으므로**(값이 같아도 파일을 새로 만든다) 대신 골든 픽스처의 `diffRatio === 0`이
  그 자리를 맡는다.

## ②번 세션(키 구분자 계약)과 겹치는 파일

| 파일 | 이 기능이 하는 것 | 충돌 위험 |
|---|---|---|
| `lib/adapters/shared.ts` | `serialize` 본문 1줄을 `serializeJson` 위임으로 | 낮음 — 시그니처 불변 |
| `lib/adapters/types.ts` | `currentFiles` **주석만** 넓힌다 | 낮음 — 타입 불변 |
| `lib/adapters/json-catalog.ts` | `write`의 `serialize(...)` 호출 2곳 | **중간** — ②는 `flatten`/`setDeep`/`nested` 분기를 만진다. 직렬화 줄과 층이 다르다 |
| `lib/adapters/__tests__/contract.ts` | 2칸 단언을 "원본 없으면 2칸"으로, 네거티브 1개 추가 | **중간** — ②도 이 파일을 만진다 |

**둘 다 만지는 자리를 최소로 유지한다**: 새 로직은 전부 `lib/adapters/json-style.ts`(신규)에
넣고, 기존 파일에서는 호출만 바꾼다.

⚠️ **목록에 `lib/adapters/index.ts`가 빠져 있었다.** 두 기능이 각각 새 파일을 만들고 **그 배럴이
유일한 export 경로**다. 키 구분자 계약이 SaaS화 이후로 미뤄졌으므로 지금은 충돌이 없지만,
되살릴 때 이 줄을 본다.

### `currentFiles?.[0]`에 기대지 않는다

수술적 어댑터가 `format.currentFiles?.[0]?.content`를 쓰는 것은 **"호출부가 정확히 한 파일을
싣는다"는 관례**에 기댄 것이고, 그 관례를 지키는 지점이 `render.ts` 한 곳뿐이다. 계약 테스트·survey에서
여러 파일을 실으면 **다른 로케일 파일의 스타일을 읽는다.** 재생성 쪽은 처음부터 **경로로 조회**한다 —
`writeWithErrors`가 이미 대상 경로를 계산하고 있어 비용이 0이다. `chrome-locales.write`는 지금
`_format`이라 시그니처부터 바꿔야 한다.

## 태스크 1을 1a / 1b로 쪼갠다

**들여쓰기 축은 직렬화기를 짜지 않고 닫힌다.** `JSON.stringify`의 `space`가 **문자열을 받고**
명세상 `space: 2`와 `space: "  "`가 동일하므로:

- **1a — 들여쓰기만** (`serialize`를 `JSON.stringify(value, null, style.indent)`로).
  대상이 학습 30개(재생성 리포의 42%)이고 **"기본 경로 바이트 동일"이 구성상 참**이다.
  손으로 짠 직렬화기의 이스케이프·서로게이트 위험을 아예 안 지난다.
- **1b — 한 줄 컨테이너(4) + 이스케이프(2)**. 커스텀 직렬화기가 필요한 것은 여기뿐이다.

지금 설계는 6개 리포를 위해 30개의 확실한 이득을 같은 커밋에 인질로 잡고 있다. **1b는 태스크 6과
같은 이유로 뺄 수 있게 둔다.**
