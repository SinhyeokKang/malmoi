# 어댑터 범용성 측정 실험

**MVP 6단계 완료 후 착수 가능 — 7단계(Actions·Cron 배선)와 독립이다** (2026-09-02 정정: 원래 "6·7단계 직후"였는데, 이 실험은 앱·DB·Actions를 쓰지 않고 모든 지표가 픽스처·대상 리포 파일만으로 계산되므로 7단계를 기다릴 이유가 없다). **이건 제품 기능이 아니라 판정 실험이다** — 산출물이 코드가 아니라 숫자와 그 숫자로 내린 결정 4개다.

## 실행 방식 — 자율 루프 (2026-09-02 결정)

**개발자가 중간에 개입하지 않는 무인 루프로 태스크 0~8을 끝까지 돌린다.** 이 전제가 문서에 요구하는 것:

- **미결(🔒)이 0이어야 착수할 수 있다.** 착수 전 결정 3개는 전부 확정됐다 — 수집 방식 `git clone --depth 1`, 오탐 판정은 리포별 **정답 카탈로그 경로**를 verdicts 파일에 기록, 결과 문서는 `docs/ADAPTER-COVERAGE.md`(루트). 루프가 결정 대기로 멈추는 지점이 없다.
- **게이트는 전부 자동이다** — `pnpm test`·`pnpm typecheck`·CLI 파이프 스모크. 수동 확인이 게이트인 태스크는 없다.
- **지표 ②의 판정은 실행 에이전트가 수행한다.** 원래 "사람이 눈으로"의 요지는 **detect 코드가 자기 자신을 채점하지 않는다**이므로, 판정 주체가 detect 밖에 있고 근거(정답 경로·판단 이유)가 verdicts 파일에 남아 **사후 감사가 가능**하면 성립한다. 표에 판정 주체를 표시한다.
- **루프 종료 조건 = 완료 조건 4개 전부 충족 + `pnpm test`·`pnpm typecheck` green.** 배포는 루프 범위 밖이다 — detect 변경은 CLI 전용이라(아래 "프로덕션 변경") 이 실험은 배포 없이 성립하고, 루프는 커밋만 쌓는다.
- 남의 리포엔 아무것도 쓰지 않는다(비목표) — 무인이라도 이 경계는 구조로 지켜진다(읽기 전용 clone, PR·커밋 코드 없음).

## 사용자

**개발자(나) 전용.** 번역 편집자에게 보이는 변화가 없다. 편집 UI도, push·pull 흐름도 건드리지 않는다.

다만 판정 ③(ts-dict 자동 탐지 제외)이 "제외"로 나오면 **코드 딕셔너리 리포의 온보딩 경로가 `--adapter ts-dict` 명시 지정으로 바뀐다** — 실전 검증 대상인 bugshot-2(903키) 자신이 그 리포라, 6·7단계 하네스 명령도 바뀐다. 하류 영향은 그것 하나다.

## 문제

**어댑터가 남의 리포에서 동작하는지에 대한 근거가 지금 하나도 없다.** 지금까지의 판단 근거는 전부 자기 리포 4개(bugshot-2·bugshot-web·skillflo·i18n-poc)이고, 그 4개는 같은 사람이 같은 관례로 쓴 것이다.

관측된 사실:

- **탐지 오탐 전례가 이미 코드 주석에 2건 박혀 있고, 서로 다른 리포에서 각 1건씩 나왔다.** bugshot-web에서 `public/search/{locale}.json`(검색 인덱스)이 실제 카탈로그보다 먼저 잡혔고(`lib/adapters/shared.ts` `rankCandidates`), bugshot-2에서 `export const ai`·`app`이 2~3자 소문자라 로케일로 잡혔다(`lib/adapters/ts-dict.ts` `localeObjects`). 리포 2개에서 각 1건 — **리포 수에 비례해 늘어난다는 뜻이다.**
- **오탐의 결과가 나쁘다.** 엉뚱한 파일을 카탈로그로 적재하고, pull이 그 파일을 덮어쓸 수 있다 *(뒷부분은 추론이다 — 실측 전례는 적재까지고, 오탐 파일로 pull이 실행된 사례는 아직 없다)*.
- **read 실패가 조용한 데이터 손실로 번지는 경로가 있다 — 단, 위험한 쪽은 에러가 아니라 무증상 skip이다** (2026-09-02 정정). `ts-dict`의 `pairs()`는 두 갈래로 갈린다: 문자열 리터럴이 아닌 **값**은 `errors`에 들어가는데, 이 경로는 `pnpm push:local`이 `errors > 0`이면 exit 1로 push를 막으므로 orphaned까지 가지 못한다. 막히지 않는 것은 **spread(`...base`)·shorthand·computed key 프로퍼티가 에러 없이 건너뛰어지는 경로**다 — 부분 payload가 게이트를 통과하고, 페이로드에 없는 키는 `orphaned = true`가 된다 — **정상 키가 export에서 빠진다.**
- **`docs/POSTMORTEM.md`가 같은 공백을 이미 규칙으로 적어뒀다**: "규모가 다른 대상으로 검증한다. 이 프로젝트에서 실전 검증이 잡은 결함이 6건째다(스캐너 4건 + CLI 2건). 작은 픽스처는 이 계열을 원리적으로 못 잡는다." 이 실험은 그 규칙을 **대상 다양성** 축으로 확장한 것이다.
- 스펙 본문에 "실물 확인 전의 추측이었다"가 두 번 나온다(MVP §5.1 `ts-dict` 범위 결정, §5.2 래퍼 오탐 1391건). 같은 함정이 범용성 판단에서 반복될 자리다.

## 프로덕션 변경 — 둘뿐이고 전부 additive다

"흐름을 건드리지 않는다"는 선언은 이 둘을 명시하고 성립한다 (2026-09-02 — spec이 변경을 숨기지 않는다):

1. **`detect`의 후보 목록 확장** — `Adapter`에 `detectCandidates(paths, probe): DetectedFormat[]`(순위순)를 **병존** 추가. 기존 `detect`·`detectFormat`·`detectFormatWith` 시그니처는 유지된다. 이게 없으면 완료 조건 ②(오탐률)를 측정할 수 없다 — 상세는 design.md.
2. **`lib/adapters/types.ts`의 계약 주석 1건** — "파일명 그대로가 로케일 코드의 진실" (design.md §함정의 부수 산출물).

detect 호출부는 CLI(`scripts/ingest.ts`·`scripts/push-local.ts`) 둘뿐이고 pull은 DB 컬럼(`Project.adapterName` 등)에서 포맷을 복원하므로 편집 UI·서버 런타임에 닿지 않는다 (실물 확인 2026-09-02).

## 완료 조건

**전부 검증 가능한 문장이다. 하나라도 숫자가 안 나오면 미완이다.**

1. **`docs/ADAPTER-COVERAGE.md`가 존재하고, 오픈소스 리포 50개 이상의 판정 결과를 포맷별 표로 담는다** (2026-09-02 상향 — 자율 루프의 목표 수치. 30개는 최소 성립선이다).
2. **지표 4개가 숫자로 있다.**
   - ① `detect` 성공률 — **분모를 둘로 분리해 둘 다 적는다**: (a) 지원 포맷 리포 대상, (b) 전체 리포 대상. 태스크 0이 YAML 등 미지원 포맷을 표본에 강제하므로(설계상 실패) 합산 분모 하나면 표본 구성으로 조정 가능한 숫자가 된다. (b)는 미지원 포맷의 실제 빈도 자료를 겸한다.
   - ② **오탐률** — 분모는 **1순위 후보를 낸 리포**. 1순위 후보가 실제 로케일 카탈로그가 아닌 비율. **판정 주체는 detect 밖의 판단자(자율 루프에선 실행 에이전트)이고, 리포별 정답 카탈로그 경로가 verdicts 파일에 남아야 하며, 표에 판정 주체를 표시한다** (자동 판정 불가 — detect가 자기를 채점하면 순환이다). **어댑터 간 오탐**(bugshot-2처럼 딴 어댑터의 후보가 정답을 가리는 경우 — MVP §5.1)도 후보 병합으로 측정 범위에 들어간다 (design.md).
   - ③ `read` 에러 유형별 건수 — JSON 파싱 실패 / 최상위 비객체 / 리프 타입 위반 / **키 충돌** / 문자열 리터럴 아닌 값 / **무증상 skip 건수(spread·shorthand·computed — 에러 없이 건너뛴 프로퍼티, 2026-09-02 추가: 유일하게 게이트를 통과하는 위험 경로가 집계에서 빠지면 안 된다)**
   - ④ **왕복 안정성** — 2층으로 정의한다 (2026-09-02 — 첫 write는 바이트가 다른 게 정상인 정규화라서, 이 구분 없이는 숫자가 정의되지 않는다. ARCHITECTURE §1.2): **의미 게이트**(read→write→read의 키·값 집합이 1차 read와 동일 — 실패는 데이터 손실) + **바이트 고정점**(2차 write가 1차 write와 바이트 동일 — 실패는 결정성 결함). **그리고 첫 write의 변경 줄 비율**(원본 대비 %)을 별도 축으로 담는다.
3. **그 표를 근거로 판정 4개가 문서에 적힌다** (2026-09-02: ts-dict 판정을 tasks에서 승격해 3→4 — spec이 정본인데 빠져 있으면 그것 없이 "완료"가 성립한다).
   - **지원 선언 포맷 목록** — 무엇을 "동작한다"고 말할 수 있는가
   - **MVP §4.1 "키 정렬" 규칙을 유지할지** — ④의 변경 줄 비율이 크면 "원본 키 순서 보존" 모드가 필요해진다
   - **`ts-dict`를 자동 탐지 후보에서 뺄지** — 무증상 skip·부분 읽기 비율 기준
   - **자동 포맷 탐지의 무인 신뢰 가능 여부** (2026-09-02 재명명 — 구 "SaaS 경로 개폐". SaaS는 MVP 어디에도 목표로 승격된 적이 없어 존재하지 않는 로드맵의 개폐를 판정할 수 없다) — ②가 **30%를 넘으면 자동 탐지는 "사람 확인 필수"로 판정**한다 (중단 기준). *30%는 잠정값이다 — 표본이 손으로 고른 비확률 표본이라, 판정 시점에 표본 구성과 함께 재검토한다.*

## 비목표

이번에 **안 하는 것**. 결과를 보고 별 기능으로 뺀다.

- **새 어댑터 구현.** YAML·`.po`·`.strings`·`.arb`·`.xliff` 전부 이번 범위 밖이다. 이 실험은 "무엇을 만들어야 하는가"를 정하는 것이고, 만드는 건 다음이다.
- **ICU/복수형 지원.** `docs/MVP.md` §7 명시적 비범위다. 이 실험은 **얼마나 흔한지만 센다** — 지원은 §7 해제가 필요하고 되물어야 한다.
- **`ts-dict` 개선.** 자동 탐지 후보에서 뺄지의 판정 근거만 만든다 (판정 자체는 완료 조건 3에 있다).
- **MVP §4.1 / ARCHITECTURE §1.1 개정.** 개정 필요 여부까지만 판정한다 (`/feature` 규칙: 스펙 문서 직접 수정 금지).
- **SaaS 온보딩 UI.** `detect` 후보를 사람이 고르는 화면은 별 기능이다.
- **대상 리포에 PR·커밋 보내기.** 읽기 전용 실험이다. 남의 리포에 아무것도 쓰지 않는다.
