# 어댑터 범용성 측정 실험

**MVP 마무리(6·7단계) 직후 착수. 이건 제품 기능이 아니라 판정 실험이다** — 산출물이 코드가 아니라 숫자와 그 숫자로 내린 결정 3개다.

## 사용자

**개발자(나) 전용.** 번역 편집자에게 보이는 변화가 없다. 편집 UI도, push·pull 흐름도 건드리지 않는다.

## 문제

**어댑터가 남의 리포에서 동작하는지에 대한 근거가 지금 하나도 없다.** 지금까지의 판단 근거는 전부 자기 리포 4개(bugshot-2·bugshot-web·skillflo·i18n-poc)이고, 그 4개는 같은 사람이 같은 관례로 쓴 것이다.

관측된 사실:

- **탐지 오탐 전례가 이미 코드 주석에 2건 박혀 있다.** `public/search/{locale}.json`(검색 인덱스)이 실제 카탈로그보다 먼저 잡혔고(`lib/adapters/shared.ts` `rankCandidates`), `export const ai`·`app`이 2~3자 소문자라 로케일로 잡혔다(`lib/adapters/ts-dict.ts` `localeObjects`). 둘 다 리포 하나에서 나왔다 — **리포 수에 비례해 늘어난다는 뜻이다.**
- **오탐의 결과가 나쁘다.** 엉뚱한 파일을 카탈로그로 적재하고, pull이 그 파일을 덮어쓴다.
- **read 실패가 조용한 데이터 손실로 번지는 경로가 있다.** `ts-dict`의 `pairs()`가 문자열 리터럴 아닌 값을 `errors`에 넣고 넘어가므로, spread·computed key가 섞인 파일은 키를 부분적으로만 읽는다. 읽히지 않은 키는 push 페이로드에 없고, 페이로드에 없는 키는 `orphaned = true`가 된다 — **정상 키가 export에서 빠진다.**
- **`docs/POSTMORTEM.md`가 같은 공백을 이미 규칙으로 적어뒀다**: "규모가 다른 대상으로 검증한다. 이 프로젝트에서 실전 검증이 잡은 결함이 6건째다(스캐너 4건 + CLI 2건). 작은 픽스처는 이 계열을 원리적으로 못 잡는다." 이 실험은 그 규칙을 **대상 다양성** 축으로 확장한 것이다.
- 스펙 본문에 "실물 확인 전의 추측이었다"가 두 번 나온다(MVP §5.1 `ts-dict` 범위 결정, §5.2 래퍼 오탐 1391건). 같은 함정이 범용성 판단에서 반복될 자리다.

## 완료 조건

**전부 검증 가능한 문장이다. 하나라도 숫자가 안 나오면 미완이다.**

1. **`docs/ADAPTER-COVERAGE.md`가 존재하고, 오픈소스 리포 30개 이상의 판정 결과를 포맷별 표로 담는다.**
2. **지표 4개가 숫자로 있다.**
   - ① `detect` 성공률 — 후보를 하나라도 낸 리포 비율
   - ② **오탐률** — 1순위 후보가 실제 로케일 카탈로그가 아닌 비율. **사람이 눈으로 판정하고, 표에 그 사실을 표시한다** (자동 판정 불가)
   - ③ `read` 에러 유형별 건수 — JSON 파싱 실패 / 최상위 비객체 / 리프 타입 위반 / **키 충돌** / 문자열 리터럴 아닌 값
   - ④ **왕복 안정성** — `read → write → read`가 동일 결과인 리포 비율, **그리고 첫 `write`의 변경 줄 비율**(원본 대비 %)
3. **그 표를 근거로 판정 3개가 문서에 적힌다.**
   - **지원 선언 포맷 목록** — 무엇을 "동작한다"고 말할 수 있는가
   - **MVP §4.1 "키 정렬" 규칙을 유지할지** — ④의 변경 줄 비율이 크면 "원본 키 순서 보존" 모드가 필요해진다
   - **SaaS 경로 개폐** — ②가 30%를 넘으면 자동 연동 기반 SaaS는 닫히고 사내 도구로 남는다 (중단 기준)

## 비목표

이번에 **안 하는 것**. 결과를 보고 별 기능으로 뺀다.

- **새 어댑터 구현.** YAML·`.po`·`.strings`·`.arb`·`.xliff` 전부 이번 범위 밖이다. 이 실험은 "무엇을 만들어야 하는가"를 정하는 것이고, 만드는 건 다음이다.
- **ICU/복수형 지원.** `docs/MVP.md` §7 명시적 비범위다. 이 실험은 **얼마나 흔한지만 센다** — 지원은 §7 해제가 필요하고 되물어야 한다.
- **`ts-dict` 개선.** 자동 탐지 후보에서 뺄지의 판정 근거만 만든다.
- **MVP §4.1 / ARCHITECTURE §1.1 개정.** 개정 필요 여부까지만 판정한다 (`/feature` 규칙: 스펙 문서 직접 수정 금지).
- **SaaS 온보딩 UI.** `detect` 후보를 사람이 고르는 화면은 별 기능이다.
- **대상 리포에 PR·커밋 보내기.** 읽기 전용 실험이다. 남의 리포에 아무것도 쓰지 않는다.
