## 사용자와 문제

개발자는 프로젝트 생성·리포 연결·소스/멤버/토큰 관리를, 번역 편집자는 탐색·번역 저장·Publish 등 기존 허용 동작을375px부터 모두 수행한다. 역할 때문에 없는 기능은 유지하지만 폭 때문에 기능을 뺄 수 없다.

문제의 근거는 **2026-10-07 사용자 결정**이다(원문: "할거면 풀스펙. 모든 기능을 지원하는 게 맞는 것 같아. 괜히 분기 만들지 말고, UI로 전부 해결"). 현재 코드의 셸 하한1280, LNB200~320/접힘40, 번역 최소772, 프로젝트 이름420, 멤버 이름300+역할132+날짜150, 온보딩 파일 판 고정분모952가 유동 배치를 막는다. 이미 폭에 따라 정보를 **숨기는** 코드도 있다 — `components/projects/project-list.tsx:288`의 `@max-[760px]:hidden` 등 760·940·1120 경계에서 로케일 미터가 사라진다. 1024 뷰포트도 LNB와 본문 여백 때문에 번역 카드가772 미만일 수 있다. A0에서 375 한 컷 실측을 관측 사실로 덧붙인다.

## 범위 게이트·확정 사항

PRODUCT §4.2 비범위 및 §4.3 후속 기능과 충돌 없음. 기존 Publish·Sync·Revert·needsReview를 재배치하며 새 승인 워크플로·역할·권한을 만들지 않는다. ARCHITECTURE §0 보존.

**이 기능은 기존 사용자 판정 두 건을 뒤집는다**(2026-10-07 사용자, 위 원문): `docs/PRODUCT.md:824`(폰 가로 스크롤 수용)와 `docs/DESIGN.md:340` §5·`:364`·`:854`·`:856`(최소 1280·반응형 분기 0). 정본 갱신은 A8의 독립 태스크다.

브리프 D4~D6 유지: 최소375px부터 전 기능, 공개 단계 후 앱 구현, 앱 완성 뒤 랜딩 목업 내부까지 실제 컨테이너 기준 반응형(A-11 — 앱 완료 조건에 포함, 2026-10-07 사용자 재확인), 가이드 컷 en 데스크톱 고정.

## 검증 매트릭스

375×812·768×1024·1024×768·1280×800.

**샘플링 규칙**(2026-10-07 검수 합의): 4폭 × 라이트 × en은 모든 화면 기본 상태. 다크·ko·es는 375·1280 양끝만. 24조합 전수는 번역 편집(A-03·A-04)·Publish/Sync(A-05)·온보딩(A-08)만. 빈/오류/진행/권한 상태는 375·1280. System OS 양쪽은 한 번 확인한다.

측정 판정: 루트 가로 overflow0, 표/코드 외 내부 가로 overflow0, 숨은 노드 포커스0, 마지막 동작 도달·겹침0. overflow-hidden으로 가린 결과는 통과가 아니다. LNB200/240/320/40와1024·1280을 교차한다. 1023/1024/1025 및 변경된 컨테이너 경계 ±1(소스 상세 모달 `max-[850px]` 포함)을 실측한다.

200% 확대(유효 CSS 폭375 이상), 긴 프로젝트명/키/경로/이메일/시간대, 다수 로케일·키, orphaned·빈 소스, UTC+5:30, 한글 조합 입력을 포함한다. 터치·소프트 키보드는 ego-browser 터치 에뮬레이션으로 판정한다(2026-10-07 사용자 — 실기기 대체). 모바일 CPU 4× 스로틀에서 5,000키 첫 렌더·목록↔상세 전환을 재고 §1.95 기준을 넘으면 별도 결함으로 분리한다.

## 출시와 비목표

**프로덕션은 공개 기능과 동시 출시한다**(2026-10-07 사용자). 공개 단계(P2~P7)가 dev에 먼저 쌓이고, A2~A7이 그 위에 쌓인 뒤 `/merge` 한 번으로 둘 다 나간다. A2~A5는 작은 커밋으로 구현하되 앱 셸 하한 제거(A6)와 전 기능 완료를 하나의 앱 단위로 검증한다. preview 중간 상태는 모바일 기능 제한판으로 표방하지 않는다. A2e(A7)는 A2~A5의 확정 배치를 사용하며 앱 완료 조건에 포함된다.

스키마·동기화·권한 변경, 여러 키 draft, 브라우저 간 동기화, 가상화 라이브러리·별도 모바일 URL·네이티브 앱·새 디자인 체계, PWA·manifest, `theme-color`, 화면 방향 고정, 스와이프 제스처, Tooltip 프리미티브는 비목표다. 기존 가이드 촬영은1280×800 en 대표 컷을 유지한다.

## 확정된 상호작용

2026-10-07 사용자 확정: ‘목록으로’는 URL·선택키·draft를 유지하는 로컬 판 전환이다. 목록 스크롤과 선택 표시를 복원하고 같은 키를 다시 열면 미저장 입력을 이어 편집한다. 브라우저 뒤로/앞으로는 기존 URL 이동과 이탈 확인을 유지한다. 판 전환만으로 history entry를 추가하거나 draft를 폐기하지 않는다. 다른 소스로의 트리 이동 의도는 클라이언트 모듈 변수 1회성으로 넘긴다(design §3). 사용자 결정 대기 항목은 없다.
