## 사용자와 문제

개발자는 프로젝트 생성·리포 연결·소스/멤버/토큰 관리를, 번역 편집자는 탐색·번역 저장·Publish 등 기존 허용 동작을375px부터 모두 수행한다. 역할 때문에 없는 기능은 유지하지만 폭 때문에 기능을 뺄 수 없다.

현재 코드의 셸 하한1280, LNB200~320/접힘40, 번역 최소772, 프로젝트 이름420, 멤버 이름300+역할132+날짜150, 온보딩 파일 판 고정분모952가 유동 배치를 막는다. 실측 장애가 아니라 코드에서 확인한 제약이다. 1024 뷰포트도 LNB와 본문 여백 때문에 번역 카드가772 미만일 수 있다.

## 범위 게이트·확정 사항

PRODUCT §4.2 비범위 및 §4.3 후속 기능과 충돌 없음. 기존 Publish·Sync·Revert·needsReview를 재배치하며 새 승인 워크플로·역할·권한을 만들지 않는다. ARCHITECTURE §0 보존. DESIGN의 앱1280 하한·미지원 판정은 앱 전체 완료 시 변경한다.

브리프 D4~D6 유지: 최소375px부터 전 기능, 공개 1차 후 앱 구현, 앱 완성 뒤 랜딩 목업 내부까지 실제 컨테이너 기준 반응형, 가이드 컷 en 데스크톱 고정.

## 검증 매트릭스

375×812·768×1024·1024×768·1280×800에서 각 화면 기본 상태24조합. 핵심 편집/위험 동작과 긴 문구도24조합, 나머지 빈/오류/진행/권한 상태는 최소375·1280에서 검사한다. System OS 양쪽도 별도 확인한다.

루트 가로 overflow0, 표/코드 외 내부 가로 overflow0, 숨은 노드 포커스0, 마지막 동작 도달·겹침0. overflow-hidden으로 가린 결과는 통과가 아니다. LNB200/240/320/40와1024·1280을 교차한다.1023/1024/1025 및 변경된 컨테이너 경계 ±1을 실측한다.

200% 확대(유효 CSS 폭375 이상), 긴 프로젝트명/키/경로/이메일/시간대, 다수 로케일·키, orphaned·빈 소스, UTC+5:30, 한글 조합 입력을 포함한다. 실제 터치 브라우저에서 소프트 키보드·주소창 변화·스크롤 후 Save 접근성을 확인해야 모바일 입력 검증 완료다. 데스크톱 에뮬레이션만 통과한 경우 그 항목은 미완이다.

## 분리 출시와 비목표

P1 공유 계약이 선행한다. A2a~A2d를 작은 커밋으로 구현하되 앱 셸 하한 제거와 **전 기능** 완료를 하나의 앱 출시 단위로 검증한다. 중간 단계는 모바일 기능 제한판으로 배포하지 않는다. A2e는 A2a~d의 확정 배치를 사용하며 앱 본체 뒤의 별도 커밋이다. 전체 feature 완료에는 A2e도 포함한다. 실제 배포/프로덕션 시점은 별도 요청으로 정한다.

스키마·동기화·권한 변경, 여러 키 draft, 브라우저 간 동기화, 가상화 라이브러리·별도 모바일 URL·네이티브 앱·새 디자인 체계는 비목표다. 기존 가이드 촬영은1280×800 en 대표 컷을 유지한다.

## 확정된 상호작용

2026-10-07 사용자 확정: ‘목록으로’는 URL·선택키·draft를 유지하는 로컬 판 전환이다. 목록 스크롤과 선택 표시를 복원하고 같은 키를 다시 열면 미저장 입력을 이어 편집한다. 브라우저 뒤로/앞으로는 기존 URL 이동과 이탈 확인을 유지한다. 판 전환만으로 history entry를 추가하거나 draft를 폐기하지 않는다. 사용자 결정 대기 항목은 없다. 시안 수령과 치수 실측은 구현 전 검증 태스크로 남는다.
