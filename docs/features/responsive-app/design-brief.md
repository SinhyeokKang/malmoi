# 앱 반응형 디자인 브리프

## 한 줄

모든 지원 폭에서 번역 편집·관리·온보딩 전 기능을 지원한다. 폭에 따른 기능 분기는 0이며 차이는 고정 내비↔서랍·적층·단일 판 전환뿐이다.

## 확정 기준

아래 확정 사항을 전제로 각 화면을 한 벌만 그린다. 공개 표면의 추천은 앱이 공유하는 헤더·가이드 맥락과 일치시킨다.

- **D4 확정 — 사용자 확인 완료:** 최소 지원 폭 375px. 이 폭부터 번역 편집과 관리 작업 전부를 검증한다.
- **D5 확정 — 사용자 확인 완료:** 공개 1차의 5씬 축소+줄바꿈 캡션을 거쳐, 앱 반응형 완성 후 랜딩 목업에도 16:10 데스크톱→태블릿→모바일 컨테이너를 순서대로 보여주고, 내부 UI는 그 컨테이너의 실제 너비에 따라 앱의 반응형 규칙으로 배치한다. A18은 앱 완성 후의 후속 프레임이며 공개 1차의 대안이 아니다.
- **D6 확정 — 사용자 확인 완료:** 좁은 로그인 화면은 KV Shell 숨김·폼 우선, 가이드 스크린샷은 en 데스크톱 고정. 앱 기능과 가이드 공유 구조를 보존한다.

A18의 내부 배치는 완성된 앱을 기준으로 한다. 목업 컨테이너의 실제 너비가 반응형 판정 입력이며, 바깥 페이지의 뷰포트나 기기별 수동 UI 선택이 입력이 되어서는 안 된다. 내비 전환 경계와 콘텐츠 컨테이너 규칙은 앱과 동일하다. 목업 외곽의 종횡비만 바꾸지 않고 고정 논리 캔버스·배율·캡션 높이·씬 배치를 함께 조정한다. 데스크톱 종횡비는16:10이고 태블릿·모바일의 구체 종횡비는 실제 앱과 스테이지 높이 예산으로 정하며, 5씬 정보와 reduced-motion·스크럽 동작은 유지한다.

## 동작 주석

- 서랍 열기·닫기·Esc·배경·Tab 순환·트리거 포커스 복귀는 공개 브리프와 같은 계약. 경로 이동 때 기존 도착 포커스 규칙을 따르고, 좁음↔넓음 변경으로 숨은 노드에 포커스가 남지 않게 한다.
- 데스크톱 수동 LNB 접기/저장폭과 좁은 자동 서랍을 분리한다. 돌아오면 사용자 폭이 복원돼야 한다.
- 번역은 모바일용 컴포넌트를 따로 마운트해 draft·선택 상태를 복제하지 않는다. 2026-10-07 사용자 확정: ‘목록으로’는 URL·선택키·draft를 유지한 판 전환이며 목록 스크롤과 선택 표시가 보존된다. 같은 키를 다시 열면 미저장 입력을 이어 편집한다. 브라우저 뒤로/앞으로는 기존 URL 이동과 이탈 확인을 유지하고, 판 전환은 history entry를 추가하지 않는다.
- 입력중 폭 전환·언어변경·소스이동에서 손실 방지와 기존 leave guard를 유지한다. IME 조합중 Enter/Esc와 키보드가 열린 Save 접근성을 별도 주석으로 표기한다.
- 단일 판에서 같은 키 재열기·다른 키 선택(다른 소스 포함)·직접 key URL·검색/Inbox 진입은 보이는 상세 제목으로 포커스를 옮긴다. 제목은 로딩→성공/빈/오류 전환에도 유지하고, 응답이 사용자가 옮긴 포커스를 빼앗지 않는다. 검색/Inbox 닫힘의 복귀가 상세 착지를 덮지 않으며 이동 취소는 기존 판·포커스, 목록 복귀는 선택행을 유지한다.
- 폭 왕복은 입력 중인 상세가 저장된 판보다 우선한다. 목록으로→넓힘→상세 입력/IME 조합→좁힘에서는 상세를 유지하고 포커스·커서·조합을 옮기거나 끊지 않는다. 상세를 사용하지 않은 폭 왕복은 기존 목록 판을 유지한다.
- 단일 판의 트리/소스 범위 선택은 미저장 확인을 통과한 뒤 목록으로 복귀한다. 서버가 첫 키를 선택해도 목록을 유지하며 다른 소스로의 재마운트에도 같다. 포커스는 목록 선택행, 없으면 목록 제목으로 옮긴다. 외부 key URL·검색·Inbox 진입은 상세를 열고, 취소되거나 대체된 트리 이동의 늦은 응답이 판을 되돌리지 않는다.
- 기존 서버 권한이 진실이다. 같은 역할·상태에서 가능한 동작은 모든 지원 폭에서 같아야 한다. 폭을 이유로 기능을 숨기거나 비활성화하지 않는다.
- Dialog footer는 스크롤로 항상 도달 가능하고, 긴 경고·읽기전용 이유·disabled 설명이 빠지지 않는다. 진행중 닫기 제한과 재시도·오류 포커스는 기존 계약을 지킨다.
- 검색·Inbox는 공개 단계의 조립을 재사용한다. 같은 Action을 모바일/데스크톱 두 인스턴스가 중복 실행하지 않는다.
- 온보딩 후보/샘플의 순차 판 경계608px은 핸들8px을 포함한 본문 content box 너비다.608px에서는 후보200+핸들8+샘플400으로 두 판을 배치하고, 그 미만은 순차 판이다. 시안에서 경계를 조정하면 설계·태스크의 본문 폭 기준도 함께 맞춘다.

## 그리지 않는 것

새 승인 상태 머신, 새 역할/권한, DB·동기화 변경, 네이티브 앱, 별도 모바일 URL, 소비자 없는 프리미티브, 새 디자인 시스템. PRODUCT §4.2에 따라 새 승인 단계는 만들지 않고 기존 Publish·Sync·Revert·needsReview 흐름을 그대로 지원한다.
