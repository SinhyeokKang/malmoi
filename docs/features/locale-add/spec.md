# Add a language — 스펙

작성: 2026-10-13 · 상태: **스펙 밑작업 완료 · 착수 대기**(순서: 감사 런 `/merge` v1.4.0 → gitlab-oauth 구현 → 이 기능)

slug는 `locale-add`이고 **범위는 웹 UI(+ MCP)에서 소스에 로케일을 "추가"하는 것 하나**다. 키 추가는 별개 스펙(나중)이고, 로케일·키 **삭제**는 범위 밖이다 — 리포에서 파일을 지우면 `orphaned`가 되는 지금 규칙을 그대로 둔다.

## 1. 목적과 사용자

OWNER가 소스 상세 모달에서 새 언어(예: `ja`)를 추가하면 번역자가 곧바로 그 언어를 채우고, Publish가 리포에 **새 로케일 파일**(`locales/ja.json`)을 만들어 Malmoi PR로 보낸다.

**1순위 사용자는 번역 편집자(비개발자 동료)**다 — 지금은 새 언어를 시작하려면 개발자에게 빈 파일을 만들어 커밋해 달라고 부탁하고, CI 적재(또는 야간)를 기다려야 한다. **개발자**는 빈 파일 커밋 한 번을 덜 한다. 추가 자체는 OWNER(`project:settings`)만 한다 — 리포의 파일 집합을 바꾸는 결정이라서다(§3·design §6).

## 2. 관측된 문제

- 로케일 행의 생산자는 적재 하나다 — `applyPush`의 Locale upsert(`lib/push/apply.ts:242`)가 페이로드의 로케일만 만들고, 페이로드에 없는 로케일은 같은 트랜잭션이 `orphaned`로 세운다(`apply.ts:264`). UI에는 로케일을 만드는 길이 없다(PRODUCT §7.2 "추가·삭제하지 않는다").
- 소스 상세 모달의 언어 카드가 그 규칙을 화면에 말한다 — `messages/en.tsx:3416` "Languages come from the repository. Add or remove the files there."
- 그런데 Publish 쪽은 새 파일을 이미 만들 줄 안다 — 재생성 writer(`json-catalog`·`chrome-locales`)는 원본 없이 파일을 낸다(ARCHITECTURE §1.1 들여쓰기 행 "재생성은 원본 없이도 파일을 만들어야 한다(신규 로케일)" · §5.5.05 "트리에 없는 파일을 만드는 갈래는 그대로다(신규 로케일이 그것으로 생긴다)"). 빠진 것은 **DB에 로케일 행을 세우는 길**과 그 행을 적재가 지우지 않게 하는 소유 규칙이다.
- 수요의 근거는 사용자 결정(2026-10-13)이다 — 이 기능을 요청한 이탈·이슈는 관측하지 않았다.

## 3. 범위 게이트

**PRODUCT §7.2 "SaaS UI에서 로케일을 추가·삭제하지 않는다" 중 *추가*를 해제한다 — 사용자 결정(2026-10-13).** 삭제는 그대로 막는다(리포에서 파일을 지우는 것이 유일한 삭제이고 결과는 비파괴 `orphaned`).

옛 근거는 "로케일 소유권 — 리포가 정본이다"였다. 이 기능은 그 근거를 버리지 않고 **시점으로 나눈다**: 추가된 로케일의 존재는 **전달 확인 전까지 DB가, 전달 확인 뒤엔 리포가** 소유한다(제안 → 전달 → 리포 소유). 어느 순간에도 소유자는 하나이고, 적재는 로케일 행을 **DB 표시(`proposedAt`)로** 고를 뿐 리포 값과 DB 값을 견주지 않는다 — 병합이 아니다(ARCHITECTURE §0 불변식 2, B3.4 "키마다 출처가 하나"와 같은 결).

코어 원칙과의 대조:

| 원칙 | 이 기능 |
|---|---|
| 번역 값 = DB, 소스 키 = 코드 | 그대로. 키는 추가하지 않는다 — 새 로케일의 키 집합은 그 소스의 활성 키다 |
| 로케일 존재 = 리포 (불변식 1) | **예외 하나를 단다** — 제안 중(전달 확인 전) 로케일은 DB가 소유한다. 정본 개정은 tasks §8 |
| 병합 없음 (불변식 2) | 자동 적재는 `proposedAt`이 선 행을 orphan하지 않는다(값 비교 없음). Publish는 제안 경로에 파일이 이미 있으면 그 로케일을 **보류**한다(값 비교 없음 — 좌표 판정) |
| 삭제하지 않는다 (불변식 3) | 제안 철회는 수동 Sync 폐기가 `orphaned`로 돌린다 — 행·번역은 남는다 |
| export 결정성 (불변식 4) | 새 파일의 표현을 base 원본에서 빌린다 — 입력이 "같은 원본 파일"이라 결정성 유지 |
| 리포 쓰기 경로는 서버가 정한다 (불변식 10) | 사람이 넣은 로케일 코드는 경로 조각이다 — `isPathSafeLocale`·`isLocaleShaped` 두 층 + 해석된 경로 `isPathSafeRepoPath` |

비범위 대조(PRODUCT §4.2): 걸리는 항목 없음 — "포맷별 무제한 설정 UI"가 아니다(어댑터 내부를 노출하지 않고 언어 코드 하나만 받는다).

## 4. 완료 조건 — 수락 기준

1. OWNER가 `json-catalog`·`chrome-locales` 소스의 상세 모달 언어 카드에서 [Add language]로 코드 하나를 넣으면, 그 소스의 언어 목록에 **제안 배지("Not in repository yet")**를 단 행이 생기고 번역 화면에서 그 언어를 편집할 수 있다.
2. 그 상태로 CI `/api/push`·야간 적재가 돌아도 그 로케일은 `orphaned`가 되지 않는다(격리 PG 시나리오: 제안 로케일 + 페이로드에 없음 → `orphaned = false`, `proposedAt` 유지).
3. 번역을 하나 이상 저장한 뒤 Publish하면 Malmoi PR에 `{pathTemplate의 {locale} 치환}` 경로의 **새 파일**이 실리고, 그 파일의 들여쓰기·줄바꿈·BOM·이스케이프·(chrome) 필드 순서가 같은 소스의 base 원본과 같다. 같은 DB·같은 원본으로 두 번 렌더하면 바이트가 같다.
4. 그 Publish의 전달 확인 트랜잭션에서 제안 표시가 지워진다. PR 머지 뒤 push가 파일을 보면 일반 로케일이고, PR이 머지 없이 닫히면 다음 적재가 `orphaned`로 세운다(비파괴).
5. 번역이 0개인 제안은 Publish가 파일을 내지 않고(ARCHITECTURE §1.1 "낼 것 0개 → 원본 없으면 `null`") 제안으로 남는다 — 미리보기·결과가 그 사실을 말한다.
6. Publish 시점에 제안 경로에 파일이 이미 리포에 있으면 그 로케일만 보류되고(`withheld`) 나머지는 나간다. 미리보기·결과·Logs가 같은 수를 말한다.
7. OWNER의 수동 Sync는 제안을 건너뛰지 않는다 — 제안이 있으면 확인 창이 그 코드를 말하고 서버 지문이 그것을 묶으며, 승인하면 제안 로케일이 `orphaned`가 된다(번역 행은 남는다).
8. `orphaned` 로케일 코드를 다시 추가하면 같은 행이 되살아나고(`orphaned = false` + 제안), 값 있는 셀에 편집 토큰이 새로 발급돼 미전달 수에 세어지고 다음 Publish에 실린다.
9. 거부가 값으로 흐른다 — 수술적 어댑터(`ts-dict`·`yaml-catalog`·`code-dict`) · 모양·경로 불가 코드 · 이미 있는 코드 · 대소문자·구분자만 다른 코드 · chrome 지원 목록 밖 · 로케일 상한(200) · 보관 · EDITOR가 각자 사유 코드로 거부되고 DB를 바꾸지 않는다.
10. 추가는 `Project`→`TranslationSurface` 잠금 안에서 `ProjectEvent`(SURFACE `surface.localeAdded`)와 같은 트랜잭션으로 확정되고, Logs가 "<누가> added <코드> to <소스>"를 말한다.
11. MCP `add_locale`(WRITE, `project:settings`)이 같은 코어를 부르고 같은 거부 코드를 영어로 돌려준다.
12. GitHub·GitLab 프로젝트 둘 다 위 3·4·6이 같다(호스트 중립 코어 — 렌더·보류는 `GitTreeEntry`만 본다).
13. 화면 문구는 en·ko·es 세 사전에 같은 커밋으로 들어가고, 언어 카드 설명(`languagesHelp`)이 "추가는 여기서, 삭제는 리포에서"로 바뀐다.

## 5. 비목표

- **키 추가** — 별개 스펙(나중).
- **로케일 삭제·제안 취소 버튼** — 제안 철회는 수동 Sync 폐기 하나다(사용자 결정 2026-10-13 ②). 전달된 로케일의 삭제는 지금처럼 리포에서.
- **수술적 어댑터(`ts-dict`·`yaml-catalog`·`code-dict`)의 새 로케일** — 원본 없이 쓸 수 없다(design §2). 후속 후보로만 남긴다.
- **여러 소스에 한 번에 추가** — 소스마다 한다(로케일은 표면 소유 — 불변식 5).
- **기준 언어를 제안 로케일로** — base는 리포 파일이 정한다(제안은 base 후보에서 빠진다).
- **로케일 이름(`Locale.name`) 편집** — 지금처럼 코드와 같다.
- **기계 번역·base 값 복사로 새 로케일 채우기** — PRODUCT §4.2(번역을 생성하지 않는다).
- **새 파일 표현의 base 외 출처**(다른 형제 파일 다수결 등) — base 원본 하나로 정한다.
