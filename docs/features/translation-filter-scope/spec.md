# translation-filter-scope — spec

## 사용자

**번역 편집자(비개발자 동료)**. 소스(표면)가 둘 이상인 프로젝트에서 "화면에 보이는 문구"로 키를 찾는 사람이다.
개발자는 키 이름을 알아 트리로 바로 가므로 이 변경의 이득이 작고, 잃는 것도 없다(`This source`는 여전히 한 번에 고를 수 있다).

## 문제 (관측)

- 소스 A·B·C가 있을 때 번역 화면에 처음 들어오면 A(프로젝트 기본 표면)가 선택되고, 범위가 **보이지 않게** `This source`로 좁혀져 있다
  (`DEFAULT_TRANSLATION_QUERY.scope = "source"`, Scope `FilterMenu`의 `on`은 `scope !== "source"`일 때만 켜진다).
- 이 상태에서 C에만 있는 값을 검색하면 **0건**(`No keys match "<q>"`)이고, 빈 상태의 버튼은 `Clear search` 하나다. 범위를 넓히라는 안내가 없다
  — `messages/en.tsx`의 `searchAll: "Search all sources"`는 정의만 있고 쓰는 곳이 없다.
- 트리 클릭이 범위 필터를 **덮어쓴다**(`treeQuery` → `This source`/`This namespace`). `All sources`로 넓혀 둔 상태도 트리를 누르면 조용히 좁혀진다.
  트리가 "위치"와 "필터" 두 역할을 겸해서, 사용자가 필터를 건드린 적이 없어도 쿼리 조건이 걸린다.

## 모델 (사용자 확정, 2026-09-30)

**필터는 단방향이다.** 필터 콤보박스(Completion · State · Scope)와 검색을 사용자가 직접 조작할 때만 조회 조건이 붙는다.

- 트리·키 선택은 **위치**다 — 필터 값을 바꾸지 않는다. 트리는 조건이 없을 때도 위치(경로 소스·`ns`)를 강조한다 — 전 소스라는 사실은 Scope
  트리거(`All sources`)와 행의 `surface · key` 접두가 말한다.
- 필터가 켜지면 트리와 키 목록에 **반영**된다 — 조건에 맞지 않는 소스·네임스페이스·키는 **숨긴다**. 예외 둘(사용자 확정):
  **위치 노드(경로 소스·위치 네임스페이스)는 0이어도 흐린 행으로 남고**, 노드 집합은 **목록 세대 안에서 고정**된다(숫자만 갱신 — 목록의
  `savedOut`이 저장으로 조건을 벗어난 행을 자리에 남기는 것과 같은 규칙).
- 필터가 모두 꺼진 상태(= 최초 진입, `Clear filters` 뒤)의 조회 범위는 **프로젝트 전체(`All sources`)**다.
- `This namespace`는 "**현재 위치의** 네임스페이스"다 — 그 상태에서 트리로 위치를 옮기면 대상도 따라간다(새 파라미터를 만들지 않는다).
- 트리 클릭은 그 위치의 **첫 키 한 행**으로 간다. 정렬이 `Incomplete first`라 같은 네임스페이스의 키는 목록에 흩어진다 — 그 네임스페이스만
  보려면 Scope `This namespace`를 고른다(PRODUCT §3·가이드에 명시).

## 완료 조건 (검증 가능한 문장)

1. 최초 진입(쿼리 없음)의 목록은 프로젝트의 **모든 활성 소스**의 활성 키를 담고, Scope 트리거는 `All sources`에 꺼진 표시(`on=false`)다.
2. 소스 A 경로에서 C에만 있는 번역값을 검색하면 C의 키가 결과에 나온다(필터 조작 없이). 트리에는 A(위치)가 흐린 0 행으로 남고 C가 보인다.
3. 트리의 소스·네임스페이스를 눌러도 URL의 `scope`·`completion`·`state`·`q`가 **바뀌지 않는다**.
4. 트리 클릭은 현재 조건의 목록에서 **그 위치(소스·네임스페이스)의 첫 키**를 선택하고, 그 행이 보이게 스크롤된다. 대상이 없으면(조건 없는 상태의
   0키 노드) 선택·스크롤 없음. 마운트 착지(딥링크·새로고침·다른 소스로의 이동)도 선택 행으로 스크롤한다. 사용자가 목록에서 직접 누른 행은
   스크롤하지 않는다.
5. 화면 목록은 **조건에 맞는 키 전부를 한 번에** 싣는다 — `Show more keys` 버튼이 없고, **재필터 직후** 목록 배지 수 = 행 수다(저장 뒤의
   `savedOut` 행은 세대가 바뀔 때까지 남는다).
6. 조건(Completion·State·Scope·검색) 중 하나라도 켜지면 트리는 **일치 키가 1개 이상인 소스·네임스페이스 + 위치 노드**만 보인다. 같은 세대 안의
   Save로 일치가 0이 된 노드는 숫자만 0으로 바뀌고 사라지지 않는다.
7. `Clear filters`는 Scope를 `All sources`로 되돌린다(완성도·상태도 기존처럼). 검색어·트리 위치·상세 언어·선택 키는 남는다.
8. `scope`가 없는 옛 링크는 `All sources`로 열린다. `scope=source`·`scope=namespace`는 그대로 그 범위로 열린다. scope 없이 링크를 만드는 앱
   내부 자리(design §1 목록)도 전부 `All sources`로 열린다.
9. 검색 결과 0건의 빈 상태는 design §2.3의 표를 따른다 — 검색어가 있고 Scope ≠ `All sources`면 주 버튼이 `Search all sources`이고, 누르면
   **Scope만** `All sources`로 바뀐다(Completion·State 유지). 완성도·상태가 켜져 있으면 `Show all n keys` 보조 버튼이 함께 선다.
10. Logs·Home의 `Open this translation`과 상세의 링크 복사는 **필터를 켜지 않은 채** 그 키를 선택한 주소를 만든다.
11. **측정 게이트**(design §3.3) — 로컬 production 빌드에서 5,000행 전 소스 착지가 한계선(`loadEventEnd`·타이핑 INP·Save 재검증·문서 크기) 안이다.
    20,000키×200언어 fixture의 전량 조회 DB 시간과 응답 바이트를 기록한다(판정이 아니라 기록 — 비교 기준 389ms는 LIMIT 100 조회였다).
12. 목록은 Tab 정지점이 **하나**이고 ↑/↓·Home/End로 행 사이를 옮긴다(Enter·Space가 선택).
13. MCP `list_keys`를 `scope` 없이 부르면 전 활성 소스의 키를 돌려주고, cursor 페이징(`pageSize`·`nextCursor`)은 그대로다.

## 비목표

- **정렬 변경 없음** — `Incomplete first` 하나를 유지한다(ARCHITECTURE §1.96).
- **MCP `list_keys`의 cursor 페이징은 그대로** — 외부 계약이다(design §3.1). 기본 범위만 화면과 같이 넓어진다.
- **키 선택이 트리 위치를 옮기지 않는다** — `All sources`에서 다른 소스의 키를 눌러도 트리 강조는 경로 소스에 남는다(다음 단계 후보).
- `This namespace` 옵션의 비활성화(트리 위치가 `All namespaces`일 때) — 지금처럼 소스 전체로 처리한다.
- 가상 스크롤 도입 없음(CLAUDE.md 스택 — 근거는 ARCHITECTURE §1.95). 측정 게이트를 못 넘으면 이 변경의 전량 로드를 다시 설계한다.
- 트리 이동을 클라이언트 전용으로 만들지 않는다 — 같은 소스 안 이동도 서버 왕복(새 목록 세대)이다(2026-09-30 사용자).
- 위치 네임스페이스에 속한 행의 별도 시각 표시 없음.
