## 1. 문제와 사용자

소스 추가·적재 상태는 Settings의 `Translation sources`, 언어 현황·기준 언어 설정은 Locales에 있다.
**OWNER가 같은 소스를 관리하려면 두 화면을 오간다** — 이 기능이 고치는 문제는 그것이고,
**두 사용자 중 OWNER를 우선한다.**

- OWNER: 소스 연결·첫 적재 재시도·기준 언어 설정을 한 곳에서 한다.
- EDITOR: 지금 Locales에서 얻는 것(언어 현황·사라진 언어의 사유와 복구 안내·번역 화면 이동)을
  **동등 이상으로 유지한다.** 이 기능은 EDITOR의 결핍을 고치는 것이 아니다.

⚠️ **EDITOR가 Settings에 접근할 수 없다는 사실은 이 기능의 근거가 아니다.**
사라진 언어의 사유와 복구 방법은 Locales가 EDITOR에게 **이미 그린다** —
`app/(edit)/projects/[slug]/surfaces/[surfaceSlug]/locales/page.tsx:45`의 게이트가 `translation:write`이고
`:110-116`이 `m.locales.orphaned.reason` + `.restore`를 role 무관하게 렌더한다(그 자리 주석이
"그 둘이 이 화면이 존재하는 이유다"라고 적는다). LNB 항목도 role 게이트 밖이다(`lib/shell/nav.ts:76`).
**EDITOR 쪽에서 관측된 결핍은 없으므로, 재편의 대가가 EDITOR에게 가지 않는 것이 완료 조건이다.**

둘째 문제는 관측된 표시 결함이다. **성공 상태가 원본 커밋 시각을 적재 완료 시각으로 말한다** —
`lib/import/surface-status.ts:14`가 `imported`의 `at`으로 `lastCommitAt`을 주고
`components/settings/sources-card.tsx:51`이 `{text} {relativeTime(status.at, now)}`로 이어 붙여
화면에 `Imported 5분 전`이 선다. §4가 그것을 고친다.

소스는 `TranslationSurface` 하나다. 파일 하나뿐 아니라 `{locale}` 파일 묶음과 다국어 파일 글롭도 포함한다.

## 3. 비목표

각 항목은 이번 라운드에서 **하지 않는다**는 판정이고, 근거를 함께 적는다.

| 비목표 | 근거 |
|---|---|
| 소스 이름·경로·형식 수정 | 경로가 바뀌면 기존 키의 소유 표면이 흔들린다. 별 기능이다 |

| 보관 중 조회 확대 | 기존 `ProjectArchived` 안내만 |
| Translations의 좌우 목록·상세 개편 | 이번 범위 밖 |

| **동시 편집 충돌 해결** | 기존 서버의 마지막 선언 쓰기 정책을 유지한다. 병합 없음 원칙과 같은 방향이다 |
| **적재 완료 시각 조회·저장** | 그 컬럼이 없다. §4는 있는 컬럼만으로 표시를 고친다 |
| **형식별 경로 추론** | §10 제안 2. A0에서 닫는다 |

프로젝트 공통 Settings와 CI의 적재·Publish 파이프라인은 기존 계약을 유지한다.

## 4. 화면과 이동

### 목록

LNB의 Locales를 Sources로 대체한다. 기존 순서와 앱 셸을 유지한다.
PanelHeader: 제목, 소스 수, 짧은 설명, OWNER의 `Add source`.
본문은 활성 소스(`archivedAt = null`) 목록이며 **순서는 slug 오름차순으로 고정**한다
(`loadSurfaceCounts`가 이미 `ORDER BY s.slug ASC`이므로 새 정렬을 만들지 않는다).

| 정보 | 계약 | EDITOR |
|---|---|---|
| 식별명 | 저장된 slug. 읽기 전용 | 보인다 |
| 경로 | `pathTemplate`. 긴 경로를 구별할 수 있게 줄바꿈 | **숨긴다**(§2 PRODUCT §3) |
| 파일 형식 | 기존 지원 어댑터의 사람이 읽는 라벨. 미확정 값은 미확정으로 표시 | **숨긴다** |
| 규모 | 고아 키·고아 언어를 제외한 키 수·언어 수 | 보인다 |
| **진행 요약** | **언어 수 옆에 진행 막대와 완료율, 사라진 언어가 있으면 그 배지** | 보인다 |
| 상태 | §5의 기존 다섯 상태. 색뿐 아니라 낱말로 구분 | 보인다 |
| 상세 | 행 클릭·키보드 활성화로 해당 소스 모달 열기 | 보인다 |
| 번역 이동 | 행의 별도 `Open translations`. 행 클릭과 중복 실행되지 않음 | 보인다 |

⚠️ **진행 요약이 목록 행에 서는 이유는 EDITOR의 정보 후퇴를 갚는 것이다.** 지금 EDITOR는 Locales
본문에서 **클릭 0으로** 언어 표를 보는데, 이 기능 뒤에는 행 클릭 → 모달 → 네 번째 블록이다.
그 한 클릭의 대가를 목록 행이 진행률과 사라진 언어 배지로 먼저 갚는다.

첫 적재 전에는 번역 이동을 비활성화하고 이유를 제공한다. 실패 원인·복구 동작은 상세에 둔다.

행의 상호작용 형: **행 본문이 버튼이고 `Open translations`는 그 형제다** — 중첩하지 않는다.
선례는 `components/onboarding/steps/files.tsx:162-180`(버튼 `flex-1` + 형제 컨트롤)이다.
카드가 `overflow-hidden`이므로 **행 포커스 링은 `ring-inset`**이고(`components/projects/project-list.tsx:235-241`,
`components/settings/sources-card.tsx:48`), 행에 `role`·`tabIndex`를 얹지 않는다
(리포 전수 `role="row"`·`role="button"` 0건 — 행이 `<button>` 자체일 때만 도달한다).

### 상세

목록 위 1024px 모달. 좁은 창에서는 가용 폭에 맞추고 본문만 스크롤한다.
제목은 소스 식별명, 설명은 활성 키·활성 언어 수(**형식은 OWNER에게만**).
**바닥 행동은 `Open translations`와 `Close`다** — 헤더에 보조 행동을 두지 않는다(design §6).

| 블록 | OWNER | EDITOR |
|---|---|---|
| 1. 읽기 전용 식별 정보: 경로·형식·저장소/브랜치 | 있다 | **통째로 없다**(§2) |
| 2. 적재 상태와 필요한 조치 | 있다 | 있다 — 재시도 버튼 대신 소유자에게 요청하는 문구 |
| 3. 기준 언어 | 폼 | 적용값 읽기 전용 |
| 4. 언어 현황 | 있다 | 있다 |

4번 블록: 코드·기준 표시·완료/전체·완료율·검토 필요·사라짐 안내·언어별 `Open`.

언어 `Open`은 **해당 소스 + 해당 언어**로 번역 화면을 좁힌다. 바닥의 `Open translations`는
해당 소스의 기본 번역 화면으로 간다. 사라진 언어의 `Open`은 비활성이다.
⚠️ **두 링크 모두 `ns: ALL_NAMESPACES`를 싣는다** — design §2에 근거가 있다.

모달을 닫으면 목록 위치와 진입 행의 포커스를 복구한다. 진입 행이 없어졌으면 헤더로 포커스를 복구한다.
착지점은 `id` + `tabIndex={-1}`을 **쌍으로** 든다 — design §6에 근거가 있다.

**사용자 확정: 상세 모달의 URL은 없다.** `/projects/:slug/sources`에서 선택한 소스를 화면 상태로 관리한다.
모달 열기·닫기는 주소와 브라우저 이력을 바꾸지 않는다. 전체 새로고침·페이지 재진입 시 목록으로 돌아온다.
⚠️ **그 대가는 공유 불가와 딥링크 불가다** — 특정 소스의 상세를 링크로 건네줄 수 없고, 브라우저 Back으로
모달이 닫히지 않는다. PRODUCT.md:639가 같은 판정을 이미 세웠다(⚠️ 모달도 라우트가 아니다).
기존 소스별 Locales 링크도 Sources 목록으로 연결한다. 추가 모달의 OAuth 복귀용 URL은 별도 기존 흐름으로 유지한다.

행을 누른 뒤 상세가 도착하기까지 **행은 눌린 상태를 유지하고 다시 누를 수 없다** — 모달 로딩 골격은 design §6.

### 빈 상태·접근 실패

- **소스 0**: OWNER는 추가 버튼과 안내, EDITOR는 소유자가 추가해야 한다는 안내. 목록 껍데기는 유지한다.
- **소스 0에서 EDITOR의 PanelHeader**: `Add source` 자리를 비운다(버튼을 꺼서 그리지 않는다).
  소스가 하나 이상일 때도 같다 — EDITOR의 헤더에는 그 버튼이 없다.
- 조회 실패를 소스 0·언어 0으로 바꾸지 않는다. 기존 오류 경계로 처리한다.
- 비회원: 기존 프로젝트 인가 오류. 다른 프로젝트의 소스 존재 여부를 알려주지 않는다.
- 보관: 기존 `ProjectArchived` 안내만. 목록·모달 조회를 진행하지 않는다.
  OWNER만 Settings 복원 링크를 받고 EDITOR는 소유자에게 요청하는 안내를 받는다.

⚠️ **꺼진 컨트롤에는 반드시 사유가 붙고, 그 사유가 영구일 수 있는지 함께 적는다**(DESIGN §6.65).
이 화면에서 컨트롤이 0개가 되는 갈래는 셋이다 — 첫 적재 전, 활성 언어 없음, 설치 연결 없음.
**설치 연결 없음은 영구일 수 있다**(App 제거·재설치는 세 환경의 모든 프로젝트를 동시에 무효로 만든다).
그 갈래의 출구는 Settings의 [Reconnect]이고, **EDITOR에게는 그 목적지를 가리키지 않는다** —
`/projects/:slug/settings`는 EDITOR에게 `/projects?e=forbidden`으로 redirect되는 화면이다
(`lib/auth/session.ts:58`, `app/(edit)/projects/[slug]/settings/page.tsx:32`).
**누르라고 말한 이름의 컨트롤은 같은 화면에 있어야 한다**(POSTMORTEM 2026-09-14, `docs/POSTMORTEM.md:1607`).

⚠️ **첫 적재가 영구 실패하는 소스의 출구는 이번 라운드에 없다.** 경로·이름 수정도 삭제·보관도 §3 비목표다.
경로 오타로 만든 소스는 양쪽 목록에 `First import failed`로 남는다 — **그 출구는 다음 라운드의 소스 보관이다.**

## 5. 적재 상태와 시각

`planSurfaceImportStatus`의 enum과 우선순위를 재사용한다. 임의 상태나 타임아웃 기준을 추가하지 않는다.

| 기존 state | 목록 | 상세 | 최초 적재 행동 |
|---|---|---|---|
| `not-imported` | Not imported yet | 최초 적재 필요, 추가가 CI 연결을 보장하지 않는다는 안내 | OWNER만 표시 |
| `importing` | Importing + 시작 경과 시간 | 진행 중, 다시 요청하지 않음 | 없음 |
| `failed-first` | First import failed | 실제 실패 코드의 원인·다음 행동 | OWNER만 표시 |
| `imported` | Imported | 현재 적재된 데이터와 원본 커밋 정보 | 없음 |
| `failed-after` | Last import failed | 실패 원인·시각, 마지막으로 읽은 커밋 정보, CI 점검 안내 | 없음 |

재시도 실행 가능 조건은 상태의 `canRetry`뿐 아니라 연결·권한도 포함한다:
OWNER, 비보관, `canRetry`, `planSurfaceReadiness(...) === "awaiting_first_sync"`, 요청 중 아님.
설치 연결이 없으면 OWNER에게 비활성 이유와 Settings 안내를 제공한다.
EDITOR에게 재시도 버튼을 그리지 않고 소유자에게 조치를 요청하는 문구를 보여 준다.

**시각 의미 정정**: `lastCommitAt`은 `payload.commitAt` / `snapshot.headCommittedAt`에서 온 **원본 커밋 시각**이다.
적재 완료 시각이 아니다. 성공 상태에 `Imported — 5 minutes ago`나 `Last successful import — 날짜`로 쓰지 않는다.
성공은 `Imported`, 보조 정보는 `Source commit — 날짜`와 짧은 SHA로 표시한다.
실패 이후에는 `Last imported commit`으로 마지막으로 읽은 커밋을 식별한다.
시작은 `lastImportStartedAt`, 실패는 `lastImportFailedAt`을 쓴다.

**시각 표기형**: 절대 시각은 `<time dateTime>` + `aria-label="2026-09-20 09:42 UTC"`로 쓴다(DESIGN §6.68).
**상대 표기는 `importing`의 경과 시간 하나뿐이다** — 나머지는 전부 절대다.
한 블록에 상대와 절대가 함께 서지 않는다.

null이면 시각을 생략하고 추정하지 않는다. ⚠️ **`lastImportFailedAt`에는 backfill이 없다**
(`prisma/schema.prisma:129-136` — POSTMORTEM 2026-09-13, `docs/POSTMORTEM.md:1253`).
그래서 **낡은 실패 행의 빈 시각은 버그가 아니다** — 이 사실을 문구로 드러내지 않고 시각만 생략한다.

`partial-import`처럼 데이터가 적재된 뒤 경고가 남는 실패 코드는 기존 판정/원인 문구를 그대로 쓴다.
성공 SHA가 있다는 이유로 경고를 숨기거나 최초 실패로 바꾸지 않는다.
이 판정은 **적재 상태 블록의 계약**이고, §8의 추가 결과 영역 문구와는 다른 자리다.

## 6. 기준 언어와 언어 현황

### 기준 언어

현재 값은 `baseLocale`, 저장된 요청은 `declaredBaseLocale`. 필드 초기값은
`baseLocaleFieldValue`로 정하고 대기 여부는 `basePending`을 사용한다.
쓰기 인가는 `project:settings`이고, 그리기 판정도 **같은 술어**를 쓴다 — design §5에 근거가 있다.

| 상태 | 표시·동작 |
|---|---|
| 변경 없음 | 저장된 요청값(없으면 적용값), Save 비활성 |
| 수정 중 | 활성 언어만 선택, 저장 전에는 서버값/언어 표를 바꾸지 않음 |
| 저장 중 | 선택·Save·모든 모달 이탈 행동 잠금 |
| 저장 성공·적용 대기 | 필드는 저장된 요청값, 적용값을 별도로 표시. `Waiting to apply` |
| 저장 거부·통신 실패 | 입력 유지, 필드 근처 오류, 재시도 가능. 실패를 저장 완료로 취급하지 않음. **거부 뒤 포커스는 Save로 돌아온다** |
| EDITOR | 적용값 읽기 전용. 대기 중이면 적용값·요청값을 혼동하지 않게 함께 표시 |
| 첫 적재 전·활성 언어 없음 | 수정 불가 이유, 비활성 컨트롤. 가짜 기본 언어를 만들지 않음 |

거부 문구는 넷을 구분한다: `unknown-locale` · `orphaned-locale` · **인가 실패**(권한 회수·세션 만료) ·
**통신 실패**. 앞 둘은 입력이 잘못된 것이고 뒤 둘은 다시 시도할 수 있는 것이라 같은 문구를 쓰지 않는다.

저장은 기존 `updateBaseLocale`만 호출한다. 선언만 바꾸며 현재 기준 언어·키·번역·`Locale.isBase`를 직접 바꾸지 않는다.
대기 중에 현재 적용값을 다시 선택하고 저장하면 기존 계약대로 선언을 취소한다. 별도 취소 API는 없다.
Save 활성·미저장 판정은 **적용값이 아닌 저장된 필드 기준값**과 비교한다.

OWNER의 적용 대기 안내는 선택한 소스에 해당하는 워크플로 항목을 수정하라고 설명한다.
복사할 코드는 기존 `baseLocaleLine(requested)`의 한 줄만 사용한다.
시안의 `- source: web`은 실제 워크플로 문법이 아니므로 복사 대상으로 쓰지 않는다.
전체 YAML은 Settings에 둔다. 워크플로가 이미 어떤 값을 보내는지, 대기 중 키가 고정되는지 단정하지 않는다.

⚠️ **비활성 `Select`는 세 이벤트를 다 막는다** — `onPointerDown`·`onClick`·`onKeyDown`.
포인터만 막으면 클릭이 도리어 열어 준다(POSTMORTEM 2026-09-19, `docs/POSTMORTEM.md:2227`).
꺼진 형은 `aria-disabled`이고 `disabled`가 아니며, `loading`과 겸용하지 않는다(DESIGN §6.65).

### 언어 현황

`localeProgress`의 결과를 재사용한다. 완료·검토 필요·미번역은 서로 겹치지 않는다.

**막대는 기존 `components/projects/locale-meter.tsx`를 값 변경 없이 공유한다** —
**두 구간 + 트랙**이다(완료 `bg-foreground/85` · 검토 필요 `bg-amber-500` · **미번역은 트랙 자신**
`bg-foreground/[0.08]`). ⚠️ **미번역에 색을 주지 않는다**(DESIGN §6.2 — 색을 주면 셋 중 가장 흔한 것이
가장 시끄러워진다). 막대는 `aria-hidden`이고, **같은 사실을 옆의 글자가 말한다**.

**퍼센트 열은 `done`만 쓴다.** `210 + 12 + 26 = 248`일 때 완료율은 `floor(210 / 248 × 100) = 84%`다.
⚠️ **막대의 채워진 길이는 `(210 + 12) / 248 ≈ 89.5%`이고 퍼센트 열은 `84%`다 — 둘은 다른 술어다.**
DESIGN §6.63이 등재한 라벨 규칙은 `(done + review)`이지만, **이 표는 `완료/전체`와 `검토 필요`를
이미 열에서 글자로 말하므로** 퍼센트를 `(done + review)`로 올리면 `210/248` 옆에 `89.5%`가 서는
말이 안 되는 행이 된다. 그 차이를 `검토 필요` 열이 설명한다.

전체 키 0은 0%다. 활성 키만 분모에 쓰고 고아 키의 번역은 분자에서 제외한다.
⚠️ **`untranslated`와 `percent`는 clamp한다** — design §3에 근거가 있다.
사라진 언어는 표에는 남기되 활성 언어 수에서는 제외한다.

사유는 "마지막 적재에서 이 언어가 발견되지 않았다"와 보존·복구 방법을 표시한다.
한 파일에 여러 언어가 있을 수 있으므로 파일 삭제를 단정하지 않는다.
표의 완료 수를 전체 보관 번역 수로 부르지 않는다(고아 키의 값은 이 집계에 없다).

## 7. 모달 이탈

**사용자 확정(2026-09-22): 미저장 변경을 붙잡는 확인창을 만들지 않는다.**

| 이탈 행동 | 저장 중이 아님 | 저장 중 |
|---|---|---|
| X·Esc·배경·Close·바닥 Open translations·언어 행 Open | 즉시 실행. 미저장 변경은 버려진다 | **비활성·닫히지 않음**(`closeDisabled`) |

`components/ui/modal.tsx:129`의 `onOpenChange`가 이미 `closeDisabled`를 보므로 새 배선이 없다.
미저장 내용이 `Select` 한 열이라 다시 고르는 비용이 낮고, **리포에 이탈 가로채기 선례가 0건이다**
(`beforeunload` 0건 · 라우터 가로채기 0건 · 중첩 Dialog 0건 · `onEscapeKeyDown`·`onInteractOutside` 0건).
확인창을 세우면 레이어 등급·Esc 전파·포커스 트랩 중첩을 리포 최초로 정의해야 하는데 그 대가가 이득보다 크다.

브라우저 Back은 이전 페이지로 가는 기존 동작이며 상세 모달의 Close로 재정의하지 않는다.
탭 닫기·브라우저 강제 종료를 커스텀 확인창으로 막는 기능은 약속하지 않는다.

서버 refresh가 입력 중 draft를 덮지 않는다. 저장 중 새 서버값 수신 후 실패한 경우에도 기준값은
최신 서버값이고 입력은 보존한다. 성공 응답 전후 refresh 순서가 달라도 허위 dirty·허위 저장 완료를 만들지 않는다.

## 8. 소스 추가와 Settings

기존 AddSourcesModal·탐지/수동 확인·기준 언어 선택·`addSurfaces`를 재사용한다.
기존 소스 잠금, 출력 경로 충돌 거부, 요청 전체 예산, 생성+첫 적재의 원자성, GitHub 재연결 왕복을 유지한다.

| 결과 | 화면 |
|---|---|
| `ok: true`, 모든 `failed = 0` | 추가 모달 닫기, 목록 갱신, 소스명별 적재 수 |
| `ok: true`, 일부 `failed > 0` | 추가 성공 + 해당 소스의 적재 경고·읽지 못한 항목 수. 첫 적재 전체 실패로 표시하지 않음 |
| `ok: false` | 추가 모달에 원인, 선택 보존. 이번 요청에서 아무 소스도 추가되지 않음 |
| 응답 불명(연결 종료 등) | 기존 결과 불명 안내. "아무것도 추가되지 않았다"고 단정하지 않음 |

현재 성공 응답은 이미 트랜잭션을 마친 결과다. 닫힌 뒤 새 소스가 가짜 `Importing`을 거치는 연출은 하지 않는다.
성공·경고 안내는 목록 화면의 고정 클라이언트 영역에 보존한다. 소스명·건수는 응답을 보관해 표시하고,
refresh로 상태/행이 바뀌어도 안내가 사라지지 않는다. 자동 토스트로 대체하지 않는다.
사용자 닫기·다음 추가 결과·페이지 이탈/전체 새로고침에서 초기화한다. DB·세션·URL에 결과를 저장하지 않는다.
추가 후 CI 워크플로 반영 안내와 OWNER의 Settings 링크를 제공한다.

Settings에서는 Translation sources 카드와 그 추가 모달 소유권을 제거한다.
General·Repository/branch·CI integration/YAML·Archive는 남긴다(**다섯 카드가 넷이 된다**).
기존 추가 URL·OAuth 복귀의 호환 경로를 보존한다.
