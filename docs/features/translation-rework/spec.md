## 2. 사용자와 관측된 문제

주 사용자는 번역 편집자(비개발자 동료)이고, 개발자는 소스·키 탐색과 Sync를 사용한다. 현재 번역 페이지는 소스/네임스페이스/언어 선택과 키별 로케일 행 표를 렌더하고, 셀 blur가 `saveTranslation`을 호출한다. 찾기와 편집이 같은 표를 공유하고 저장의 명시적인 경계가 없다. `loadKeys`가 목록에 전 로케일 값을 싣고, 기본 네임스페이스 착지를 URL에 고정하여 저장 중 이동을 막고 있다.

이번 변경은 찾는 곳을 **소스 트리 + 키 목록**, 고치는 곳을 **선택 키의 로케일 상세**로 나누고, 키 하나의 변경 로케일을 Save 한 번으로 저장한다.

### 3.2 필터·검색·선택

| 축 | 계약 |
|---|---|
| 완성도 | `All keys`, `Incomplete`, `Missing in {locale}`, `Complete` |
| 상태 | `Any state`, `Not sent`, `Needs review`, `New from GitHub`. `createdAt > lastPulledAt`, lastPulledAt이 null이면 활성 키 전체. Sync 시각이 아님 |
| 범위 | `This namespace`, `This source`, `All sources`. 검색어가 없어도 적용 |
| 상세 언어 | `All languages`, `Missing only`, 언어 하나 + base. 목록 집계에는 영향 없음 |
| 검색 | 키 이름·원문·활성 로케일의 저장된 번역값을 대소문자 무시 부분 일치로 찾는다. 설명은 검색 대상에서 제외한다 |
| 정렬 | `Incomplete first`: 전 활성 언어에서 결측 또는 검토필요가 있는 키를 앞으로 **안정 분할**한다. 각 그룹의 기존 순서 유지, 결측 수 내림차순 아님. 3차 시안에 맞춰 기존 제안을 폐기 |

완성도·상태·범위·검색은 AND다. 각 소스의 활성 로케일을 분모로 삼는다. `Missing in ja`에서 ja가 없는 소스는 결과에서 제외한다(3차 시안 확정). 그 소스의 모든 키를 미번역으로 만들지 않는다.

**All sources에서도 상태 축을 활성화한다**(3차 시안). 소스별 활성 셀에서 판정한 뒤 프로젝트 안에서 합친다. 이전 state 비활성/기억 정책은 폐기했다. 새로 제시된 정책은 `Missing in ja`에서 ja가 없는 단일 소스로 좁히면 Incomplete를 적용하고, 범위를 넓히면 ja를 복원하는 것이다. 요청한 completion/missingLocale는 URL에 남기고 실제 적용값만 계산한다. Clear filters나 다른 완성도 선택은 기억값도 지운다. 뒤로/앞으로·새로고침·공유 URL은 같은 요청값에서 같은 결과를 낸다.

`Clear filters`는 세 축만 기본값으로 돌린다. 검색어·트리 선택·상세 언어·폭은 유지한다. 선택 키는 새 범위/필터에도 남을 때만 유지하고, 빠지면 URL의 키와 상세를 함께 비운다. 검색 X는 검색어만 지운다. 최초 진입과 Clear filters의 기본 범위는 `This source`로 확정했으며, 트리의 네임스페이스 클릭은 `This namespace`를 함께 설정한다.

트리 전환은 새 목록의 첫 키를 연다. 필터/검색 변경은 선택 키가 남으면 유지하고 빠지면 상세를 비운다. 3차 시안은 초기화에도 이 규칙을 적용한다. 저장/재검증은 선택을 유지하며 같은 필터 세대에 남긴 Saved 행도 다시 선택할 수 있다. 트리 전환은 미저장 guard 통과 뒤 첫 키를 열고, 필터/검색/초기화는 범위 밖 선택을 비우되 자동 선택하지 않는다. 오래된 키 링크는 임의의 다른 키를 자동 편집 대상으로 삼지 않는다.

### 3.3 상태 표

키 집계는 **저장된 값**으로만 계산한다. 활성 키 × 그 소스의 활성 로케일만 분모에 들어간다. `needsReview`는 결측에 넣지 않는다(3차 시안 확정). 따라서 Complete와 Needs review는 동시에 참일 수 있다.

| 대상/조건 | 서버·클라이언트 근거 | 표현/위치 |
|---|---|---|
| 미완 키 | null/행 부재/빈 문자열인 활성 셀 수 > 0 | `{n} missing`, 목록의 amber |
| 완료 키 | 위 수 = 0 | `Complete`, 목록의 보조색; 승인 완료라는 뜻 아님 |
| 값 있음 | 저장값이 null/빈 문자열 아님 | 입력의 실제 값, 기본 글자색 |
| Missing | 저장값이 null/빈 문자열 | 로케일 행 `Missing`, amber. 점선/원문 도움말은 저장값 대신 **현재 draft가 빈 문자열인가**로 판정하므로 저장 집계와 독립 |
| Not saved | draft 원문과 로컬 저장 기준 문자열이 다름 | 로케일 행 amber, 푸터 변경 로케일 수 |
| Not sent | `pendingWhere`와 같은 활성 셀의 pending boolean | 행/목록의 중립 배지; 값/시각 비교로 만들지 않음 |
| Needs review | 저장값 존재 + needsReview | 로케일 행 amber. Not sent와 공존 가능 |
| base | 실제 소스의 base 로케일 | `Source` 보조 라벨. 편집 잠금 아님 |
| 사라진 키/언어 | orphaned 또는 소스 보관 | 일반 목록·집계에서 제외, 직접 링크는 부재/비활성 안내 |

3차 시안은 입력 상태(Not saved 또는 Missing)·검토·전달의 세 슬롯을 함께 표시한다. Not saved와 Not sent는 공존한다. 점선은 **현재 입력이 비어 있음**을 뜻하고, 도움말은 입력과 형제 요소로 선택/복사할 수 있다. 포커스는 blue ring이며 검은 테두리를 추가하지 않는다. 접근 이름은 기존 키·언어 조합을 유지하고 원문을 aria-describedby로 연결한다.

### 3.4 Save

- Save는 선택 키의 **변경된 로케일만 한 트랜잭션**으로 저장한다. 유효하지 않은 로케일 하나라도 있으면 전부 거부한다. DB/사건 기록 실패는 전체 롤백한다.
- Enter는 줄바꿈이다. blur/Tab은 저장하지 않는다. `Ctrl/Cmd+Enter`는 키 단위 저장, Escape는 현재 입력만 취소한다(3차 시안). IME 조합은 단축키로 소비하지 않는다.
- 전송 중 Save는 중복 요청을 막고 라벨을 유지한 채 스피너를 보인다. 입력은 계속 받는다. 성공 응답은 **전송한 draft**에만 적용하며 그 뒤 입력한 값은 Not saved로 남긴다.
- 저장 성공 응답을 적용한 뒤 미저장 변경이 없을 때만 sessionStorage의 복구 사본을 제거한다. 변경이 남으면 최신 draft와 갱신된 저장 기준을 다시 기록하여, 같은 사용자로 재인증한 뒤에도 저장 중 추가한 입력을 복구한다.
- 변경된 셀만 새 pending 토큰·저자·시각·`translation.saved` 사건을 쓴다. no-op은 셋을 모두 쓰지 않는다. 동일값 저장만으로 needsReview를 해제하는 새 승인 동작은 만들지 않는다.
- 미저장 비교는 원문 문자열 비교다. 서버 저장은 기존 `planSave`대로 공백만 있는 입력을 빈 문자열로 정규화한다. 앞뒤 공백이 있는 비빈 문자열은 보존한다. 성공 후 서버가 돌려준 값으로 기준을 교체한다.
- 성공 토스트 대신 푸터와 단일 live region이 결과를 알린다. 실패는 푸터 바로 위 Alert, draft 유지, Try again. 응답 유실은 ‘저장 여부 확인 불가’로 구분하며 ‘전혀 저장되지 않음’으로 단정하지 않는다.
- 저장 직후 목록의 기존 순서/행을 유지한다. 조건에서 벗어난 저장 행은 취소선 + Saved로 남기고 수만 최신 저장값으로 갱신하고 목록 머리에 `+{n} saved`로 남은 표시 행을 구분한다. 다른 키 클릭은 이 보존을 끝내지 않는다. 필터/검색/범위/정렬/트리 변경으로 목록 세대가 바뀌거나 새로고침·재진입할 때 보존을 끝내고 다시 계산한다.

### 3.5 미저장 전환·Publish·Sync

키·네임스페이스·소스·필터·앱 내 이동은 공통 440 Dialog를 사용한다. 확인 전 URL이나 선택을 바꾸지 않는다. 키와 언어 목록을 본문에 표시하고 취소에 기본 포커스를 둔다. 여러 키 draft를 축적하지 않으며, 건수는 현재 키의 변경 로케일 수다. 새로고침/탭 닫기는 native beforeunload다. 뒤로/앞으로도 검증 대상이다.

Publish는 프로젝트 전체의 저장된 편집을 미리 보고 실행한다. 미저장 확인의 `Keep editing`은 입력으로 돌아가고, `Preview saved changes`는 기존 Publish 미리보기를 연다. 실제 전송은 미리보기의 실행 버튼에서 한다. 진행·성공·실패·닫기 뒤에도 현재 키 draft와 Not saved는 유지한다. 자동 저장·자동 폐기는 없다. Sync는 OWNER만 실행하며 기존 미전달 폐기 지문 확인을 재사용한다. 로컬 draft 확인과 서버 미전달 폐기 확인은 별개다.

세션 만료 시 draft를 화면에 남기고 Save를 차단한다. **선택 키 URL만으로 입력은 복구되지 않는다.** 3차 시안은 한 키 draft를 이 탭의 사용자별 sessionStorage에 보존한다. 같은 사용자로 재인증하면 인가 뒤 복구하고, 다른 사용자면 복구하지 않는다. storage 사용 불가에는 복사 후 이동 안내를 표시한다(Q6 디자인 결정 완료). 보관된 프로젝트는 현재 ProjectArchived 화면을 유지하며, 번역 전체를 읽기 전용으로 새로 개방하지 않는다.

### 3.6 Revert to last sent — 이번 범위 포함

마지막으로 서버가 전달을 확인한 **DB 유래 값의 스냅샷**으로 선택 키의 pending 셀을 한 번에 복원한다. 현재 GitHub 값을 읽어 승자를 고르지 않는다. PR 머지/배포 완료를 뜻하지 않는다. `no-changes`도 전달 확인이므로 문구가 ‘PR로 실제 전송된 값’만 뜻하지 않도록 설명을 붙인다.

- 대상은 선택 키의 활성 pending 로케일 전부. pending이 없는 언어는 건드리지 않는다. 상세 언어 필터로 숨긴 pending 언어도 포함하므로 Dialog가 전체 언어 목록과 건수를 보여준다.
- 복원 기준이 없는 셀이 하나라도 있으면 전체 복원 불가. 기존 DB 값으로 과거 전달값을 추정하거나 일부 언어만 조용히 복원하지 않는다.
- 미저장 draft, Save/Publish/Sync 실행 중에는 복원을 실행하지 않는다. Dialog 이후 대상 토큰·스냅샷·설정이 바뀌면 재확인한다. 이는 파괴적 명령 승인 경계이며 일반 저장의 충돌 UI가 아니다.
- **검수 확정: Publish의 외부 쓰기 전 기존 복원 기준을 무효화한다.** 그 뒤 실패하거나 전달 결과가 불확실하면 다음 안전한 전달 확인까지 Revert를 차단하고 사유를 표시한다. GitHub에 실제 변경이 없었더라도 차단될 수 있는 보수적 정책이다. 실행이 FAILED로 닫히거나 시간이 지났다는 이유로 옛 기준을 되살리지 않는다. 늦은 외부 쓰기의 종료가 확인되지 않은 동안에는 새 기준도 복원에 사용하지 않는다. **종료 확인의 근거는 플랫폼이 강제하는 함수 실행 상한(`maxDuration`)이다** — 교체·실패 실행의 `startedAt + STALE_AFTER_SECONDS`가 지나고 그 뒤 새 전달 확인이 성공해야 열린다(사용자 결정 2026-09-23, design §10.4). 벽시계 추정만으로 여는 것은 여전히 금지다.
- 복원 성공 시 해당 pending을 해제하고 값 변경/폐기를 사건으로 남긴다. 현재 needsReview를 자동 해제하지 않는다. 키·번역을 삭제하지 않는다.
- 권한은 **OWNER 전용**. EDITOR에게는 비활성 버튼과 권한 사유를 표시한다.
- 최초 도입·최초 전달 전에는 복원 기준이 없다. 비활성 Revert와 사유를 보이는 상태가 필요하다. Publish 성공/동등 확인 이후부터 기준이 생긴다. Sync로 리포를 재적재하면 해당 소스의 옛 기준을 무효화하는 안이다.

복원 실패는 서버 거부/롤백 확인과 결과 미확인을 구분한다. 전자만 `No changes were made.`를 표시한다. 후자는 `We couldn't confirm the revert.`와 `Check current values`를 표시하고 재조회 전 재실행을 차단한다. 남은 pending이 있으면 새 확인창을 연다. 성공 후 버튼이 사라지면 푸터 결과 영역(`tabindex=-1`, live region)으로 포커스를 옮긴다.

상세 기본값은 `All languages`이고 `N translated` 접기는 이번 범위에서 제외한다. Copy link는 선택 키 제목 오른쪽 28px 버튼이며 성공은 `Copied` 2초, 실패는 선택 가능한 읽기 전용 URL을 표시한다.

## 4. 검증 가능한 완료 조건

1. 세 열에서 키 한 개를 선택하면 그 소스의 모든 활성 언어가 base 우선으로 표시된다. 목록 응답에는 전 키의 모든 번역값이 실리지 않는다.
2. 활성/보관 소스, orphaned 키/언어, 부재/빈값/검토필요를 섞은 fixture에서 제목·트리·키 결측·Publish 집계가 각 단위와 일치한다.
3. 여러 언어를 편집 후 blur해도 DB는 그대로이고 Save 한 번으로 함께 커밋된다. 한 셀 또는 사건 기록 실패 시 전부 롤백한다.
4. 저장 중 추가 입력·늦은 응답·재검증·통신 유실에도 draft와 선택을 잃지 않는다. saved 행의 보존과 재필터 시점이 일관된다.
5. 다섯 전환 경로와 뒤로/앞으로에서 취소는 원래 화면/draft를 보존하고 확인은 의도한 목적지로 한 번만 이동한다.
6. Revert 기준은 실제 전달 확인 때만 전진한다. Publish 중 재편집은 pending을 유지한다. 미확인/오래된 기준과 승인 후 변경은 복원하지 않는다. GitHub 쓰기 성공 뒤 DB 완료 기록이 실패해도 옛 기준으로 pending을 해제할 수 없다. 늦은 외부 실행 종료와 새 전달 확인 전에는 복원을 열지 않는다.
7. 다른 프로젝트/소스 keyId·locale 조합, 비멤버·보관·권한 상실 요청은 목록/상세/저장/복원에서 모두 거부된다. 토큰 원문·원문 이메일이 응답에 없다.
8. Copy link·Logs·Home·Sources·옛 URL이 의도한 키/범위로 착지한다. 존재하지 않는 키와 조회 장애는 다른 상태다.
9. 1280/1440/1920과 LNB 최소/기본/최대에서 확정된 폭 계약을 실측한다. 키보드·IME·긴 문장·수십 언어·Dialog 포커스를 실제 브라우저로 검증한다.
10. 타입·단위/DOM·격리 PostgreSQL·어댑터 결정성 회귀를 통과한다. 이번 문서 작업에서 테스트 통과를 구현 완료로 보고하지 않는다.
