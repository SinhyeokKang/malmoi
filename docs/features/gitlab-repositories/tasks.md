# GitLab repositories — 재개 후 태스크

상태: **전부 미착수·구현 보류**. 문서 기록·검수는 아래 실행을 승인하지 않는다. 각 묶음은 향후 구현 커밋 경계이며 현재 구현 코드를 커밋하지 않는다.

## 0. 재개 결정·설계 확정 — 문서 경계

- [ ] 사용자가 구현 우선순위를 다시 결정하고 실제 검증 리포/도입 팀을 정한다. GitLab.com 한정 여부와 지원 플랜을 확정한다.
  - 검증: spec §6의 결정 표에 사용자 결정과 근거가 남는다.
- [ ] 인증 방식·쓰기 신원·권한 증명·만료/회전·연결 해제의 영향을 확정한다. 개인 OAuth 쓰기를 허용하려면 기존 원칙과의 차이를 먼저 결정한다.
  - 검증: 로그인/연결/쓰기 자격증명 표와 신규 env 목록, 철회·퇴사 사례가 design에 확정된다.
- [ ] GitLab 실제 테스트 리포에서 API의 base 재생성·MR 재사용·no-changes 정리·권한 부족·응답 유실을 검증하고 공통 인터페이스를 확정한다.
  - 검증: 원격 parent SHA·파일 바이트·MR 개수·실패 후 상태의 증거가 남고 미지원 계약이 없다.
- [ ] UI 변경 범위를 확인한다. 신규 표면 또는 큰 변경이면 design-brief를 먼저 작성하고, **UI 구현 작업의 첫 태스크로 로컬 핸드오프 시안 수령**을 배치한다.
  - 검증: 필요한 브리프·시안 경로·대상 화면이 확정되며 시안 없는 신규 UI 구현이 시작되지 않는다.

## 1. 공통 판정·계약 — 커밋 A

- [ ] identity·연결/readiness·설정 비교·원격 상태 정규화·URL·CI 입력의 순수 함수 테스트를 먼저 작성한다.
  - 검증: 필요한 red를 관측한 뒤 구현하고 `pnpm test` green. 다른 제공자의 같은 id·하위 그룹·조회 실패·첫 적재 미완 포함.
- [ ] 실제 GitHub 소비자를 새 경계로 함께 이관하고 GitHub 전용 요청 조립은 제공자 구현에 남긴다.
  - 검증: 기존 호출 생략·고정 base·단일 PR·전달 확인 계약 테스트 및 `pnpm typecheck` 통과.

## 2. additive 스키마·연결 저장 — 커밋 B

- [ ] 확정 설계에 따라 제공자/주소/자격증명 migration을 작성한다. 번역 테이블을 복제하거나 기존 필드를 즉시 제거하지 않는다.
  - 검증: `/db` 절차로 SQL 검토, 기존 GitHub 데이터 보존과 혼합 제공자 identity를 격리 PG에서 확인.
- [ ] 연결 저장·재연결·쓰기 권한 검증·승인 지문·readiness에 provider identity를 연결한다.
  - 검증: 연결 변경 중 적재/Publish, 제거된 멤버, 보관 프로젝트, 다른 리포 id에 대한 PG 통합 테스트 통과.
- [ ] 호출자의 리포 권한 검사를 경로별로 보존한다. 수동 Sync·연결된 프로젝트 브랜치 조회는 읽기 권한, 생성·재연결·소스 추가·push 토큰 회전은 쓰기 권한을 요구한다.
  - 검증: 두 제공자 모두 읽기 전용 OWNER의 Sync·연결된 프로젝트 브랜치 조회는 성공하고, 쓰기 권한이 필요한 네 경로는 거부된다. 서버 쓰기 자격증명의 존재만으로 호출자의 권한을 인정하지 않는다.

## 3. GitLab I/O·Sync·Publish — 커밋 C

- [ ] 완전한 tree/blob 스냅샷·크기 예산·페이지네이션·불변 id 검증을 구현한다.
  - 검증: 중간 페이지 실패·잘린 목록·크기 초과·이름 재사용을 성공/빈 목록으로 처리하지 않는다.
- [ ] commit actions 조립 테스트를 먼저 작성한 뒤 GitLab 쓰기와 MR 생명주기를 연결한다.
  - 검증: 고정 base·파일 mode·중복 MR 방지·target 변경·no-changes·결과 미확인 계약 테스트 통과. 동명 fork MR과 자체 MR이 공존하거나 fork MR만 있는 경우를 넣어 source/target project id가 다른 MR을 재사용·닫기·자동 적재 보호 대상으로 선택하지 않는지 확인한다.
- [ ] 첫 적재·소스 관리·수동 Sync·야간·자동 적재 보호를 기존 코어에 연결한다.
  - 검증: `pnpm test` 및 관련 격리 PG 스위트 통과. 열린 MR/조회 실패 보류, Publish/no-changes 경합, 미전달 토큰 보존 포함.

## 4. CI·MCP — 커밋 D

- [ ] 기존 페이로드 생산자를 사용하는 GitLab CI 경로와 설정 안내를 만든다. base/skip marker/failure 보고를 연결한다.
  - 검증: 실제 CI에서 정상 적재·보류·실패·오래된 커밋·재실행·머지 방식별 루프 방지를 확인.
- [ ] MCP 저장소 목록·프로젝트 생성·연결 및 Sync/Publish를 동일 코어에 배선한다.
  - 검증: 제공자 지정/기존 클라이언트 호환·사용자/프로젝트 인가·credential 비노출·실패 응답 테스트 통과.

## 5. UI·번역·가이드 — 커밋 E

- [ ] 기존 프리미티브로 연결/설정/상태/PR·MR 표시를 구현한다. 0단계에서 시안이 필요한 대상으로 확정된 경우에는 로컬 핸드오프 시안을 먼저 수령한다.
  - 검증: DOM 테스트와 브라우저에서 권한별 연결·만료·철회·일시 장애·재시도·라이트/다크를 확인.
- [ ] 시안 대상 신규 UI는 `/design-sync`로 대조한다. 기존 화면의 소규모 수정은 해당 DOM·런타임 검증을 한다.
  - 검증: 시안 대상은 대조 기록, 그 외는 화면별 결과 도달·링크 목적지 증거가 남는다.
- [ ] en/ko/es 사전·가이드와 PRODUCT/ARCHITECTURE/DIRECTORY/OPERATIONS 및 필요한 `.env.example`을 실제 구현에 맞춘다.
  - 검증: 가이드·사전 테스트 통과, 지원 플랜·인증 만료·지원 배포형 설명과 구현이 일치.
- [ ] 초대 이메일의 GitHub 고정 소개 문구를 제공자 중립 문구로 바꾼다.
  - 검증: 메일 템플릿 테스트에서 GitHub·GitLab 프로젝트의 초대 모두 실제 전달처와 모순되는 안내가 없는지 확인한다.
- [ ] 인증 결정에 따른 GitLab 전송처·자격증명·수집 정보를 `/privacy` 영문·국문 본문과 수집 목록에 반영하고 필요한 개정 이력·시행일을 갱신한다.
  - 검증: `lib/privacy/__tests__/`의 수집 목록·방침 게이트 테스트 통과 및 새 전송처·수집 목적·보존 설명과 구현의 수동 대조 완료. GitLab 활성화 전에 반영한다.

## 6. 수락·배포 게이트 — 검증 경계

- [ ] GitHub와 GitLab 테스트 리포에서 적재 → 편집 → Publish → PR/MR 머지 → 재적재를 실행한다.
  - 검증: 값·바이트·orphan 복원·중복 PR/MR 없음·Last sent/Logs·실패 후 편집 보존 증거를 기록.
- [ ] 새 PG 테스트를 추가하는 배치에서 해당 `vitest.*.config.ts`의 수집 경로와 `scripts/gate-plan.ts`의 실제 구현 경로 트리거를 함께 확인·등록한다.
  - 검증: 새 PG 테스트 파일이 해당 스위트에서 실제 실행되며, 새 제공자·연결 구현 경로만 변경해도 필요한 PG 스위트가 선택되는지 gate-plan 테스트로 확인한다.
- [ ] 전체 `pnpm test`·`pnpm typecheck`와 관련 PG 스위트를 실행하고 두 제공자의 외부 실패를 주입한다.
  - 검증: 성공/실패 범위를 구분해 기록하고 spec 완료 조건 1–9에 증거를 연결한다.
- [ ] additive migration → reader/writer 배포 → GitLab 생성 활성화 순서와 롤백 절차를 확인한다.
  - 검증: 구버전이 GitLab 프로젝트를 처리하는 창이 없고, 기존 GitHub 프로젝트가 정상이다. dev는 `/push`, 프로덕션은 별도 사용자 `/merge` 요청으로만 진행한다.

다음 단계는 **구현 시점과 spec §6의 결정 재확인**이다. 지금 `/tdd interface`로 진행하지 않는다.
