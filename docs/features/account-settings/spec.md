# spec — account-settings

## 의존

**이 기능은 둘을 이어받는다.** 앞의 둘이 능력을 만들고 여기는 그것을 **화면에 세운다.**

| 의존 | 무엇을 받나 | 없으면 |
|---|---|---|
| `file-upload` | `uploadProfileImage` · `deleteProfileImage` Action 둘 | [Image upload]·[Delete]가 눌러서 거절당하는 자리가 된다 |
| `account-connect` | 미연결 수단을 붙이는 왕복 | [Connect]가 **리포가 막은 바로 그 모양**이 된다 — 화면에만 있고 뒤가 없는 버튼 |

⚠️ **버튼만 먼저 세우지 않는다.** 시안이 그린 [Connect]·[Image upload]는 뒤에 경로가 있을 때만
의미가 있고, 없으면 "여기서 못 하는 일"을 더 늘린다 — 이 화면을 고치는 근거가 정확히 그것이었다.

## 사용자

**둘 다.** 사용자 축의 유일한 화면이고, 비개발자 동료가 로그인 수단을 확인하는 자리이자 개발자가
GitHub 연결을 끊는 자리다.

## 문제

카드 다섯이 `space-y-6`으로 평평하게 쌓여 있고 축이 안 보인다.

- **같은 화면에 "GitHub"이 세 군데 나온다** — 로그인 수단 / 리포 쓰기 권한 / (세션 확인 상대).
  코드 주석은 *"그 구별이 화면에서 보여야 한다"*고 적어 놓고 그 일을 **카드 설명문 두 줄**에
  맡겼다. 설명문은 읽은 사람에게만 작동한다.
- **되돌릴 수 없는 동작 넷 중 하나에만 확인이 있다.** 수단 해제만 Dialog가 있고, GitHub 연결 해제
  (모든 프로젝트의 발송이 멈춘다) · 전체 로그아웃 · 로그아웃은 즉시 실행이다.
- **프로필이 읽기 전용이다.** 이름은 멤버 목록·초대에서 **남이 나를 알아보는 이름**인데 provider의
  표시 이름이 그 자리에 맞지 않을 수 있다.
- 구역마다 몸통이 다르다 — 수단은 `divide-y` 목록, 연결은 칩 + 버튼, 세션은 `Card` 둘.

## 완료 조건

1. **머리 하나 + 리스트 셋**이다(Profile 카드가 머리로 흡수된다). 1440×900에서 **접히는 것이 없다.**
2. **되돌릴 수 없는 넷 전부에 확인 Dialog가 붙는다.** 확정 라벨이 **결과**를 말한다
   (전체 로그아웃은 `Continue to GitHub` — 그 버튼이 일을 끝내지 않기 때문이다).
3. **이름을 고쳐 저장할 수 있고**, 재로그인이 그 값을 **덮지 않는다**.
4. 사진을 올리고 지울 수 있다.
5. 미연결 수단에 [Connect]가 서고 **눌러서 실제로 붙는다**.
6. `/design-sync`의 실측(computed style + CDP 접근성 트리)이 캔버스와 **전부 일치**한다.
7. `pnpm test` green + `pnpm build` green.
