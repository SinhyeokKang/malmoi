# spec — account-settings

## 의존

**이 기능은 둘을 이어받는다.** 앞의 둘이 능력을 만들고 여기는 그것을 **화면에 세운다.**

| 의존 | 무엇을 받나 | 없으면 |
|---|---|---|
| `file-upload` | `uploadProfileImage` · `deleteProfileImage` Action 둘 | [Image upload]·[Delete]가 눌러서 거절당하는 자리가 된다 |
| `account-connect` | 미연결 수단을 붙이는 왕복 | [Connect]가 **리포가 막은 바로 그 모양**이 된다 — 화면에만 있고 뒤가 없는 버튼 |

⚠️ **버튼만 먼저 세우지 않는다.** 시안이 그린 [Connect]·[Image upload]는 뒤에 경로가 있을 때만
의미가 있고, 없으면 "여기서 못 하는 일"을 더 늘린다 — 이 화면을 고치는 근거가 정확히 그것이었다.

## 사용자

**둘 다.** 사용자 축의 유일한 화면이고, 비개발자 동료가 로그인 수단을 확인하는 자리이자 개발자가
GitHub 연결을 끊는 자리다.

## 문제

카드 다섯이 `space-y-6`으로 평평하게 쌓여 있고 축이 안 보인다.

- **같은 화면에 "GitHub"이 세 군데 나온다** — 로그인 수단 / 리포 쓰기 권한 / (세션 확인 상대).
  코드 주석은 *"그 구별이 화면에서 보여야 한다"*고 적어 놓고 그 일을 **카드 설명문 두 줄**에
  맡겼다. 설명문은 읽은 사람에게만 작동한다.
- **되돌릴 수 없는 동작 넷 중 하나에만 확인이 있다.** 수단 해제만 Dialog가 있고, GitHub 연결 해제
  (모든 프로젝트의 발송이 멈춘다) · 전체 로그아웃 · 로그아웃은 즉시 실행이다.
  - ⚠️ **셋 중 GitHub 연결 해제는 누락이 아니라 판단이었다.** `components/account/login-methods.tsx`의
    주석이 그 근거를 적어 놨다 — *"그쪽은 **다시 누르면 복구되는** GitHub App 연결이고, 로그인 수단
    해제는 되돌리려면 OAuth 왕복 전체가 필요하다."* **그 판단을 뒤집는다**: 복구가 쉬운 것과 결과가
    가벼운 것은 다른 일이고, 이 해제는 **내가 OWNER인 모든 프로젝트의 발송을 멈춘다.** 그 결과를
    화면에서 말하는 것이 `N projects use this connection.` 한 줄이고, 그 줄이 있어야 할 자리가
    확인 Dialog다. ⚠️ **그 주석을 같은 커밋에서 정정한다.**
- **프로필이 읽기 전용이다.** 이름은 멤버 목록·초대에서 **남이 나를 알아보는 이름**인데 provider의
  표시 이름이 그 자리에 맞지 않을 수 있다.
- 구역마다 몸통이 다르다 — 수단은 `divide-y` 목록, 연결은 칩 + 버튼, 세션은 `Card` 둘.

## 완료 조건

1. **머리 하나 + 리스트 셋**이다(Profile 카드가 머리로 흡수된다). 1440×900에서 **가로 스크롤이 0이고,
   리스트 항목의 우측 컨트롤이 줄바꿈되지 않는다**(`flex-shrink:0`이 지켜진다).
2. **되돌릴 수 없는 넷 전부에 확인 Dialog가 붙는다.** 확정 라벨이 **결과**를 말한다
   (전체 로그아웃은 `Continue to GitHub` — 그 버튼이 일을 끝내지 않기 때문이다).
3. **이름을 고쳐 저장할 수 있고**, 재로그인이 그 값을 **덮지 않는다**.
4. 사진을 올리고 지울 수 있고, **거부 셋이 각자 화면에 닿는다** — ① 800 KB 초과는 **제출 전에**
   사유가 보이고 ② `.png`로 이름만 바꾼 SVG는 **서버 사유**로 거절되며 ③ 사진이 없을 때 [Delete]의
   `disabled` 옆에 사유가 선다. (판정과 문구는 `file-upload`가, 이 셋이 서는 자리는 태스크 4b가 든다.)
5. 미연결 수단에 [Connect]가 **시안과 같은 모양으로 선다**(크기·variant·자리). ⚠️ **누르면 붙는
   동작은 `account-connect`의 완료 조건이다** — 여기서 다시 세지 않는다. 이 화면이 책임지는 것은
   그 버튼이 **뒤가 있는 상태에서만 선다**는 것이고, 그 보장이 의존 표다.
6. `/design-sync`의 실측(computed style + CDP 접근성 트리)이 **`design.md` 대조표에 남은 전 항목**과
   일치한다. ⚠️ **"캔버스 전부"가 아니다** — `design.md`가 근거를 적고 뺀 항목(`--text-xs`가 13px인
   자리 등)은 대조 대상이 아니고, 그 표가 범위의 정본이다.
7. `pnpm test` green + `pnpm build` green.

## 비목표

- **계정 삭제** — 이번 범위 밖이다. 들어오면 `Sessions` 아래 네 번째 구역인지 그 안인지 정해야 한다.
- **provider 접근을 잃은 사람의 복구** — `account-connect`의 비목표 그대로다.
- **`loadAccountView`를 넓히는 것** — 프로젝트 설정 화면이 같은 함수를 쓴다. 새 집계는 `/account`
  전용 조회로 얹는다. (이건 비목표라기보다 **구현 제약**이고, 여기 적는 이유는 넓히는 쪽이 더 쉬워
  보이기 때문이다.)
- **`account-connect`·`file-upload`의 문서를 고치는 것** — 경계가 겹치는 자리(⚠️ [Connect] 완료
  조건 · PRODUCT §7.7 IA 아래 ⚠️ 문단이 **두 항목을 함께 든다**)는 이쪽 문서에서만 좁힌다.
  ⚠️ **그 IA 문단은 먼저 출하한 쪽이 통째로 지우면 안 된다** — 자기 절반만 지운다(태스크 11).
