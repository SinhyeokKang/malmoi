# 자격증명·회원 정보 저장 보호

> 상태: feature-review 반영 · 구현 재개 전 | 2026-09-10
> 연결: [기술 설계](./design.md) · [태스크](./tasks.md) · [보안 감사 2](../sec-audit-2/findings.md)

## 1. 사용자와 문제

개발자는 DB 유출 시 GitHub 연결과 로그인까지 탈취되는 피해를 줄여야 한다. 번역 편집자는 재로그인 후 기존 프로젝트·권한·번역을 그대로 사용해야 한다.

현재 `Session.sessionToken`은 브라우저 bearer 원문이며, GitHub App 사용자 access/refresh 토큰과 기존 로그인 Account의 잔존 토큰이 평문이다. sec-audit-2(`dac4c97`, origin/dev 반영)의 safePrismaAdapter는 신규 로그인 OAuth 토큰을 이미 저장하지 않는다. 로그인용 OAuth 토큰은 현재 앱 기능에서 재사용하지 않는다. GitHub App 사용자 토큰은 설치 조회·갱신에 원문이 필요하다. 모두 같은 방식으로 암호화할 이유는 없다.

## 2. 범위와 결정

| 대상 | 저장 정책 | 이유 |
|---|---|---|
| DB 세션 토큰 | SHA-256 해시만 저장 | 일치 조회만 필요 |
| `github-app` access/refresh 토큰 | AES-256-GCM 암호문 | GitHub 호출 시 복호화 필요 |
| 로그인 `github`·`google` access/refresh/ID 토큰 | 저장하지 않고 기존 값 제거 | 신원 확인 후 재사용하지 않음 |
| 회원 이메일·이름·프로필 이미지 URL | AES-256-GCM 암호문 | 인증·표시에 필요한 시점에 서버에서 복호화 |
| 초대 대상 이메일 | AES-256-GCM 암호문 + 프로젝트 범위 HMAC 인덱스 | 가입 전 회원 정보도 같은 수준으로 보호 |
| 회원 이메일 조회 | 별도 키의 HMAC-SHA-256 인덱스 | 원문 없이 정확 일치·유일성 검사 |
| 초대·push 토큰 | 기존 해시 유지 | 이미 원문 불필요 |
| installation 토큰·App 개인키·OAuth client secret | 기존 서버 자격증명 경계 유지 | 이번 Account/Session 저장 변경의 대상 아님 |

**사용자 결정(2026-09-10): 출시 전이므로 기존 로그인은 전환 시 모두 만료시켜도 된다.** 기존 세션을 유지하는 이중 조회나 평문 호환 모드는 만들지 않는다. GitHub 연결은 기존 토큰을 암호화해 유지하는 것으로 설계한다. 계정·멤버십·번역은 삭제하지 않는다.

MVP §7, SAAS §4.2·§4.3과 대조: 기존 인증·연결의 저장 보호이므로 범위 안이다. OAuth 계정 병합·이메일 로그인·새 인증 공급자는 추가하지 않는다. ARCHITECTURE의 기존 평문 수용 결정을 이 기능 구현 시 대체한다.

## 3. 보호 경계

목표는 **DB 읽기 권한 또는 DB 덤프만 유출됐을 때 저장된 자격증명을 바로 재사용하지 못하게 하는 것**이다. DB와 분리한 서버 키가 안전하다는 전제가 있다.

서버 실행권한·암호화 키·브라우저 쿠키 탈취, DB 쓰기를 통한 권한 조작, OAuth 인가 오류는 이 보호로 해결되지 않는다. 기존 백업에 남은 평문도 소급 제거되지 않는다.

sec-audit-2에서 닫은 #31의 만료 세션 검사·조건부 정리·추가 로그인 계정 연결 거부와 #33·40의 GitHub 연결 소유권·직렬화를 보존한다. 암호화 어댑터가 이 방어선을 대체하거나 약화해서는 안 된다. #39는 신규 저장 제거를 유지하고 기존 로그인 토큰 정리만 이번 전환에서 수행한다.

## 4. 완료 조건

- **AC1** 신규 로그인 DB 행에는 세션 원문이 없고, DB 해시를 쿠키로 제시해도 인증되지 않는다. 정상 로그인·시간당 갱신·로그아웃은 유지된다.
- **AC2** 만료 시각과 같은 시각부터 세션 조회는 실패한다. OAuth 콜백도 같은 판정을 거치며, 회수된 세션을 갱신이 되살리지 않는다. DB 장애는 비로그인과 구별된다.
- **AC3** GitHub 연결 생성·교체·재연결·refresh의 모든 쓰기는 암호문만 남긴다. 정상 복호화 후 설치 조회와 토큰 갱신이 동작한다.
- **AC4** 다른 사용자·계정·컬럼으로 암호문을 복사하거나 nonce·tag·ciphertext·key ID를 변조하면 실패한다. 키 누락·손상에서 평문 저장/읽기로 후퇴하지 않는다.
- **AC5** refresh 경쟁과 연결 해제 경쟁에서 이전 요청이 새 연결을 덮거나 삭제된 연결을 복구하지 않는다. 비교 조건은 읽었던 저장 암호문 그대로다.
- **AC6** `github`·`google`의 access/refresh/ID 토큰이 신규 저장되지 않고 기존 값도 NULL이다. 기존 사용자 식별·검증된 이메일 정책은 유지된다.
- **AC7** dev 전환 리허설에서 기존 쿠키는 무효, 새 로그인은 성공, GitHub 연결은 유지된다. 작업 재실행은 새 해시 세션을 삭제하거나 암호문을 이중 암호화하지 않는다.
- **AC8** 키 회전·부분 실패·복구 리허설을 통과한다. 현재 DB에 이전 키 암호문이 0건임을 확인하기 전 키를 제거하지 않는다.
- **AC9** 세션·OAuth/GitHub 토큰과 키는 로그·예외·RSC·세션 JSON·클라이언트 번들에 원문/암호문으로 노출되지 않는다. 브라우저의 HttpOnly 세션 쿠키는 기존 인증 운반 경로다. 초대·push 토큰은 기존 권한 아래 발급 직후 최초 표시 계약을 유지한다. 공개 세션 허용 목록과 AC13의 개인정보 표시 범위를 유지한다.

## 5. 비목표

번역 콘텐츠 암호화, E2EE, 자체 암호 알고리즘, KMS 도입, 무중단 평문 전환, 온라인 일괄 키 회전, 세션 관리 UI, 감사 나머지 항목 일괄 수정은 포함하지 않는다. 세션 24시간·갱신 1시간 정책과 프로젝트 인가 구조도 변경하지 않는다.

## 6. 확정 사항과 구현 시 확인

기존 로그인 만료는 사용자 확인 완료다. 기술 기본안은 Node 내장 암호 모듈, DB 외부 환경변수 키, 이메일 조회 인덱스 추가와 기존 개인정보 컬럼 암호문 전환, 요청을 차단한 전환이다. 추가 제품 결정은 없다.

실제 운영 전에는 이전 배포 URL까지 요청을 차단하고 진행 중 쓰기를 종료할 수 있는지, 키 보관/복구 권한과 백업 보존 기간을 확인한다. 충족하지 못하면 전환을 시작하지 않고 배포 절차를 먼저 보완한다.

## 7. 회원 정보까지 같은 전환에 포함

사용자 결정(2026-09-10): 회원 정보를 다음 기능으로 미루지 않고 함께 보호한다. `User.email/name/image`와 모든 상태의 `ProjectInvitation.email`을 암호화한다. 기존 회원·초대·권한·번역은 보존한다. 로그인·이메일 갱신·초대 발급/재발급/수락·멤버 및 번역자 표시에 연결된 모든 읽기/쓰기를 같은 배송에서 변경한다.

- **AC10** 전환 후 대상 개인정보 컬럼에는 암호문 또는 허용된 NULL만 있다. 기존 만료/수락 초대에도 평문 이메일이 남지 않는다.
- **AC11** 이메일 정규화는 기존 trim+소문자를 유지한다. 신규 로그인·검증된 이메일 갱신·초대 재발급/수락이 암호화 전과 같은 사용자/프로젝트를 식별한다. 신규 가입의 중복 이메일은 거부한다. 기존 회원의 새 검증 이메일이 점유된 경우(동시 갱신 P2002 포함)는 이메일 갱신·병합만 거부하고 기존 userId·이메일로 로그인을 허용한다. Gmail 점·plus 태그를 합치지 않는다.
- **AC12** 동일 이메일의 동시 회원 생성/변경은 DB unique 제약으로 한 사용자만 허용한다. 인덱스 조회 결과는 복호화한 이메일로 재검증하며 다른 이메일이면 인증하지 않는다.
- **AC13** 본인 계정 화면·공개 세션은 기존 허용 필드만, 멤버/초대/번역자 표시는 기존 권한과 서버 마스킹 정책에 따라 반환한다. 암호문·검색 인덱스·키는 클라이언트로 나가지 않는다.
- **AC14** 개인정보 암호화 키와 검색 키의 교체·중단·재개를 각각 리허설한다. 인덱스 재계산 누락·서로 다른 키 세대가 섞인 상태로 서비스를 열지 않는다.

DB에는 내부 userId·멤버십·OAuth providerAccountId·리포 식별자·시각 등 기능에 필요한 메타데이터가 남는다. 이메일 인덱스는 같은 범위 내 동일 값 여부를 드러내고 암호문 길이도 숨기지 않는다. 따라서 이번 변경은 익명화나 모든 개인정보의 비식별화를 보장하지 않는다. 사용자 브라우저에 권한에 맞게 표시되는 개인정보와 서버 실행권한 탈취도 보호 경계 밖이다.

DB 최소권한·공개 접근 차단·로그 원문 제외·백업 접근/보존 제한은 계속 필요하다. 과거 평문 백업은 자동으로 정화되지 않으므로 보존 목록과 삭제/만료 정책을 운영 점검에 포함한다.


## 8. 구현 완료와 운영 전환 완료

구현 완료는 AC의 자동 검증과 격리 PostgreSQL·Auth.js 통합 검증을 통과한 상태다. 운영 전환 완료는
각 환경의 차단·전환·검증·서비스 재개를 수행하고 두 provider 재로그인, GitHub 연결 유지,
기존 회원·초대·권한·번역 보존 증거까지 남긴 상태다. dev 리허설만으로 prod 전환을 완료로 표시하지 않는다.

feature-review(CPO·CDO·CTO·QA)의 보완은 기존 승인 범위 안이다. 원래 로그인 공급자로 다시
로그인하면 같은 사용자와 권한으로 돌아온다. 개인정보 키/DB 장애는 이메일 미검증이나 새 가입
안내로 바꾸지 않으며, 손상된 행을 빈 목록·익명 actor·정상 저장으로 취급하지 않는다.
