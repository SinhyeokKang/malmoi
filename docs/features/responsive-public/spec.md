# responsive-public — 공개·Auth 반응형

상태: 구현 전 설계. 2026-10-07 정적 코드 대조 완료, 브라우저 실측·구현·배포 미실행.
관련 문서: [기술 설계](design.md) · [태스크](tasks.md) · [시각 브리프](design-brief.md) · [앱 설계](../responsive-app/spec.md).

## 사용자와 문제

개발자는 작은 창에서 제품·가이드·로그인을 확인하고, 번역 편집자는 초대 링크·로그인·OAuth 동의를 좁은 화면에서도 완료해야 한다. 같은 역할·상태의 기능은 폭 때문에 없어지지 않는다.

소스에서 확인한 현재 제약은 공개/Auth 셸의 `min-w-shell-min`(1280), Docs 내비264·TOC200, Auth 폼320·OAuth480, Inbox360, 대형 모달 총 거터96이다. 랜딩은 1440×900 캔버스와 한 줄 캡션을 가정한다. 이는 코드 선언값이며 실제 모바일 장애를 브라우저에서 재현한 결과는 아니다.

## 범위 게이트와 확정 사항

PRODUCT §4.2·§4.3에 반응형 웹은 비범위가 아니다. DESIGN의 기존 1280 하한·모바일 미지원 판정은 이번 공개 범위부터 변경한다. ARCHITECTURE §0의 병합 없음·단일 판정·인가 불변식은 보존한다.

브리프에 기록된 사용자 확정 D4~D6을 유지한다: 최소375px, 공개 1차는 기존 5씬 축소+줄바꿈 캡션, 좁은 로그인은 장식 숨김·폼 우선, 가이드 이미지는 en 데스크톱 공유. 앱 완성 후 목업 내부 반응형은 responsive-app A2e 소유다.

지원 검증 뷰포트: 375×812·768×1024·1024×768·1280×800. 각 페이지 유형의 기본 상태는 light/dark×en/ko/es = 24조합이다. P-01~06의 주요 동작·긴 문구도 24조합, 나머지 오류/빈/진행 상태는 최소375·1280 양끝에서 검증한다. System은 OS light/dark를 각각 따라가는지 별도 확인한다. 화면 언어가 es여도 Privacy 본문 en, Changelog 원문·가이드 스크린샷 en인 기존 정책은 그대로다.

측정 판정: 루트 `scrollWidth <= clientWidth`, 제목·입력·닫기·마지막 동작 도달, 헤더 겹침0, 포커스가 숨은 노드에 남는 경우0. 루트 overflow를 감춰 통과시키지 않고 자식 rect의 잘림까지 확인한다. 표/코드 내부 overflow만 예외다. 200% 확대는 유효 CSS 폭375 이상에서 같은 계약을 확인하며 그 미만은 지원 보증 범위 밖이다.

## 분리 배포와 앱 연결

공개 전체가 완료된 뒤 독립 배포할 수 있다. 앱은 그 시점에 기존1280 하한을 유지한다. 공유 Dialog·LargeModal·검색·Inbox 변경은 앱의 기존 지원 폭1280 이상에서도 회귀 검증한다. 공개 기능이 앱 반응형 미완성을 이유로 미완이어서는 안 된다.

공개 단계는 앱 내부 모바일 지원을 표방하지 않는다. 초대/검색/Inbox에서 앱으로 가는 URL과 권한은 유지되며 좁은 앱 착지는 앱 단계까지 기존 제약이 남는다. 이것을 임시 기능 차단이나 새 경고 화면으로 해결하지 않는다.

## 비목표

앱 편집/관리 레이아웃, 앱 완성 후 목업 A18, 새 승인 흐름·권한·서버 API·DB·쿠키·환경변수, 새 UI 라이브러리·토큰 체계, 네이티브 앱·별도 모바일 URL, 가이드 원고 기능 확장·언어별/모바일 스크린샷은 제외한다. 이 문서 작성은 구현·커밋·배포를 포함하지 않는다.

## 확정 전 시각 값

1024 셸 내비 경계·960 본문 TOC 경계는 소스 폭 예산에 근거한 설계값이다. 시안 수령 때 긴 문구 및 경계 양쪽 실측으로 확정하며, 변경 시 두 기능의 설계와 브리프를 함께 맞춘다. 새로운 제품 선택지는 없다.
