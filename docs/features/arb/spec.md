# arb — spec

Flutter `gen-l10n`의 ARB 파일을 지원 포맷에 더한다. 모바일 세 스펙(**arb → apple-strings → android-strings**) 중 첫째다.
공통 결정(모바일 코퍼스, 기준선 보고서, 탐지 버킷, 값 표현 원칙)을 가장 싼 어댑터에서 먼저 실물로 확정한다.

**출시는 세 스펙을 한 번에 묶는다**(결정 2026-10-19 사용자). 세 스펙이 모두 dev에 들어갈 때까지 기능 `/merge`를 하지 않고,
그 뒤 새 action·GitLab CI 원본 태그 발행과 GitLab SHA 후속 패치를 android-strings T5에서 한 번에 처리한다. 중간에 머지하면 생성 워크플로가
`adapter: arb-catalog`를 박는데 v3 action의 CLI가 그 이름을 몰라 exit 2가 된다(`scripts/format.ts:54` · `lib/adapters/index.ts:106`).

## 사용자

- **주: 개발자** — Flutter 앱 리포를 가진 팀이 지금은 온보딩에서 후보 0개를 받는다(설명 없이 혼자 완주 불가 — PRODUCT §1).
- **부: 번역 편집자** — 화면에서 보는 값의 모양이 이 기능에서 정해진다. ARB는 ICU 문자열을 통짜로 보여 준다(design §3).

## 문제 (관측)

2026-10-19 보급률 표본(GitHub 리포 1,397개 — 스타 7구간 × 200, 2026-04 이후 push, fork·보관 제외, **경로 정규식 분류**):

- 로케일 파일이 있는 리포 394개 중 지금 지원 선언 포맷 넷(ARCHITECTURE §1.9 판정 ①)이 덮는 것은 **249개(63.2%)**다. TS/JS 리포는
  125개 중 119개(95%)로 거의 다 덮는다 — 남은 37%는 웹 밖이다.
- 모바일 세 생태계를 합치면 **지원 포맷이 하나도 없던 리포 49개(+12.4%p)**가 새로 덮인다(순증). 그중 ARB가 **8개(+2.0%p)**다.
  ARB 파일을 가진 리포 전체(보유)는 9개다 — 하나는 이미 지원 포맷을 함께 가진다. 코퍼스 후보(mobile-strings M1)는 보유 기준이다.
- ⚠️ 이 수치는 정규식 추정이다. 지원 여부를 실제 탐지기로 재는 것은 mobile-strings M1(모바일 코퍼스)이 한다.

## 완료 조건

1. 모바일 홀드아웃 코퍼스의 ARB 리포(사람이 판정한 정답 경로가 있는 리포)를 연결한 사용자가 **ARB 후보 중** 정답 경로를 받고 →
   번역을 고치고 → 그 셀 외에 diff가 없는 PR/MR을 받는다(PRODUCT §1의 완료 조건을 이 포맷으로). 리포 전체의 1순위는 리포별 대표 정답 하나로
   따로 판정한다 — 여러 생태계를 가진 리포에 포맷마다 다른 1순위를 동시에 요구하지 않는다(survey는 리포마다 `found[0]` 하나를 고른다, `lib/survey/one.ts:73-80`).
   **첫 Publish에 한해** 허용하는 정규화가 둘 있다: 키보다 앞에 있던 `@key`가 키 바로 뒤로 옮겨지는 것, 기존 `@@locale` 값이 경로의 코드와 다르면
   경로 코드로 고쳐지는 것. 그 뒤 Publish는 고정점이다(셀 외 diff 0).
2. **모바일 코퍼스**(학습 + 홀드아웃)의 ARB 리포에서 `pnpm adapter-survey`가 지원 포맷 탐지 · 왕복 의미 동일 · 바이트 고정점 · 조용한 손실 0을
   기존 4포맷과 같은 기준으로 보고한다. 목표: 고정점 100%, 조용한 손실 0건. 탐지·오탐 수치는 목표가 아니라 **보고 대상**이다(§1.9 판정 ④).
3. **기존 코퍼스 회귀 0** — 학습 109·홀드아웃 20의 25차 표가 한 칸도 나빠지지 않는다. 특히 **기존 리포의 1순위 후보가 바뀌지 않는다** —
   mobile-strings M0 기준선 보고서(리포별 SHA를 고정한 같은 입력)와 리포별 1순위 경로 diff 0으로 판정한다(바뀌면 `adapter`를 박지 않은 기존 워크플로가 `format mismatch` 409로
   영구 red가 된다 — POSTMORTEM 2026-09-14).
4. 번역하지 않는 구조(ARB `@key` 메타데이터, `@@*` 전역 항목)가 Publish 뒤에도 **원본 텍스트 구간 그대로** 남는다 — `@key` 객체는
   다시 직렬화하지 않고 같은 로케일 원본의 바이트를 복사한다. 예외는 조건 1의 첫 Publish 정규화(`@key` 위치·`@@locale` 값)뿐이다. 골든 테스트로 고정한다.
5. 언어 추가·제거(§7.2 locale-add)가 동작한다.

## 비목표

- **복수형·ICU 편집 UI** — PRODUCT §4.2 비범위 그대로. ARB의 ICU 문자열(`{count, plural, …}`)은 **통짜 문자열**로 보여 주고 저장한다.
- `flutter gen-l10n`이 만드는 생성물(`app_localizations*.dart`) 갱신.
- 화면 신규 표면 — 어댑터 라벨·예시가 기존 수동 지정 목록에 붙을 뿐이다(그래서 design-brief가 없다).
- 크로스플랫폼 리포에서 같은 언어가 포맷마다 다른 코드(`zh_CN`·`zh-Hans`·`zh-rCN`)로 갈려 별개 언어 열로 서는 것 — 지금의 raw 코드
  정책("파일명이 코드의 진실")을 따른다.
- gettext·Qt Linguist·.NET resx·Fluent·Java properties·XLIFF — 키 = 원문(gettext·Qt)은 원칙 충돌이라 포지셔닝 판정이 먼저다.
