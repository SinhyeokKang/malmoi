# session-absolute-timeout — spec

## 사용자

**번역 편집자(비개발자 동료)** 가 주 대상이다. 개발자도 같은 정책을 받는다.

## 문제

- **번역자가 하루에 한 번 들어올 때마다 다시 로그인한다** — 사용자 제보·직접 겪은 사실이다.
- 원인은 설정값만이 아니다. **세션 쿠키가 로그인 뒤 한 번도 다시 발급되지 않는다**(코드로 확인, 실측은 tasks T0). 앱이 `auth()`를 부르는 곳은 `lib/auth/read-session.ts:43` 하나이고 인자 없는 호출은 `next-auth/lib/index.js`의 RSC 분기를 타서 Auth.js가 만든 Set-Cookie를 버린다. `useSession`·`/api/auth/session` 호출도 0건이다. 그래서 쿠키 만료는 로그인 callback이 정한 `createSession`의 `expires`에 고정되고, DB `expires`만 시간마다 미끄러진다.
  - 실제 정책은 **"로그인 뒤 24시간 고정"** 이다. 방침·가이드·ARCHITECTURE §6.1.1의 "마지막 활동 뒤 24시간"은 **지금 이미 사실과 다르다**(POSTMORTEM 2026-09-19와 같은 부류 — T0 실측 뒤 `/postmortem`).
  - 24시간은 JWT 시절의 유산값이고, 그 근거(권한 회수 지연)는 DB 세션으로 옮긴 2026-09-06에 사라졌다(`auth.ts` 머리 주석).
- idle sliding을 살리려면 쿠키를 다시 심는 둘째 장치(미들웨어 재발급 등)가 필요하다. 그래서 **sliding을 포기하고 고정 수명 하나로 간다**(2026-10-15 결정).

## 값을 고른 근거

- **7일**: 주 단위로 들어오는 번역자가 주말을 건너도 한 번의 로그인으로 한 주를 쓴다. 24시간 → 7일은 "매일 로그인"을 "주 1회 로그인"으로 바꾼다.
- **고정(absolute) 하나**: 쿠키 만료와 DB 만료가 같은 시각이라 둘이 어긋나는 구간이 없다. 활동과 무관하게 끝나므로 무기한 사는 세션이 없다.
- **대가**: 탈취된 쿠키가 쓰일 수 있는 기간이 최대 24시간 → 최대 7일로 는다. 완화책은 기존 [Sign out everywhere](`/account`, 전체 세션 폐기)다. 버려진 세션(공용 컴퓨터)도 최대 7일 산다.

## 범위 게이트

PRODUCT §4.2 비범위와 대조했다 — 걸리는 항목이 없다. PRODUCT에는 세션 수명 서술이 없어 갱신하지 않는다.

## 완료 조건

1. 세션은 **세션 행을 만든 시각(로그인)부터 7일**이 지나면 쓸 수 없다. 활동해도 연장되지 않는다. 로그인한 상태에서 다시 로그인하면 Auth.js가 기존 행을 돌려주므로(`@auth/core` `callback/handle-login.js:99-101`) 7일이 다시 시작되지 않는다.
2. 브라우저 쿠키 만료와 DB `Session.expires`가 같은 시각(`createSession`의 `expires`)이고, 이후 어느 요청도 DB `expires`를 바꾸지 않는다.
3. 7일이 지난 세션 원문으로는 인증되지 않는다. 경로별 결과는 지금 만료·폐기된 세션과 같다:
   - 보호 페이지 GET → `/signin`으로 redirect(`app/(edit)/layout.tsx:38`). 쿠키가 브라우저에서 이미 사라졌으면 미들웨어가 먼저 보낸다.
   - Server Action → redirect 없이 값 `unauthorized`(`app/(edit)/actions.ts:29-31`).
   - 공개 페이지 → 비로그인 상태로 렌더(`lib/auth/landing.ts:57-60`).
   - 그 원문이 다시 제시되면 행이 지워진다(`lib/credentials/adapter.ts` `getSessionAndUser`). 다시 제시되지 않은 행은 남는다(정리 cron 없음).
4. 배포 시각에 로그인해 있던 세션은 원래 쿠키 만료(로그인 + 24시간) 안에 끝나고, 다음 로그인부터 7일을 받는다 — 강제 로그아웃이 없고 스키마 변경도 없다.
5. 개인정보 방침(en·ko)·셀프 호스팅 가이드 저장 필드·쿠키 표·운영 문서(en·ko·es)·ARCHITECTURE §6.1.1이 새 정책을 말한다. 방침 개정 이력에 행이 하나 생긴다.
6. `provider-config.test.ts`가 `maxAge` 7일과 "연장 없음" 설정을 고정하고, 어댑터 단위 테스트·격리 PG 스위트가 "갱신이 DB를 바꾸지 않는다"를 고정한다.

## 비목표

- **idle(sliding) 만료** — 쿠키 재발급 장치가 필요하다(위 문제 절). 고정 7일로 대신한다.
- **파괴적 액션 재인증** — OAuth 전용 로그인에선 재인증이 살아 있는 IdP 세션만 증명하고(ARCHITECTURE §6.1.1 GitLab 실측), 파괴적 액션은 대부분 되돌릴 수 있고 이미 OWNER·서버 지문을 요구한다. 오버스펙으로 판정(2026-10-15).
- **전체 세션 폐기의 MCP 토큰·OAuth 연결 확장** — 별건.
- 만료 임박 안내·"로그인 유지" 체크박스·세션 목록 UI·로그인 뒤 원래 화면으로 돌아가기(지금은 `/projects` 고정).
- 정책 값의 설정화(환경변수) — 소비자 없는 설정이다.
