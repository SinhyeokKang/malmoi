# session-absolute-timeout — spec

## 사용자

**번역 편집자(비개발자 동료)** 가 주 대상이다. 개발자도 같은 정책을 받는다.

## 문제

- 세션이 **마지막 활동 뒤 24시간**에 끝난다(`auth.ts` `maxAge: 60 * 60 * 24`, ARCHITECTURE §6.1.1). 하루에 한 번 들어오는 번역자는 사실상 매번 다시 로그인한다.
- 정책에 **절대 상한이 없다.** idle만 늘리면 매일 쓰는 세션(또는 탈취된 쿠키)이 무기한 산다.

## 완료 조건

1. 세션은 마지막 활동 뒤 **7일**이 지나면 쓸 수 없다(idle, sliding).
2. 세션은 활동과 무관하게 **로그인 시각부터 30일**이 지나면 쓸 수 없다(absolute). 30일째 이후 첫 요청에서 세션 행이 지워지고 `/signin`으로 간다.
3. DB의 `Session.expires`가 언제나 그 세션의 **실제 만료 시각**이다 — `min(마지막 갱신 + 7일, createdAt + 30일)`. 이 값을 읽는 기존 판정(`getSessionAndUser`·세션 폐기·로그인 수단 연결)이 코드 변경 없이 absolute를 따른다.
4. absolute 상한에 닿은 세션은 남은 기간 동안 요청마다 DB 쓰기를 하지 않는다(갱신 결과가 저장값과 같으면 쓰지 않는다).
5. 이미 로그인해 있는 세션은 배포(마이그레이션) 시각을 `createdAt`으로 받는다 — 강제 로그아웃이 없다.
6. 개인정보 방침(en·ko)·셀프 호스팅 가이드 저장 필드·쿠키 표(en·ko·es)·ARCHITECTURE §6.1.1이 새 정책을 말한다. 방침 개정 이력에 행이 하나 생긴다.
7. `provider-config.test.ts`가 idle 값(`maxAge`)을 고정하고, 순수 함수 테스트가 absolute 상한을 고정한다.

## 비목표

- **파괴적 액션 재인증** — OAuth 전용 로그인에선 재인증이 살아 있는 IdP 세션만 증명하고(ARCHITECTURE §6.1.1 GitLab 실측), 파괴적 액션은 대부분 되돌릴 수 있고 이미 OWNER·서버 지문을 요구한다. 오버스펙으로 판정(2026-10-15).
- **전체 세션 폐기의 MCP 토큰·OAuth 연결 확장** — 별건.
- **쿠키 만료를 DB 만료와 같은 시각으로 맞추기** — Auth.js가 세션 조회마다 쿠키를 `now + maxAge`로 다시 심고 어댑터가 그 값에 닿지 못한다(design §2). 쿠키가 DB보다 오래 남아도 다음 요청에서 지워진다.
- 만료 임박 안내·"로그인 유지" 체크박스·세션 목록 UI.
- 정책 값의 설정화(환경변수) — 소비자 없는 설정이다.
