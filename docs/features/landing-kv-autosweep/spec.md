# landing-kv-autosweep — spec

> 2026-10-18 사용자. landing-kv-background(같은 날 dev `1191e41b`)의 후속이다. 정본은 DESIGN §6.615 "KV 배경" · §6.62 "도트 필드 — 두 소비자"이고, 이 기능은 그중 랜딩(`follow="scroller"`)의 커서 동작만 바꾼다.

## 문제 (관측된 사실)

- 랜딩 배경의 점 격자는 마우스 커서를 따라 밝아진다(R7 — `pointerType === "mouse"`만 실제 커서). 사용자는 랜딩에서 커서 추종을 원하지 않는다.
- 자동 순회 가상 커서(`autoCursor`)는 캔버스 모서리(`x = 0` · `x = width`)에서 방향을 바꾸고 다음 줄로 내려간다. 반경 180의 밝은 원이 패널 안에 반쯤 걸린 채 꺾여, 패널 안에서 줄을 바꾸는 것이 보인다.

## 결정 (2026-10-18 사용자)

1. **랜딩은 커서를 따르지 않는다** — 항상 자동 순회다. 마우스·터치·펜 모두 점에 영향을 주지 않는다.
2. **랜딩의 줄바꿈·방향 전환은 패널 밖에서 한다** — 가상 커서가 패널(캔버스) 모서리를 지나 밝은 원이 완전히 사라질 만큼 더 간 뒤 다음 줄로 내려가고, 반대 방향으로 다시 들어온다.
3. **로그인 KV는 현행 유지** — 커서 추종도, 모서리에서의 방향 전환도 그대로다.

## 완료 조건 (검증 가능한 문장)

1. `autoCursor`에 넘침 폭(`overshoot`, 기본 0)이 생긴다. **0이면 지금 출력과 바이트 단위로 같다**(로그인 불변). `overshoot = o`이면 가로 이동이 `[-o, width + o]`를 훑고, 세로 이동(줄바꿈)은 `x = -o` 또는 `x = width + o`에서만 일어난다. 단위 테스트.
2. 랜딩(`follow="scroller"`)은 `overshoot = CURSOR_RADIUS(180)`로 부른다 — 줄바꿈 동안 반경 안에 드는 점이 0이다(`partitionDots(...).near.length === 0`). 단위 테스트.
3. 랜딩은 포인터 리스너를 붙이지 않는다 — 스크롤러·캔버스 어디에도 `pointermove`·`pointerleave`가 없고, 마우스 이동이 그리기를 바꾸지 않는다. 로그인(`follow` 기본)은 지금처럼 캔버스에서 포인터를 받는다. DOM 테스트.
4. 속도(320px/s) · 5줄 · 모션 감소(정적, 스크롤마다 한 번) · 스크롤 위상(R6) · 묶음 그리기(R8)는 그대로다. 기존 테스트 green.
5. 정본 — DESIGN §6.62 "도트 필드" 행의 R7을 "랜딩은 포인터를 받지 않는다 · 패널 밖 줄바꿈"으로 바꾸고, §6.615 "KV 배경"의 "커서를 따르는 점 격자" 서술을 랜딩에 맞게 고친다. landing-kv-background의 지휘자 판단 D7(마우스만 실제 커서)은 폐기된다.
