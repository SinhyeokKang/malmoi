# mcp-connector — spec

## 사용자

**둘 다다** (2026-09-28 사용자 · 검수 L 재확인). 개발자는 자기 리포를 연 CLI·코딩 에이전트(Claude Code · Codex · Cursor 등)에 Malmoi를 MCP
서버로 붙이고 프로젝트 생성부터 번역·Publish·설정·멤버 관리까지 맡긴다. **번역 편집자도 같은 기능을 쓴다** — 자기 에이전트로
번역을 채우고 Publish한다. 할 수 있는 일은 **그 프로젝트에서의 역할이 정한다**: EDITOR의 토큰은 EDITOR가 화면에서 할 수 있는
것(조회·번역 저장·Publish)까지다. 에이전트가 한 일은 사람이 한 일과 같은 인가·같은 사건 기록을 지난다.

인도되는 채널은 **Bearer 헤더를 붙일 수 있는 클라이언트**(CLI·코딩 에이전트)다. claude.ai·ChatGPT 웹 커넥터는 OAuth만 받아
비목표다 — 편집자가 그쪽 클라이언트만 쓴다면 이번 인도물로는 닿지 않는다(비목표 절).

## 문제

- Malmoi의 모든 쓰기가 **브라우저 세션 + Server Action**이다. 비-쿠키 인증은 프로젝트 push 토큰(`/api/push`·`/api/push/failure`)과
  `CRON_SECRET`(`/api/pull`) 둘뿐이고 둘 다 사람을 대신하지 않는다.
- 개발자는 이미 리포를 연 에이전트 안에서 일한다. 그런데 온보딩 ①–④ · 워크플로 YAML 복사 · Actions secret 등록 · 번역 입력이
  전부 웹 화면이라, 에이전트가 할 수 있는 일(워크플로 파일 커밋, `gh secret set`, 문자열 번역)을 사람이 화면과 터미널을 오가며 옮긴다.
  편집자는 키 수백 개를 한 칸씩 입력한다.
- PRODUCT §4.3 ⑤가 "MCP 서버 자체는 비범위가 아니다"라고 열어 두고 개방 조건을 **"도구 목록과 각 도구의 쓰기 범위가 정해질 때"**로
  적었다. 이 스펙이 그 조건을 채운다(design §2).

⚠️ **토큰 권한은 역할의 부분집합일 뿐이다 — 새 역할도 넷째 `Permission`도 아니다.** 프로젝트 쓰기의 유효 권한은
`canPerform(role, p) && token.grants ∋ p` 이고, 토큰이 역할보다 넓을 수는 없다. 그래서 §4.2의 비범위(역할·권한 체계를 늘리는 것)는
그대로 서고, 이 기능은 "위임할 때 덜 주는 것"만 연다. 어휘는 기존 셋(`translation:write` · `project:settings` · `member:manage`)에
**토큰 전용 하나**(`project:create` — 프로젝트가 없는 동작이라 역할 표에 들어갈 자리가 없다)를 더한다.

**grant 없는 토큰이 읽을 수 있는 것은 한 문장이다** (검수 K): **내 프로젝트 안의 데이터**(키·번역·사건·멤버·표면·기존 프로젝트의
브랜치 목록·워크플로 YAML)는 역할·범위 안에서 grant 없이 읽는다. **GitHub 계정을 열거하거나 GitHub에서 파일을 내려받는 도구**
(`list_repositories` · 신규 프로젝트의 `list_branches`·`detect_formats`)만 생성/설정 grant를 요구한다. 발급 폼의 체크박스 옆 한 줄이
이 문장을 말한다.

**설계 가정** (확인 전 — 확인 결과로 갱신한다)

- **전송은 원격 Streamable HTTP 하나다** — `https://mal-moi.com/api/mcp`. stdio 로컬 서버·npm 패키지는 만들지 않는다.
- **프로토콜 개정은 T1이 확정한다** (검수 C — 로컬에 SDK가 없어 어느 개정도 검증되지 않았다). 세션 없이 JSON 한 벌로 응답하고
  호출 사이 상태는 서버 발급 **핸들을 도구 인자로** 넘긴다 — Malmoi는 이미 그 형(Sync 폐기 지문 · 샘플 확인값 HMAC)을 쓴다.
  SDK가 안 맞으면 JSON-RPC 세 메서드를 직접 받는다(design §1.1).
- **인증은 개인 토큰(Bearer)뿐이다** (✅ 2026-09-28 사용자 확정). OAuth 2.1 인가 서버는 이번에 만들지 않는다.
- **Malmoi는 LLM을 부르지 않는다.** 번역 값을 만드는 것은 사용자의 에이전트이고 Malmoi에게 그것은 `Save`를 누른 편집자와 같다.
  PRODUCT §4.2 "AI 번역"은 Malmoi가 번역을 생성하는 기능의 비범위로 남는다 (✅ 2026-09-28 사용자 확정).
- **화면이 지키는 확인 절차는 도구에서도 지킨다.** Publish 미리보기 · Sync 폐기 지문 · Revert 지문이 도구에서 `preview_*` → 핸들 →
  실행 두 걸음이다. boolean `confirm: true`는 만들지 않는다.
- 라우트는 **`/mcp`**, 사이드바·제목 라벨은 **`MCP connector`** (✅ 2026-09-28 사용자).

## 완료 조건

메커니즘·상수·잠금 순서는 design이 정본이고 여기엔 관측 가능한 결과만 적는다(검수 I).

1. 사이드바 사용자 구역에서 `New project` 아래 `MCP connector`가 서고, 누르면 `/mcp`가 열린다. 제목이 사이드바 라벨과 같은 키다.
   비로그인 GET은 `/signin`으로 간다(`isProtectedPath`).
2. `/mcp`에서 토큰을 발급한다 — 만료(**필수**, 30/90/365일) · **허용 동작**(체크 넷: Translate & publish · Project settings · Members ·
   Create projects — 위의 한 문장 규칙이 체크박스 옆에 선다) · **프로젝트 범위**(All my projects / 고른 프로젝트). 원문은 발급 직후 한 번만
   보이고(서버는 해시만 저장) 연결 예시 셋(Claude Code · Codex · Cursor)이 그 토큰을 **환경변수로** 넘기는 꼴로 나온다.
3. 토큰은 계정당 하나다. 카드에 허용 동작 · 범위 · Created · Last used · Expires가 보인다. 토큰이 있으면 [Rotate]·[Revoke], 없거나
   만료됐으면 [Create token]이 선다. Rotate·Revoke 뒤 앞 토큰의 다음 호출은 401이다. 권한·범위는 바꿀 수 없다 — 재발급이 그 길이다.
4. 토큰 없음 · 무효 · 만료 · 폐기가 전부 **같은 401**이고 본문이 갈래를 말하지 않는다. 쿠키만 실은 요청도 401이다.
5. `tools/list`가 design §2의 도구를 **결정적 순서로** 돌려준다(토큰 권한과 무관하게 같은 목록 — 거부는 호출 시점에 한다).
   `whoami`가 그 토큰의 허용 동작·범위를 돌려준다(에이전트가 자기 권한을 알 유일한 수단이다 — 검수 R).
6. **유효 권한 = 역할 ∩ 토큰.** EDITOR가 `Project settings`를 체크한 토큰으로 `sync_repository`를 부르면 화면과 같은 `forbidden`이다.
   OWNER가 `Translate & publish`만 준 토큰으로 `invite_members`를 부르면 `token-scope`다. 범위 밖 프로젝트는 `not-found`다(존재를
   말하지 않는다). 멤버에서 제거된 사용자의 토큰도 그 프로젝트에 `not-found`다. 미리보기 핸들은 실행 권한을 주지 않는다.
   **잠금 대기 중 회수된 토큰(폐기·만료·재발급)은 아무것도 쓰지 못한다** — 번역·설정·사건·실행권·프로젝트 생성 전부(design §1.25).
7. **Create projects가 있는 토큰**으로, GitHub App이 연결·설치된 사용자는 `list_repositories` → `detect_formats` → `create_project`로
   프로젝트가 `ready`가 되고 결과에 push 토큰 원문과 워크플로 YAML이 실린다. 고른-프로젝트 범위 토큰이 만든 프로젝트는 그 토큰의
   범위에 들어간다. 에이전트가 YAML을 쓰고 `gh secret set PUSH_TOKEN --repo OWNER/REPO`에 원문을 표준입력으로 전달한 뒤 CI 첫 push가
   200이다(실물 — preview). 기존 프로젝트의 OWNER는 `Project settings`만 가진 토큰으로 `detect_formats({ slug })` → `add_sources`를
   완료한다. **낡거나 다른 대상의 확인값은 `sample-expired`로 쓰기 0회**다(design §2.2).
8. 연결·설치가 안 된 사용자는 같은 도구가 `needs-browser`로 **`/account` 하나**를 돌려준다 — 연결·설치는 브라우저에서 한 번이고,
   그 뒤 같은 토큰으로 조건 7이 성립한다(검수 Q). `detect_formats`가 정상 조회를 마쳤지만 후보가 없으면 `needs-browser` ·
   `reason: "no-candidates"`로 수동 설정 화면(`/projects/new` 또는 `/projects/<slug>/sources`)을 안내한다. GitHub 장애·권한 거부·예산
   초과를 후보 없음으로 바꾸지 않는다.
9. `publish`는 `preview_publish`가 준 핸들 없이 실행되지 않는다. **핸들을 받은 뒤 export 입력이 달라졌으면 GitHub 쓰기 없이
   `reconfirm`이다** — 표시 상한 밖의 편집과 미전달 토큰 없이 파일을 바꾸는 변경(orphan 등)도 잡는다. 캡처 뒤의 새 편집은 이번
   전송에 섞이지 않고 미전달로 남는다(design §3.1). Sync 폐기·Revert의 기존 지문 확인도 유지한다.
10. 도구로 한 번역 저장·Publish·설정 변경이 Logs에 **그 사용자의 사건**으로 선다. 에이전트 경유는 표시하지 않는다(✅ 2026-09-28 사용자 —
    "에이전트가 수정한다 = 그 사용자가 수정한다"). `ProjectEvent`는 바뀌지 않는다.
11. 보관된 프로젝트는 `unarchive_project` 외 쓰기 도구가 `archived`다. 본문 상한 초과는 읽기 전에 400이다(인증 → 크기 → 파싱).
    `set_translations`는 최대 100키를 **한 잠금·한 tx**로 저장하고 키별 결과를 입력 순서대로 돌려준다 — 일부 키의 거부(`cannot-clear`
    · `not-found` 등)는 그 키만 거부이고 나머지는 커밋된다(검수 E).
12. 기존 Server Action의 동작이 바뀌지 않는다 — 추출한 코어를 Action과 도구가 같이 부르고 기존 테스트가 그대로 green이다.
13. `/privacy`가 새 저장 항목(토큰 해시·권한·범위·사용 시각)을 싣고, `pnpm typecheck` · `pnpm test` · `pnpm build` ·
    `pnpm test:projects:postgres`가 green이다. preview에서 CLI·CI 왕복이 앱에 도달했음을 확인한다(배포 순서·보호층 통과는 tasks T3·T9).

## 비목표

- **MCP 수동 포맷 확정 도구** — 자동 탐지 후보가 없는 리포는 기존 브라우저 온보딩/소스 추가에서 수동 설정한다.
  에이전트가 포맷·경로를 추측해 확인값 없이 생성/추가하는 우회는 열지 않는다.
- **OAuth 2.1 인가 서버 · claude.ai/ChatGPT 웹 커넥터 등록** — 웹 커넥터는 OAuth만 받고 CLI·코딩 에이전트는 헤더를 받는다. 필요해지면
  같은 `/api/mcp` 앞에 세운다(토큰 → 주체 해석 한 곳만 바뀐다).
- **토큰 여러 개 · 토큰 편집** — 계정당 하나, 불변. 에이전트별 다른 권한이 관측되면 그때 목록으로 넓힌다.
- **프로젝트마다 다른 토큰 권한(행렬)** — 허용 동작은 토큰 하나에 한 벌이고 범위는 프로젝트 목록이다. 행렬은 §4.2에 더 깊이 든다.
- **새 역할 · 역할의 권한 변경** — 토큰은 좁히기만 한다.
- **Malmoi 안의 기계·AI 번역**, 번역 메모리, 용어집.
- **계정 축 도구** — 프로필·사진, 로그인 수단, 전체 세션 회수, **토큰 발급·폐기 자체**(토큰이 토큰을 만들지 않는다), 초대 수락.
- **이미지 업로드**(썸네일) — 바이너리 입력이 도구 계약에 안 맞는다.
- **GitHub App 설치·인가를 도구로 대신하기** — state 쿠키가 방어선인 브라우저 왕복이다(ARCHITECTURE §6.4). URL만 준다.
- **stdio 서버·npm 배포**, `subscriptions/listen`·tasks 확장·MRTR elicitation, **`resources`·`prompts` 프리미티브**.
- **`retry_first_ingest`** — 실패한 표면의 재시도는 Sources 화면의 버튼이다.
- **GitHub secret scanning 파트너 등록** — `mlm_` 접두는 사람 눈용이다.
- **빈도 상한** — ARCHITECTURE §6.06의 판정을 따른다.
- **사용량 대시보드·호출 로그** — 사건은 Logs가 든다. 토큰 행은 `lastUsedAt` 하나만 든다. 만료 토큰 정리 job도 없다 — 카드가
  `Expired`를 보이고 재발급이 덮는다.
