# sidebar-projects — spec

앱 셸 사이드바가 **지금 프로젝트가 없는 자리**(`/projects`·`/projects/new`·`/inbox`·`/mcp`·`/preferences`·`/account`)에서
사용자 구역 아래(구분선 + 둘째 구역 자리)에 **내 프로젝트 목록 + `New project`**를 보인다. 프로젝트 라우트에서는 지금과 같다.
요청·결정: 2026-10-09 사용자 — 목록 + New project · 소속 프로젝트가 없으면 New project만 · **헤더 버튼·`/projects` 빈 상태 CTA와 겹쳐도 괜찮다**.
리뷰 결정(2026-10-09 feature-review): `/projects` 본문 목록과의 겹침도 수용 · 구역 `aria-label`은 새 키 `Your projects` · 프로젝트 행 이동 뒤 포커스는 Home 항목에 착지.

## 사용자

**둘 다.** 프로젝트 밖 화면(Inbox·MCP·계정·환경설정)에서 프로젝트로 가는 사람은 개발자·편집자 모두다.
`New project`는 프로젝트를 만드는 사람(주로 개발자)의 입구다(진입은 `requireUser`만 — 역할 게이트 없음, 헤더 버튼과 같다).

## 문제 (관측된 사실)

- 프로젝트 밖 화면에서 사이드바는 사용자 구역 다섯 줄 다음에 바로 하단 둘이 온다 — 둘째 구역이 없다(`navZones`가 `project === null`이면 구역 하나만 내고, 구분선 `border-t pt-2`는 둘째 구역에만 붙는다 — `components/shell/sidebar.tsx:94`).
- 그 자리에서 프로젝트로 가는 길은 `Projects` → 목록 → 행(두 번 이동), 헤더 아바타 메뉴(2026-10-09 user-menu-projects — 두 번 클릭), `⌘K`다. 사이드바에는 없다.
- `New project`는 2026-09-30부터 헤더 아바타 왼쪽 버튼 하나다 — 사이드바에서 "프로젝트를 만든다"는 행동이 보이지 않는다.
- ⚠️ **이 구역은 "최근 작업한 프로젝트로 돌아가기"가 아니라 "목록 앞 5개로 가는 지름길"이다** — 순서는 스위처 빈 질의 순서(멤버십 slug 오름차순에서 보관 제외)이고, 6개 이상이면 뒤쪽은 이 구역에 서지 않는다(`Projects`·스위처·`⌘K`가 든다).

## 범위 게이트

- PRODUCT §4.2 비범위에 걸리는 항목 없음 — 새 권한·데이터·조회가 없다. 사전 키는 하나 는다(`Your projects` — 구역 `aria-label`).
- ⚠️ **새 결정 셋** — PRODUCT §7.7·:949·DESIGN §6.5에 기록한다(T4):
  1. **`New project`가 LNB로 돌아온다** — 단 사용자 축(`navWorkItems`)이 아니라 **프로젝트 목록 구역의 끝 행**이다. `navWorkItems`는 헤더 사용자 메뉴와 공유하므로 거기에 넣으면 메뉴에도 서게 된다(2026-09-30 결정은 사용자 축·메뉴에서 그대로 유효). 9-30 결정은 근거 문장 없이 자리만 옮겼다(PRODUCT:949) — 이번 반전은 그 결정 중 "사용자 축에 없다"만 남기고 "LNB에 없다"를 되돌린다.
  2. **둘째 구역 자리가 두 형을 갖는다** — 지금 프로젝트가 있으면 그 프로젝트의 구역(지금과 같음), 없으면 프로젝트 목록 구역. PRODUCT §7.7의 "구역이 스코프를 표시한다"는 이렇게 지킨다: **프로젝트 구역은 늘 머리(썸네일·이름·스위처)가 있고, 머리 없음이 "지금 프로젝트 아님"의 표시다.**
  3. **목록은 아바타 메뉴와 같은 목록이다** — 상한 5·순서·보관 제외를 `menuProjects` 하나가 정한다. 같은 5인 이유는 두 자리의 목록이 갈리지 않게 하기 위함이다(메뉴 길이 상한이 사이드바 근거는 아니다 — 상한을 바꾸면 두 자리가 같이 바뀌는 것이 의도). 프로젝트 밖 사이드바는 최대 13행(사용자 5 + 프로젝트 ≤5 + New project 1 + 하단 2)으로 프로젝트 라우트와 비슷한 밀도라 수용한다(DESIGN :2280 "사이드바 항목 십수 개").
- IA 결정 1(PRODUCT — 프로젝트로 가는 자리는 전부 Home에 착지)을 따르고, 그 "자리" 목록에 이 구역의 행을 등재한다(T4).
- 같은 셸을 만지는 진행 중 spec — responsive-app A-01(LNB 서랍·프로젝트 전환). 이 기능이 먼저 들어가면 그 행에 이 구역을 등재하고 AT1 검증 범위에 **프로젝트 밖 서랍**을 더한다(T4).

## 완료 조건 (검증 가능한 문장)

1. 지금 프로젝트가 없는 앱 셸 화면(`activeProject(pathname, memberships) === null`)의 사이드바는 **사용자 구역 / 구분선 / 프로젝트 목록 구역 / 하단** 순이다. 구분선은 기존 구역 사이 선(`border-t pt-2`) 하나다.
2. 프로젝트 목록 구역은 **보관 안 된** 멤버 프로젝트를 **최대 5개**(`menuProjects` — 스위처 빈 질의 순서) 보이고, 그 뒤 마지막 행이 `New project`다. 6개 이상이면 앞 5개 + `New project`다.
3. 프로젝트 행은 `ProjectThumbnail xs`(16, 항목 아이콘 자리) + 이름(truncate)이고 누르면 그 프로젝트 Home(`routes.project(slug)`)으로 간다. 배지가 없다.
4. `New project` 행은 `Plus` 글리프 + 기존 `m.common.nav.newProject` 문구이고 `routes.newProject()`로 간다. `/projects/new`에서 그 행이 `aria-current="page"`다(`Projects`는 아니다 — 지금처럼 exact). 누르면 응답 전에 `Item`의 pending 면이 선다.
5. 보관 안 된 멤버 프로젝트가 0이면(소속 없음 · 보관만 있음) 구역에 `New project` 한 행만 선다.
6. 프로젝트 라우트(보관 프로젝트 포함 — 지금 프로젝트가 있는 자리)는 지금과 같은 구조다 — 머리 줄·스위처·항목·배지. 증거: `sidebar-identity`·`sidebar-collapse`·`sidebar-pending`·`sidebar-selection` 무수정 green + `navZones(project≠null)`이 `projects`를 넘겨도 `["work","project"]`.
7. 접힌 레일에서 프로젝트 행은 썸네일만, `New project`는 `Plus`만 보이고 `title`이 이름을 댄다(기존 `Item`의 접힘 규칙).
8. 구역 `<nav>`의 `aria-label`은 새 키 `m.common.nav.yourProjects`(`Your projects`)다 — 바로 위 사용자 구역의 `Projects` 링크와 랜드마크 이름이 겹치지 않게. 보이는 머리 줄은 없다(사용자 구역처럼).
9. 프로젝트 행을 눌러 이동하면 구역이 `project`로 바뀐 뒤 포커스가 `body`가 아니라 새 구역의 `aria-current` 항목(Home)에 있다.
10. 새 조회가 없다 — 레이아웃이 이미 넘기는 `memberships`를 쓴다. 새 사전 키는 `yourProjects` 하나이고 en·ko·es 세 사전에 같은 커밋으로 든다.
11. 정본 문서(PRODUCT §7.7·:949·IA 결정 1 · DESIGN §6.5 구역·항목 행·pending·접힘·§6.8 아이콘 · nav.ts/sidebar.tsx 머리 주석)가 새 결정을 말한다. 사이드바가 든 가이드 컷 중 프로젝트 밖 화면은 컷마다 재촬영/변화 없음을 판정한다(T5).
12. `pnpm gate` green — 커밋 경계마다.

## 비목표

- **"더 보기"·전체 수** — 위 `Projects` 항목이 목록으로 가고 개수 배지를 이미 든다.
- **최근 작업 순** — 마지막 방문·편집 시각이 필요해 새 데이터·조회가 생긴다. 순서는 아바타 메뉴와 같은 스위처 순서다.
- **보관 프로젝트** — 목록 화면·스위처가 든다.
- **프로젝트 행의 카운트 배지** — 그 수는 프로젝트 구역 항목(Sources·Translations·Members)의 것이다.
- **구역 머리 줄(라벨·스위처)** — 프로젝트 밖에서는 "지금 프로젝트"가 없어 머리가 말할 것이 없다(머리 없음이 곧 표시다 — 범위 게이트 결정 2).
- **헤더 `New project` 버튼·사용자 축 변경** — 그대로 둔다(겹침은 사용자 결정으로 수용).
- **상한 5의 설정화** — `menuProjects`의 모듈 상수를 그대로 쓴다.
- **디자인 시안** — 기존 `Item` 행과 `ProjectThumbnail`을 조립한다.
- **멤버십 0 계정의 실물 확인** — dev에 그런 계정이 없다. 단위·jsdom 테스트로 갈음하고 T3에 미검증으로 남긴다.
